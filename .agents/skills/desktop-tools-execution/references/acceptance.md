# acceptance：修复验收七步

修复类改动（缺陷、回归、对现有行为的改造）按本页走。编排原文见 `docs/agents/修复验收轮次.md`，证据层与判据见 `docs/validation/验收流程.md`。

## 七步

| 步 | 动作 | 出口 |
| --- | --- | --- |
| 0 复现分级 | 固定构建、DPI、形态/边、动效开关与操作序列；选最低足够层 | 对当前代码稳定失败 |
| 1 定位 | 写清不变量、影响面与回归矩阵 | 根因可证，矩阵覆盖受影响状态 |
| 2 修复与红绿 | 先让复现失败，再修到通过；补同层断言 | 复现由红转绿，受影响测试通过 |
| 3 构建与制品 | 构建真实产物，记录哈希与构建时间 | 运行实例与源码一致 |
| 4 独立审核 | 冻结 diff 与证据，交另一模型审核 | 无阻断项；修复后复审 |
| 5 同产物真机 | 同一产物复现原场景并跑回归矩阵 | 用户确认，证据留档 |
| 6 暂存与同步 | 只暂存通过验收的改动，同步事实文档 | 暂存范围 = 验收范围 |

任一步失败：带证据回到步骤 1，不直接改代码进入下一轮。步骤 3、5 不得跳过。

## 制品指纹

```powershell
git rev-parse --short HEAD
git status --short
Get-FileHash build\target\debug\desktop-tools.exe -Algorithm SHA256
```

- 前端改动再记 `build/frontend` 的构建时间；主题/插件改动记 `build/target/debug/plugin/<目录>` 的同步时间。
- 审核后改代码必须重建并重新记录；修复前的构建不能用于步骤 5。
- 只改注释或事实文档：按影响跑 `npm run typecheck` + 受影响测试，写明补验依据。

## 红绿与测试有效性

- 断言必须能区分「旧代码失败、新代码通过」；只验证新代码通过不算回归测试。
- 新测试要进既有入口：`node --test` 清单、`scripts/断言页目录.mjs` 或 `npm test` 链，不能只留临时脚本。
- 失败注入用例要确认注入真的走到生产分支，否则「通过」没有意义。

## 独立审核

- 审核输入是冻结的 diff + 复现用例 + 证据，不是口头描述；审核期间不改文件、不暂存。
- 审核者与实现者用不同模型/会话；审核 pass 只代表代码审查通过。
- 按 [review-packet](review-packet.md) 准备材料；finding 分阻断/非阻断，阻断项修完复审。

## 风险缩放

| 变更 | 可省略 | 不可省略 |
| --- | --- | --- |
| 纯样式/文案 | 独立审核 | 构建、同层复现、用户确认 |
| 组件/交互 | 无 | 断言页、独立审核、真机确认 |
| 原生窗口/合成/DWM | 无 | 窗口盒或录屏、独立审核、用户确认 |

## 收尾

- 结束本轮启动的开发服务器、无头 Edge、开发版实例、后台任务与临时目录；确认 1420 无监听。
- 保留步骤 3 的构建产物给步骤 5，不要清掉或重建。
- 验收记录写 `build/validation/记录/`：构建、命令、退出码、证据类型、未验证项。
