# theme：主题同步与缓存

改主题、插件样式或排查「改了没生效」时读本页。规则原文见 `docs/agents/构建运行.md` 与 `docs/design/主题变量契约.md`。

## 同步

```bash
npm run sync:plugin
```

- 源：仓库 `plugin/<插件>`；目标：`build/target/debug/plugin/<作者>@<名称>`。
- 默认跳过 `示例/`；需要时 `node scripts/同步插件.mjs --include-examples`。
- 同 id 的插件沿用目标已有目录，不会生成两份注册。
- 同步只覆盖文件，不删除目标里多出来的旧文件；换字体或删文件后，必要时手工清理对应目录再同步。

## 缓存键

宿主把样式表地址写成 `theme.css?v=<cacheKey>`，cacheKey 由清单版本 + 样式表大小 + 修改时间派生。同步会保留源文件时间戳，源文件一改，URL 就变；不需要手动 bump 版本。

## 核对顺序

样式没生效时按这个顺序查，不要先改 CSS：

1. 运行目录里的文件是否已更新：`npm run sync:plugin` 后看目标文件时间与内容。
2. 页面 `link[data-theme-plugin]` 的 href 是否变化。
3. 用无缓存 fetch 读样式表文本，确认规则数或选择器存在。
4. 再读计算样式，判断实际生效值。
5. 最后才查令牌、选择器层级与主题覆盖顺序。

## 令牌与边界

- 先查 `docs/design/主题变量契约.md`，只用已声明的令牌；需要新令牌时先确认契约，不在主题里写死颜色。
- 主题只改契约允许的外观，不改变布局职责与组件结构。
- 同时检查浅色与深色；切换主题后确认旧主题样式已摘除、用户原值能还原。
- 插件目录与设置窗口是两套产物；改主题不影响 `build/frontend`，但设置页要看主题效果仍需重开窗口。
