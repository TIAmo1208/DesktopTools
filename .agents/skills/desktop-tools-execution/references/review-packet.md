# review-packet：独立审核包

交给另一模型/会话审核前，把材料写成一份审核包。目标是让审核者从同一份冻结事实出发，而不是从口头描述猜。

## 冻结

```powershell
git rev-parse HEAD
git status --short
git diff --stat
git diff > build/validation/审核包-<主题>.diff
```

- 审核期间不改文件、不暂存、不重写提交；工作区有无关改动时先说明，不混进审核范围。
- 修复后重新冻结、重新审核；旧审核结论不对应新代码。

## 模板

```markdown
# 审核包：<主题>

## 冻结
- 提交/分支：
- 工作区状态：
- diff 文件：

## 目标与不变量
- 要解决的现象：
- 必须保持的不变量：

## 改动范围
- 文件与职责：
- 明确不包含：

## 复现与验证
- 命令：
- 实际输出/退出码：
- 证据类型：软件模拟 / 浏览器断言 / 运行时探针 / 真机日志 / 人眼确认

## 风险与回归矩阵
- 受影响状态：
- 未覆盖：

## 待决问题
- （待补充）

## 审核输出格式
- 阻断项：file:line + 问题 + 必须的修法
- 非阻断项：建议与理由
- 结论：pass / needs_revision / reject
```

## 规则

- 审核者与实现者用不同模型/会话；审核者只读，不改代码。
- 证据必须来自当前冻结版本；准备完成、未执行、超时都不算通过。
- 审核 pass 只代表代码审查通过，不替代同产物真机验收。
- 阻断项修完后重新冻结并复审；非阻断项可以记录后延，不静默忽略。
