# 验收取证

执行验证时使用本页。层定义、判据与产物见 `docs/validation/验收流程.md`。

## 先跑哪条命令

1. 纯逻辑、契约、几何 → `node --test <测试文件>`，收尾跑 `npm test`。
2. React 组件、样式、交互 → 加跑 `npm run dev` + `npm run test:browser`。
3. Rust 侧平台代码 → `npm run test:rust`。
4. 需要真实宿主行为 → `.\scripts\后台启动程序.ps1 -Theme <主题>`，用户操作后读日志与退出码。

Rust 编译或测试前先设 `TMP` 到 `build\tmp`（见根 `AGENTS.md`），否则 `cl.exe D8050` 会阻断整条链。

## 优先在哪层取证

按 L0→L1→L2→L3 顺序，能落低层就不上高层。凡是能表达成返回值、尺寸、计数或计算样式的现象，必须在该层断言，不得用截图。

## 环境性失败

受限环境（沙箱、无交互桌面）下，`cargo test` 有固定的环境性失败项。判据是「除 `验收流程.md` §6 清单内、且报错为权限或前置条件类的用例外，0 失败」。**不得**因此重跑同一命令，也不得转而打开程序截图。

## 才允许启动程序截图的情况

只有 `验收流程.md` §4 列出的六项人眼项允许看画面，用户截图写进 `docs/validation/` 记录并标注时间。其余一律靠 L0–L2 或 L1 的数值断言。

## 禁止

- 无界重试；等待必须单次有界，超时即失败并给原因。
- 反复重启程序碰运气。同一现象重试两次仍无结论，回到 L0–L2 补断言。
- 用截图替代可数值化的断言。
- 用低层结论冒充高层：L0 通过不等于宿主传参正确，L1 断言页 PASS 不等于真实宿主通过（页面桥接是模拟的）。
- 复用受测源码或配置已变化的旧证据。

结论标注属于哪一类：软件模拟、浏览器断言、真机日志、人眼截图。L3 结论来自 Debug 构建，不能作为 Release 验收结果。
