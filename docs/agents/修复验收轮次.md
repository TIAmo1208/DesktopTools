# 修复验收轮次

本页规定**修复类改动**（缺陷修复、回归修复、对现有行为的改造）从复现到交付的轮次顺序与出口。证据层、判据与命令以 `docs/validation/验收流程.md` 为准，命令入口见 `docs/agents/验收取证.md`，构建前提见 `docs/agents/构建运行.md`，TMP/互斥体/产物见 `docs/agents/环境前提.md`；本页只编排执行顺序，不重复层定义、阈值与取证细节。

新增功能、界面设计变更仍按需求分流与设计确认流程走，不套用本页。

## 核心原则

1. **制品一致**：调试和验收必须使用同一份构建产物。每次调试前构建，并在运行实例上核对版本或构建哈希；只跑源码断言、没有重建运行产物，不算调试。
2. **复现同层**：缺陷在哪一层，就在哪一层写会失败的复现。纯逻辑用单测；样式与交互动用浏览器断言；原生窗口与合成用窗口盒采样或录屏。至少覆盖缺陷所在层。
3. **审核冻结**：独立审核针对冻结的 diff 或 commit，审核期间不改文件、不暂存；调试发现的问题回炉后重新审核。审核通过只代表代码审查通过。
4. **用户终端门**：用户可见的缺陷以用户真机确认为准；单测、断言、审核 pass 都不等于验收通过。
5. **收尾清理**：每轮测试、取证或真机验证结束，都结束本轮启动的进程与临时资源（开发服务器、无头浏览器、开发版实例、后台任务、临时目录），确认端口释放、内存回落后再进入下一步；下一轮必须拿到干净环境，而不是上一轮的残留。

## 轮次流程

| 步骤 | 动作 | 出口条件 |
| --- | --- | --- |
| 0 复现分级 | 固定复现条件，记录构建、显示器与 DPI、贴边/形态/动效开关与操作序列，选定证据层 | 有一份对当前代码稳定失败的复现 |
| 1 定位 | 读代码、日志与现场证据，写清不变量、影响面与回归矩阵 | 根因可证，矩阵覆盖受影响的状态组合 |
| 2 修复与红绿测试 | 先让复现失败，再修到通过；补纯函数与同层断言 | 复现由红转绿，受影响单测/断言通过 |
| 3 构建与制品核对 | 构建真实产物；在运行实例核对版本或构建哈希 | 运行实例与源码一致 |
| 4 独立审核 | 冻结 diff 交另一模型审核，逐条处理发现 | 无阻断项；修复项重新审核 |
| 5 同产物真机验证 | 用同一产物复现原场景并跑回归矩阵，用户确认 | 用户确认修复，回归项通过，证据留档 |
| 6 暂存与同步 | 只暂存通过验收的改动，同步受影响的事实文档 | 暂存范围与验收范围一致 |

任一步失败：带上证据回到步骤 1，不直接改代码进入下一轮；不得跳过步骤 3、5 宣布完成。每步结束按「每轮收尾清理」结束本轮启动的进程，确认无残留后再进入下一步。

## 步骤细则

### 0 复现分级

- 记录：构建版本、显示器与 DPI、贴边方向/形态、动效开关、触发的指针或拖动序列。
- 选择最低但足够的一层；能表达成返回值、尺寸、计数或计算样式时，先在 L0–L2 或 L1 收口，不靠截图。必须看合成结果时才升级到真机录屏，并按 `docs/agents/取证工具.md` 取得同意。
- 复现必须对当前代码稳定失败；偶现问题记录频率与触发条件，不把一次未复现当作修好。

### 1 定位

- 写清不变量（几何、层级、可见性、输入归属、坐标空间）与破坏它的路径。
- 列出回归矩阵；新增图层、遮罩、原生尺寸变化、坐标系变化或事件订阅时，必须扩充矩阵。
- 先证明根因再改实现；不确定时保留最小排查手段（日志、探针、窗口盒采样），不在多个假设间反复试改。

### 2 修复与红绿测试

- 先写或保留失败复现，再改实现；修复后同一复现必须通过。
- 单测覆盖纯函数；DOM/动画断言覆盖元素位置、样式与逐帧状态；原生侧补窗口盒、尺寸序列或返回值断言。
- 断言要能区分“旧代码失败、新代码通过”，否则不算回归测试；新增测试必须进既有测试入口或断言页清单，不能只留临时脚本。

### 3 构建与制品核对

- 前端改动：`npm run build`；Rust 改动：按 `docs/agents/构建运行.md` 构建；主题或插件改动：先 `npm run sync:plugin`，再确认运行目录里的文件已更新。
- 开发版、设置窗与岛页等独立窗口可能加载不同产物；确认被测窗口实际加载的构建，而不是只看源码断言或 Vite 热更新。
- 记录构建时间或哈希；重启后再验证，避免拿到旧进程。
- 制品以**最后一次代码变更**为准：审核后修复又改代码，必须重建并重新绑定哈希；修复前的构建不能用于步骤 5。
- 只改注释或事实文档时按影响补验（`typecheck` + 受影响单测），不重跑全量矩阵；在验收记录里写明补验依据。

### 4 独立审核

- 输入是冻结的 diff 加复现用例与证据，不是口头描述；审核对象在审核期间保持不变。
- 审核包按 `.agents/skills/desktop-tools-execution/references/review-packet.md` 准备；审核者与实现者使用不同模型。
- 审核项：正确性、回归风险、测试有效性、文档一致性；发现按阻断/非阻断分级，阻断项必须修完并复审。
- 文档一致性看**因果句能否指向代码或几何证据**：解释性长句与实现不符时按 finding 处理，不接受“文字大意正确”。
- 独立审核不替代步骤 5；审核 pass 只说明代码审查通过。

### 派单与范围

- 任务范围（`inScope`）按验收反推列全：验收要求补断言 → 列断言页与测试文件；要求同步文档 → 列 `CONTEXT.md`、相关 ADR 与设计文档；可能改原生 → 列对应 Rust 文件与清单。
- 验收项点到某类文件，该类文件就必须出现在范围里；否则会出现“工作完成、记录因越界拒绝收口”。
- 审核 finding 只涉及表述时，修复任务的验收限定为“文字与实现一致、行为不变”，并保留行为断言作为回归。

### 5 同产物真机验证

- 用与步骤 3 相同的产物，由用户按检查清单操作；至少覆盖原缺陷场景与回归矩阵。
- 证据按 `docs/validation/验收流程.md` 的分层留档；不把“准备完成”“未执行”“超时”当作通过。
- 用户确认前不得宣称修复完成；未验证范围在交付说明中明确列出。

### 6 暂存与同步

- 只暂存通过验收的文件；不带入调试脚本、临时日志、旧产物或未验收的顺手改动。
- 同一行为变更与受影响的事实文档同步；验收记录写清证据与未验证项。
- 暂存不是质量门；需要候选快照时明确标记 WIP，验收通过后再进入正式提交。

### 每轮收尾清理

- 时机：步骤 2 的断言/测试、步骤 4 的审核取证、步骤 5 真机验证，每次结束时都执行；一轮内多次调试按最后一次结束清理。
- 范围：本轮启动的开发服务器（`npm run dev`，127.0.0.1:1420）、无头浏览器及其 `--user-data-dir` 临时目录、开发版 `desktop-tools.exe` 实例、断言脚本与后台任务、临时抓图/录屏工具。只结束本轮启动的进程树，不碰用户日常浏览器、已安装实例和用户正在使用的窗口。
- 做法：后台任务用任务句柄结束；有可见 Edge 窗口时只按本轮进程树结束，没有可见窗口时可清理全部无头残留（`scripts/跑断言页.mjs` 在启动与收尾各做一次），再删除本轮 `--user-data-dir` 临时目录。
- 判据：断言端口不再监听（如 127.0.0.1:1420）；任务列表与后台任务列表没有本轮进程；临时目录已删除；内存占用回落到清理前水平。残留的无头浏览器与开发服务器会跨轮累积内存，并因端口、文件句柄被占用让下一轮出现“环境性失败”。
- 不清理：步骤 3 的构建产物（`build/frontend`、debug 可执行文件）留给步骤 5 做同一产物验证，不删除、不重建；只清运行实例与临时资源。
- 记录：验收记录或交接里写清结束了哪些进程、哪些被有意保留，便于下一轮核对环境。

## 风险缩放

| 变更类型 | 可省略 | 不可省略 |
| --- | --- | --- |
| 纯样式/文案 | 独立审核 | 构建、同层复现、用户确认 |
| 组件/交互 | 无 | 断言页、独立审核、真机确认 |
| 原生窗口/合成/DWM | 无 | 窗口盒采样或录屏、独立审核、用户确认 |

## 常见失效方式

- 只跑单测或源码断言，运行实例还是旧产物。
- 审核期间继续改文件，审核结论对应不到最终代码。
- 用“审核 pass”代替真机验收。
- 只测默认分支（默认边/形态/动画），回归矩阵未覆盖。
- 把一次未复现当作修复，或把准备、未执行、超时算作通过。
- 断言页、取证脚本或真机验证跑完不结束无头浏览器和开发服务器，多轮后内存与端口堆积，把下一轮的环境性失败误读成修复失败。
- 收尾清理时连步骤 3 的构建产物一起删掉或重建，步骤 5 实际验证的是另一份产物。
- 新图层或新坐标系上线时没有扩断言，等用户真机撞出换边残留、颜色不一致一类问题。
