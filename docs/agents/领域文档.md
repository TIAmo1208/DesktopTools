# 领域文档

## 阅读顺序

开始分析项目前：

1. 阅读仓库根目录的 `CONTEXT.md`。
2. 当 `CONTEXT-MAP.md` 存在时，阅读与当前任务相关的上下文。
3. 阅读 `docs/adr/` 下与当前任务相关的架构决策。
4. 多上下文仓库还需检查各上下文目录中的 ADR。

相关文件缺席时，继续依据当前仓库证据工作。`domain-modeling` 流程会在领域术语和架构决策明确后创建这些文件。

## 仓库布局

本仓库采用单上下文布局：

/
├── CONTEXT.md
├── docs/adr/
└── src/

使用 `CONTEXT.md` 定义的标准领域术语。通过 `domain-modeling` 记录真实存在的术语缺口。

当工作内容与现有 ADR 冲突时，明确指出冲突，并说明重新评估该决策的原因。

维护 ADR、CONTEXT 及关联事实文档时，遵循根目录 `AGENTS.md` 的“事实文档维护”规则；确认变化后直接同步权威原文，避免保留互相冲突的定义。

## 文档输出

输出文档时，正文内容和文档文件名默认使用中文。命令、协议字段、接口、类型、枚举、设备标识、文件路径及其他需要精确检索的技术标识保留原文，以确保可执行性和可检索性。

根目录 `README.md` 是项目功能介绍文档；`src/README.md` 和 `src-tauri/README.md` 分别是前端与 Rust/Tauri 的目录结构介绍文档。三份 README 说明当前实现，不作为领域事实来源；未实施的架构方案保存在 `.scratch/`，确认实施后再同步实际目录和相关事实文档。
