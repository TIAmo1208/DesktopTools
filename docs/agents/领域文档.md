# 领域文档

## 阅读顺序

开始分析项目前：

1. 按三级标题定位 `CONTEXT.md` 中与当前任务相关的小节，不整读全文。领域语言按节组织，运行不变量在文末。
2. 当 `CONTEXT-MAP.md` 存在时，阅读与当前任务相关的上下文。
3. 阅读 `docs/adr/` 下与当前任务相关的架构决策。
4. 多上下文仓库还需检查各上下文目录中的 ADR。

相关文件缺席时，继续依据当前仓库证据工作。`domain-modeling` 流程会在领域术语和架构决策明确后创建这些文件。

## 文档分层

按加载时机分四层，新增文档先判断它属于哪一层，再决定写在哪：

| 层       | 文件                                                  | 加载时机                     |
| -------- | ----------------------------------------------------- | ---------------------------- |
| 常驻     | `AGENTS.md`、全局 `~/.dsh/AGENTS.md`                  | 每轮都在上下文里             |
| 领域事实 | `CONTEXT.md`、三个 `README.md`                        | 改功能前按小节定位           |
| 决策     | `docs/adr/`                                           | 触及已定架构时读相关几份     |
| 按需场景 | `docs/agents/`、`docs/design/`、`docs/validation/`     | 命中 `AGENTS.md` 路由表时加载 |

常驻层只放两类内容：任何任务都要遵守的硬约束，以及「什么情况读哪份文档」的路由。其余一律下沉到按需层，靠路由表的触发条件召回。

## 编写规范

- **单一事实源**：同一含义只写在一处，其他位置用链接指过去。发现两处各自完整复述时删掉一处，不保留两个版本。
- **分支标题**：单份文档超过 120 行必须用二级或三级标题分节，标题取读者要跳转的领域，不取写作顺序；分节后单节仍超过 300 行时拆成独立文件，原位置留一行链接。
- **可判定措辞**：约束写成「触发条件 → 必须动作」，或给出反例；不做无法判定做没做到的模糊表述，禁用词表由 `scripts/检查文档规则.mjs` 持有。
- **机械可查优先**：能用脚本判定的规则先写进 `scripts/` 并挂到 `npm test` 或 `npm run check:commit`，文档只留脚本判不了的原因、边界与例外。
- **同步方向**：描述性事实（术语细节、目录说明）跟随代码，代码是真相；规范性约束（决策、门槛、白名单）由 ADR 持有，代码服从。数值门禁必须标注方向并在失败信息里写明改哪一侧，避免反向改代码去迁就过期文档。
- **条款有主**：每条规则写明它管哪类改动；不再约束任何改动的条款直接删，不留在文档里等以后有用。
- **不靠语气**：约束力来自条款可判定与门禁，不靠堆「必须」「严禁」「重要」；同一份文档内不重复强调同一件事。

## 归档与失效

- 结论仍然生效的部分必须写进当前事实文档（`CONTEXT.md` 或生效中的 ADR），不能只存在于被取代的 ADR 里。
- ADR 被取代时，在新 ADR 写取代关系，并在旧 ADR 顶部加一行指向新 ADR；旧文件保留作溯源，不继续承担约束。
- 索引与路由只列生效项。归档等于从「当前生效」的路径上摘掉，并删掉所有指向它的链接；文件留在磁盘上、链接还在，都不算归档。
- 删除文档前先在仓库内搜文件名与标题，确认没有入链，再连同其失效条款一起删。

维护 ADR、CONTEXT 及关联事实文档时，遵循根目录 `AGENTS.md` 的「事实文档」一节；确认变化后直接同步权威原文，避免保留互相冲突的定义。

## 仓库布局

本仓库采用单上下文布局：

```text
/
├── CONTEXT.md
├── docs/adr/
└── src/
```

使用 `CONTEXT.md` 定义的标准领域术语。通过 `domain-modeling` 记录真实存在的术语缺口。

当工作内容与现有 ADR 冲突时，明确指出冲突，并说明重新评估该决策的原因。

## 文档输出

输出文档时，正文内容和文档文件名默认使用中文。命令、协议字段、接口、类型、枚举、设备标识、文件路径及其他需要精确检索的技术标识保留原文，以确保可执行性和可检索性。

根目录 `README.md` 是项目功能介绍文档；`src/README.md` 和 `src-tauri/README.md` 分别是前端与 Rust/Tauri 的目录结构介绍文档。三份 README 说明当前实现，不作为领域事实来源；未实施的架构方案保存在 `.scratch/`，确认实施后再同步实际目录和相关事实文档。
