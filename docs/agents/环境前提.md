# 环境前提

本页是 TMP、互斥体、产物路径、1420/Edge、0xC0000142 与工具读取失败的单一来源。其他文档只保留现象与链接，不重复展开。

## TMP

`npm run test:rust`、`npm run tauri:dev`、`npm run tauri:build`、`npm run tauri:installer` 已通过 `scripts/with-tmp.mjs` 注入 `TMP=build\tmp`，不需要先手动设置。

直接调用 `cargo` 时仍需在当前命令行会话设置（只设 `TEMP` 无效）：

```powershell
New-Item -ItemType Directory -Force "$PWD\build\tmp" | Out-Null
$env:TMP = "$PWD\build\tmp"
cargo check --manifest-path src-tauri/Cargo.toml
```

漏设时 `ring` 等 C 依赖会报 `cl.exe D8050`，整条 Rust 侧构建无法进行。先查 TMP，不要换 MSVC 版本、调整 `_CL_`、`/Z7`、`/Brepro` 或排查安全软件。

## 已安装实例与互斥体

开发版启动前先正常退出已安装实例。桌面菜单互斥体 `Local\DesktopTools.DesktopMenu.Instance` 被占用时，开发版按副实例处理：exit 0，日志止于「初始化完成」，没有窗口。

看到「exit 0 + 无窗口 + 日志止于初始化完成」按互斥体处理，不要当成启动成功；先查 `tasklist /FI "IMAGENAME eq desktop-tools.exe"`。

## 低完整性启动拒绝

工作区目录带 Low 强制完整性标签时，其中的 `build\target\debug\desktop-tools.exe` 会以低完整性启动。低完整性进程写不进 `%LOCALAPPDATA%` 日志目录，也无法跨进程附着 Explorer：旧行为是 `SetWindowPos` 返回「拒绝访问 (0x80070005)」后 Tauri setup panic（退出码 101）；现在启动前检查进程完整性，直接弹出「Desktop Tools 启动失败」原生对话框并以退出码 1 结束，提示里给出需要恢复标签的目录。

恢复工作区（或只恢复 `build` 目录）后重试：

```powershell
icacls "E:\Project\DesktopTools" /setintegritylevel "(OI)(CI)Medium"
icacls "E:\Project\DesktopTools\build\target\debug\desktop-tools.exe" | Select-String Mandatory
```

标签应为 `Medium`。开发者沙箱（例如 DSH 的 workspace-write 模式）会重新给工作区打 Low 标签；在该策略下启动仍会被拒绝，需要再次恢复标签或改在 danger-full-access 下运行。不要用管理员运行绕过。

## 产物路径

| 产物 | 路径 | 何时更新 |
| --- | --- | --- |
| 设置窗/桌面宿主前端 | `build/frontend` | 改前端后 `npm run build`，再重开设置窗 |
| 开发插件目录 | `build/target/debug/plugin` | 改 `plugin/` 后 `npm run sync:plugin` |
| Rust 可执行文件 | `build/target/debug/desktop-tools.exe` | `npm run tauri:dev` 或构建命令 |

- 设置窗加载 `build/frontend`，不是 Vite 页面；改完不重建会看到旧 UI。
- 桌面层浮层（格子右键菜单、确认框、天气弹窗）的页面同样取自 `build/frontend`：前端改动没重建时，弹层窗口建得出来但页面不上报尺寸，右键看不到菜单，日志里 5 秒后出现一条“页面没有上报尺寸”的错误并带上页面来源。看到这条错误先跑 `npm run build`，不要按窗口或平台问题排查。
- `npm run tauri:dev` 启动时打印前两项的实际路径。
- 插件目录名是 `作者@名称`；`sync:plugin` 按清单 id 复用已有目录，默认跳过示例。

## 端口、无头 Edge 与后台任务

- 断言页依赖 `127.0.0.1:1420` 的 `npm run dev`；被其他进程占用时运行器打印 PID 与进程名并 exit 2，按环境问题处理。
- 断言与 Rust/前端构建串行执行；并发会互相等锁，制造 CDP 超时。
- 收尾确认 1420 无监听；无可见 Edge 窗口时清理本轮无头残留。只结束本轮启动的进程，不碰用户日常浏览器与已安装实例。
- 后台任务句柄不跨回合：长任务在同一回合内分块，或把结果增量写入 JSONL/日志后再汇总。

## 命令无输出（0xC0000142）

任何命令都拿不到输出（包括 `echo hi`、`git --version`、`cmd /c echo`），退出码 `3221225794`：这是进程启动阶段 DLL 初始化失败，命令根本没被执行。

判定顺序：

1. 先跑最小命令；同样无输出即判定为环境级失败。
2. 这是宿主执行环境问题，不是项目、脚本或上游工具的问题。
3. 按当前会话的权限策略处理环境，恢复后用最小命令确认，再跑原任务。

不要逐条重试业务命令，也不要换工具链碰运气。它与 `cl.exe D8050` 不同：后者有输出、发生在编译阶段。

## 工具读取失败

`ops_read_files`、`ops_glob` 或官方 `read` 报 `dsh-ops-worker.exe ENOENT`：dsh-ops 运行器缺失或被杀软隔离。先改用 `bash`/`ops_inspect_local_file` 完成当前任务，再把修复 dsh-ops 作为独立事项；不要每次读取都重复重试。
