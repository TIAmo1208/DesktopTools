# 设计确认流程

新增界面或改变信息层级、布局、操作流程、控件、视觉样式前按本页执行。视觉数值基线见 `docs/design/视觉规范.md`；CSS 归属见 `docs/design/CSS约定.md`。

## 触发条件

- 仅在新增用户界面，或主动改变现有界面的信息层级、布局、操作流程、控件或视觉样式时，进入设计确认流程。
- 根据用户请求的实际变更内容判断，不因修改 TSX、CSS、前端代码，或结果能够在画面上观察到，就触发设计确认流程。
- 实现方式由 Agent 查证并决定；本流程只要求确认尚未明确的产品交互、信息布局或视觉设计选择，其他事实文档的约束仍须遵守。

## 按变更类型执行

- 新增界面，或改变信息层级、布局、操作流程：按「UX 方案 → 用户确认 → UI 方案 → 用户确认 → 实现与验证」执行。
- 仅改变颜色、字体、间距、尺寸、图标样式等视觉表现：按「UI 方案 → 用户确认 → 实现与验证」执行，无需重新进行 UX 确认。
- UX 阶段使用 Penpot 输出可评审的信息层级、布局线框、操作流程、状态与异常处理及取舍；UI 阶段基于已确认的 UX 和视觉规范，明确尺寸、间距、字体、图标、主题与交互状态。各阶段交付后等待用户确认，再进入后续阶段。
- 同时涉及功能实现和界面设计时，仅依赖设计决定的部分等待确认；可以先完成不依赖设计决定的文档、后端及其他实现工作。

## 不触发设计确认的修改

以下修改在沿用已确认交互、布局与视觉规范时，直接实现并验证：

- 后端逻辑、API 接入、数据来源、线程、缓存及性能优化。
- 在现有控件中呈现真实数据、系统图像或媒体内容。
- 修复与已确认规范不一致的显示错误，例如图片拉伸、文字截断、状态未更新或主题样式遗漏。
- 落实用户已明确指定、无需进一步设计取舍的局部显示要求。

例如：将现有文件图标接入 Windows Shell 缩略图，保留既有图像外框、布局与交互，并落实用户明确要求的“不显示音乐角标、视频边框和快捷方式箭头”，无需重新制作 Penpot UX/UI 稿；应验证比例、透明度、加载回退和拖动显示。

## 设计产物与阻塞边界

- 需要设计确认时使用 Penpot。同一功能的 UX 或 UI 调整分别复用现有对应页面；只有新增功能或确实不存在对应页面时才创建新页面，不因迭代重复创建页面。
- 已明确确认的要求不重复确认；只有新增设计选择或与既有事实文档冲突的部分需要再次确认。既有代码和未验证改动不视为新设计方案已经确认。
- Penpot 不可用只阻塞需要 Penpot 交付的设计工作，不阻塞无需设计确认的代码修改、文档同步及验证；与本流程无关的其他阻塞仍按“计划与执行”规则处理。
- 所有界面相关修改仍须遵守视觉规范并执行适当的视觉和交互验证；免除设计确认不等于免除验证。

## 视觉基线

- 修改 UI 前必须阅读 `docs/design/视觉规范.md`。
- 已有界面以当前组件实现和视觉规范共同作为视觉基线。
- 颜色、尺寸和间距优先复用现有 CSS 变量与组件规则，不创建近似值。
- 需要偏离视觉规范时，先说明偏离内容、原因和影响，取得用户确认后再修改。

## 图标资源

- 图标属于实现细节，不进入 UX/UI 确认内容。画板用占位框表达“此处有图标”即可，不为挑图标类型反复确认；评审关注尺寸、命中区、状态与位置，不关注具体字形。
- 实现阶段按视觉规范给出的尺寸、命中区与状态，从开源图标库获取可用图标，保存为 SVG 到 `resources/`，通过既有资源引用方式加载；不引入图标字体，不为单次使用新建内联图标组件。
- 图标颜色由样式控制：资源本身不写死主题色，或统一映射到对应 CSS 变量；命中区、尺寸与状态变体由使用方样式定义。
- 同一含义在全应用使用同一个图标资源。新增图标前先查 `resources/` 是否已有同义资源，避免同一含义出现两套字形。
- 记录所引入图标库的名称与来源，并在根 `README.md` 的功能边界中按需说明第三方资源归属。
