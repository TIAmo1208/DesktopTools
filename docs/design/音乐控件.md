# 音乐控件

## 定稿范围与实现来源

当前音乐控件的布局与视觉参数已由用户定稿，以 `src/features/tile-content/music/MusicControl.tsx`、同名 CSS 和 `musicLayout.ts` 的当前实现为准。视觉定稿不等同于所有原生交互与动画场景已完成验收。

歌词区已按本文件「歌词区布局与三态」实现；改动时不得自行改变阈值、行数规则、字号与颜色。

公共表面、标题栏、主题和缩放规则沿用 [视觉规范](视觉规范.md) 与 [共享格子外观并隔离布局撤销](../adr/0018-共享格子外观并隔离布局撤销.md)。本文件不重新定义设置窗口的视觉方案。

## DOM 与布局归属

```text
music-control
├── music-control__artwork
└── music-control__body
    ├── music-control__metadata
    └── music-control__actions
```

封面直接归属根容器。右栏负责信息与按钮的纵向编排；宽布局顶部为信息、底部为按钮，紧凑布局将整个右栏贴底。

| 属性         | 宽布局                                 | 紧凑布局                     |
| ------------ | -------------------------------------- | ---------------------------- |
| 根容器内边距 | 0                                      | 6px                          |
| 封面         | 左侧正方形，顶部对齐                   | 绝对定位铺满根容器，居中裁切 |
| 左右列间距   | 12px                                   | 单列                         |
| 按钮宽度     | 三列，各列最大 88px，按钮最小宽度 24px | 固定 40px                    |
| 按钮高度     | 24px                                   | 24px                         |
| 按钮间距     | 11px                                   | 4px                          |
| 按钮组内边距 | 3px                                    | 3px                          |
| 按钮圆角     | 3px                                    | 3px                          |
| 图标         | 16 × 16px                              | 16 × 16px                    |

封面 CSS 当前公式为 `min((100cqw - 24px) × 0.4, max(0px, 100cqh))`。容器查询宽高来自外部音乐内容容器；宽布局根容器本身没有 padding，公式中的 24px 是显式扣除项。封面只读取已分配空间，不参与外框最小尺寸计算。紧凑布局覆盖该尺寸，使用根容器的全部宽高。

## 字体与显式间距

歌曲名称和艺人继承 `--interface-font-size`，默认 13px；来源字号为该变量的 `12 / 13`，默认 12px。字体继承项目界面字体，歌曲名称字重为 400；艺人和来源透明度为 0.78。

三行均使用 `line-height: max(16px, 1.2em)` 与 `height: 1lh`，元素高度对应一行行盒，空文本保留相同高度。网格行使用 `max-content`，不通过更大的固定轨道制造文字下方留空；当前行间距为 `gap: 2px`。文字单行截断，保留原生完整文本提示。

## 最小尺寸职责

`MusicControl` 使用私有 refs 和 `ResizeObserver` 测量信息及按钮组，通过 `onMinimumSizeChange` 上报内容需求；使用 `offsetHeight` 排除动画变换，不测封面或被外框拉伸后的右栏空白。

```text
内容最小宽度 = ceil(max(168, CSS min-width))
内容最小高度 = ceil(max(94, 信息区高度 + 按钮组高度 + 根容器上下 padding))
外框最小宽度 = 内容最小宽度 + 24
外框最小高度 = 内容最小高度 + 24 + 固定标题栏的 28
```

外层 24px 包含视口上下各 10px 的内边距，以及外壳两侧各 1px padding 和 1px border。`MusicWidget` 透传结果，`MusicTile` 只叠加外壳占用并交给公共几何交互。

默认字号下，信息区为 `16 × 3 + 2 × 2 = 52px`，按钮组为 `24 + 3 × 2 = 30px`。宽布局内容需求 82px，紧凑布局内容需求 94px，均取 94px 保底，因此固定标题外框最小基线为 `192 × 146px`。较大字号可能提高高度下限；降低下限不会自动缩小已保存的外框。折叠状态只显示 28px 标题轨道。

## 模式切换与动画

`musicLayout.ts` 依据宿主内容盒宽度（组件 client 宽度，含自身 padding）及字号判断模式，高度不参与选择。当前下界公式为 `ceil((144 × fontSize / 13 + 12) / 0.7) + 5`。

默认 13px 字号：宽布局在内容宽度 ≤228px 时进入紧凑，紧凑在 ≥244px 时进入宽布局，中间保持原模式；初次以 236px 为分界。大字号提高阈值。

仅跨模式时执行 180ms ease-out 过渡：封面平移与缩放，信息和按钮所在区域仅平移，字体与图标不缩放。连续切换采样当前呈现位置并取消旧目标。有效动画状态由 `PreferencesProvider` 按 `followSystemReducedMotion` 选择 Windows 减少动态效果状态或 `interfaceAnimations`；动画关闭时立即切换。

## 主题、媒体与可访问状态

表面沿用围栏 58% 半透明主题。紧凑且封面成功加载时，使用白色文字与黑色遮罩：顶部透明度 12%，40% 位置为 35%，底部为 82%。无封面或加载失败时恢复对应主题，不显示失效图像；信息和按钮不移位。

无会话时保留空信息与禁用按钮。按钮保持中文可访问名称，图标不参与辅助技术及指针命中；禁用透明度 0.48，键盘焦点为 2px 描边、1px 偏移。播放中按钮为暂停，其他状态为播放；不支持的动作和命令执行期间禁用。错误继续交给现有消息管道。

## 浮岛上的音乐卡

浮岛卡与桌面格子是两条呈现路径：浮岛上的音乐卡不复用 `MusicControl` 的宽/紧凑两套布局，也不吃「最小尺寸 + 24px 外壳 + 28px 标题轨道」那套几何；它按浮岛的三种形态各自排版，像素值与令牌见[浮岛](浮岛.md)。

| 形态 | 内容 |
| --- | --- |
| 常态 | 圆形媒体图 ＋ 一行歌词；歌词不可用时依次回落「歌名 · 艺人」和播放状态；尺寸按有无同步词固定为档位值，超出内容盒的当前行按播放进度滚动 |
| hover | 媒体图、歌名、艺人、媒体输出应用、上一首 / 播放暂停 / 下一首 |
| 展开 | hover 的内容 ＋ 进度条、频谱条带、歌词区（当前句加重，前后各一句） |

- 常态胶囊按有无同步词固定尺寸：横向 `240` / `168`，竖向 `176` / `96`，竖向最小 `52`（胶囊外框，内容盒再减 `52` 固定件）。尺寸只随有无同步词与贴边方向提交，换句不重设窗口；超出内容盒的当前行按播放进度滚动：横向文本向左平移（阅读位置从左往右推进），竖向自上而下；暂停冻结在当前偏移，切歌与跳转按新位置重新对齐，末句后停在末位。无同步词（含首句前）时回落文本慢速往返循环；减少动效时改为单行截断、不滚动。
- 滚动只位移合成层，不改变卡片与窗口尺寸，也不触发浮岛测量：尺寸只随有无同步词与贴边方向提交，滚动与换句都不重新测量、不提交窗口，避免播放中重设窗口造成的高度抖动。尺寸与滚动细节见[浮岛](浮岛.md)。
- 歌词走外部源，不读播放器自带歌词；未取到词（取词中、无匹配、纯音乐、失败）时回落「歌名 · 艺人」或播放状态，并按无词档位收缩（横向 `168`、竖向 `96`），播放控制保持可用。
- 展开态媒体图与右侧信息列等高并保持正方形；切换形态时媒体图圆角跟随外框。
- 无会话时常态显示「未在播放」，hover 控制保留但禁用，图标透明度 `0.48`。
- 当前浮岛频谱只消费既有音频采集事件，不启停全局采集；仅有浮岛且没有采集消费者时保持 `18px` 高的基线。浮岛按需启动采集须以后端支持消费者引用计数为前提，避免收起浮岛停掉桌面格子的采集。

## 桌面格子的歌词与共享数据源

播放时间轴与歌词是桌面格子与浮岛共用的第二类事实，不是某一表面私有：Rust 侧统一读取时间轴并从外部源取词，经独立事件下发；前端只有一份音乐状态源，桌面格子与浮岛卡都从这一份取快照、时间轴与歌词，不各自建立订阅或请求歌词。

当前实现由 `src/features/music/musicSource.ts` 持有模块级源与引用计数订阅，`MusicWidget` 与浮岛卡都以 `useMusicState` 读取；播放位置用 `performance.now()` 本地锚投影，歌词为按 `startMs` 升序且时间戳唯一的 `{startMs, text}` 数组。Rust 取词先按当前播放源切换歌词源：网易云（`cloudmusic.exe`）先查其公开 web 接口（`api/search/get` 与 `api/song/lyric`，只带 `Referer`，不登录、不解密），同名同艺人按搜索顺序取第一条有同步词的版本；失败或未登记来源回退 LRCLIB。取词随后把标题、艺人统一为简体，并按破折号分段处理标题：只剥离明确的描述性副标题（影视、动画、游戏出处等），`Live`/`Remix`/`Radio Edit`/`Remastered`/`伴奏` 等版本标识与未知后缀都保留，版本不同不共用歌词；前导破折号不会把标题截成空，半角连字符仅在带空白时视为分隔，避免切断 `G-Eazy` 一类曲名。标题归一后相等；艺人有时长时允许相等或包含，无时长时要求严格相等。有时长时取 `±2` 秒内最接近者，距离并列时只有歌词一致才接受；播放器不填时长时（如网易云只发元数据）先合并全部查询变体的候选，再把简体解析后的歌词结构去重，只有唯一结构才接受，已知冲突保持空态。查询依次尝试简体/繁体字形与是否带艺人；歌词文本统一按简体显示，避免与简体界面混排。

### 无时间轴播放器

网易云的媒体会话要先在客户端设置里打开系统媒体控制（SMTC），否则系统层没有会话、格子保持空态。播放器只发元数据、把 `Position` / `EndTime` / `LastUpdatedTime` 全报为 0（如网易云）时，时间轴按受支持输入处理，而不是冻结整条链路：

- Rust 在 `Playing` 状态下按本地单调时钟外推位置；暂停与停止把已外推位置冻结为新锚点；会话或曲目变化重置为 0。若播放器确实上报了非 0 的公开 `Position`，把它当作新锚点重置（best-effort）。真实时间轴仍按 `LastUpdatedTime` 外推，行为不变。
- 协议中 `durationMs = 0` 表示播放器不提供时长（未知），负数无效；此时 `positionMs` 可以大于 0。前端 `positionAt` 只在 `durationMs > 0` 时夹紧，`lyricTickDelay` 只以「没有下一句」停止，因此逐句跟随不依赖时长是否有效。
- 客户端以 `--remote-debugging-port=9222` 启动时，后端按秒经 CDP 读取播放条位置与总时长并推送，前端仍只接收事件；端口未开、页面未就绪或选择器变化时回退本地外推。实测目标页为 `orpheus://orpheus/pub/app.html`，播放条选择器 `[class*=StyledSliderContainer] input` 仍命中、读数与滑块一致；调试端口是客户端启动参数，运行中无法追加。
- 回退本地外推时没有可用的 `Position` / `LastUpdatedTime`（网易云 `Position` 恒 0），无法检测拖动跳转：应用不宣称跳转立即对齐；CDP 可用时以每次读数为新锚点，跳转在下一秒内对齐。
- 零时间轴末句没有下一句、又没有真实时长时，没有可审计的结束时间：动效开启时回退慢速循环、不裁切；减少动效仍按单行截断（竖排为静止裁切）。进度停在歌词末行时间戳。
- 浮岛展开的进度条量程优先用真实时长；播放器不报时长时用歌词源返回的时长兜底（网易云接口在搜索结果里给出毫秒时长），再缺失时用歌词末行 `startMs`；三者都缺失时只显示已播放时间，总时长显示占位 `--:--`，不画满格假进度。
- 不新增媒体轮询或 `rAF` 常驻循环；仅网易云零时间轴且调试端口可用时由后端按秒读取 CDP，前端不参与轮询。

### 歌词区布局与三态

歌词区是格子自身的内容块，与封面、右栏（信息、频谱、按钮）并列；判定只看宿主分配的内容盒（不含 `28px` 标题轨道与外壳）的宽高，先看高度再看宽度；不继承宽/紧凑布局的当前模式，但同一歌词形态在阈值内侧保留 `16px` 滞回，频谱开关不参与判定。

| 条件 | 布局 | 歌词区 |
| --- | --- | --- |
| 有同步歌词且内容高 ≥ `168px` | 歌词在下（优先） | 通栏，宽 = 内容宽；高 = 内容高 − 正文下限 − `6` |
| 有同步歌词、内容宽 ≥ `420px`、内容高 < `168px` | 歌词在右 | 固定宽 `156px`，列间距 `12px`，高 = 内容高 |
| 其余，或当前没有同步歌词 | 无歌词区 | 收起，不占位 |

- 高度达标即用下方，此时宽度再大也不切右侧；宽高同时达标取下方。宽/紧凑布局仍只由内容宽度与字号选择，高度只参与歌词区判定。阈值两侧保留 `16px` 滞回，与音乐布局模式共用同一档位，阈值附近来回拖动不反复切换。
- 取词中、无匹配、取词失败、无会话一律收起歌词区，拿到同步词后展开，切歌无词时收起；收起状态不保留空白。
- 下方模式把封面限制在正文下限高的媒体区，右侧模式为正文保留 `128px` 并反算封面，避免封面压住歌词或按钮溢出；正文下限默认 `94px`，打开频谱或大字号时按实际内容抬高。封面、信息与按钮不因歌词区改变自身样式。
- 紧凑布局（内容宽 < `236px`）里封面铺满整格，歌词排在底部信息和按钮上方、叠在封面下半部，宽 = 内容宽 − `12px`，压暗遮罩延伸到歌词区。
- 行数不设上下限，按实际行高累加能放几行放几行：`13px` 行高 `16px`、当前句 `14px` 行高 `17px`、翻译 `12px` 行高 `16px`、行间距 `2px`。已唱在上、当前句居中、未唱在下，当前句始终可见。
- 单行截断、不做逐字高亮；换句位移分已播放/未播放两段：已播放行立即 `220ms`，当前句与未播放行延迟 `80ms` 再 `240ms`（延迟段 `fill: backwards` 停在起始位移）；当前句字号与颜色 `200ms`（延后 `80ms`），其余句 `140ms` 立即回落；减少动效时直接切换。歌词区不接收指针与键盘焦点。
- 频谱与按钮不受影响：信息、频谱条、播放按钮同属右栏一个容器且同宽，频谱开关只改变右栏内部高度，不改变歌词列宽与行数。

字号与颜色：当前句 `14px`、`--fence-text` 100%；其余句 `13px`、62%；翻译 `12px`（= 当前 −2）、52%。当前句只靠字号更大与颜色更深区分，不加粗。歌词不新增颜色令牌；紧凑布局且有有效封面时沿用白色文字与遮罩规则。

翻译行跟随当前句占一行，仅在歌词区能多容纳一行时显示；翻译行同样高 `16px`。当前 `LyricLine` 只有 `startMs`、`text` 与可选 `translation`，本轮 Rust 不取翻译，缺字段时不占行。

设置：音乐设置提供「显示歌词」，位于「显示媒体来源」之下、「显示实时频谱」之上，复用「显示实时频谱」那一行的排版与开关控件，字段 `musicLyricsEnabled`，默认开启；关闭后不取词、不显示歌词区。

动画：模式切换与歌词区展开/收起共用 `180ms` ease-out。封面、信息与按钮按切换前后的实际位置做 FLIP 位移，文字与图标不缩放；歌词区从 `0` 过渡到目标尺寸并淡入，收起反向；切歌时旧歌词 `120ms` 淡出，逐句更新做 `120ms` 交叉淡化；换句已播放行立即位移 `220ms`，当前与未播放行延迟 `80ms` 再 `240ms`（`fill: backwards`），当前句字号与颜色 `200ms`（延后 `80ms`）、其余句 `140ms`；界面动画关闭或系统减少动态效果时直接切换。

## 验证边界

统一原生拖放按 [ADR-0017](../adr/0017-分离系统拖放与布局投放结果.md) 的媒体白名单接收单个文件，复用系统默认打开入口，不增加新的播放界面。打开后沿用现有媒体会话更新，不保证自动播放，也不向原全局会话补发播放命令。此次用户授权复用已有界面并跳过单独 UX/UI 设计确认；真实播放器响应仍需实机验收。

当前代码的封面比例为 40%，而阈值函数仍保留按 30% 封面推导的 `/ 0.7`。判定已统一使用宿主内容盒宽度，两种模式的 padding 不再改变判定宽度；`16px` 的函数滞回仍不等于根容器上的同等切换间隔。这些是当前实现事实，临界宽度下右栏可读性及实际切换区间需单独验收，不能视为已验证一致。

需在当前原生宿主核对：阈值往返拖动、窄高与宽矮、12–18px 字号、长文本、封面失败、连续动画中反向切换、动画开关跨窗口同步、跟随开关与系统减少动态效果组合及真实壁纸对比度。本次文档定稿只核对源码与文档一致性，不补记未经执行的运行时验收结果。

歌词区另需核对：`420 × 94` 与 `168 × 168` 两个阈值在真实拖动下的往返、无词收起与词到达展开的动画、行数随高度增减、当前句与其余句的对比度、翻译缺失时不占行，以及关闭「显示歌词」后不发起取词。
