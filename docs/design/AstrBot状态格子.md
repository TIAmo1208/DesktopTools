# AstrBot 状态格子

本文记录「AstrBot 状态」插件的格子类型划分、信息层级、尺寸档位、状态语义与交互约定。视觉数值基线见 `视觉规范.md`；设计稿位于 Penpot「DesktopTools → AstrBot 状态 · UX」页面，画板 `00`—`08` 按 `00` 到 `08` 从左到右排成一行。

## 适用范围与现状

- 本文约束桌面上的 AstrBot 格子。插件内容归属见 `视觉规范.md`「全局设计语言」；本文只记录已确认的设计决定，不改变插件样式隔离与安全边界。
- **已确认**：一个功能一个格子、版本只在插件设置二级页、六类格子的信息层级与尺寸档位（状态与就绪时长为单档）、运行日志用时间轴呈现，以及每个类型自己的默认与最小尺寸。
- **数据通道已落地**：经通用 loopback 通道取原始快照，解析、缓存、去重与过期判定都在插件内（[ADR-0038](../adr/0038-插件loopback通道.md)）。宿主不再提供 `probe-service-status` 给本插件，六类格子都走通道。
- 六类格子的界面已按本文实现；真机对端、真实凭据与端口占用场景尚未验收。

## 类型划分

一个插件拆成多个格子类型，创建时选择类型，建成后不能改类型（ADR-0037）。一格只放一件事；需要两个功能同时看时并排创建两个格子，不做同格串联。

| 类型 | 内容 | 职责边界 | 尺寸变大时 |
| --- | --- | --- | --- |
| 状态 | 结论点 + 结论 + 就绪时长 | 只回答「在不在、已就绪多久」 | 不扩展，保持一行结论 |
| 就绪时长 | 一行大号时长 | 只回答「已就绪多久」 | 不扩展，保持一行大号时长 |
| 平台连接 | 逐平台状态、运行时长、错误次数 | 只看平台连接，不混资源与日志 | 行数随高度增减，多出折叠 |
| 资源占用 | CPU、内存、线程数 | 只给进程自身占用 | 补线程明细与采样口径 |
| 消息量 | 今日合计 + 24 小时柱状 | 只看消息量与趋势 | 柱高与标注变大，柱数固定 24 |
| 运行日志 | 时间轴上的 ERROR / WARNING 节点 | 只看最近异常发生顺序 | 节点数随高度增减，轴线不动 |

拆分规则：

- 类型影响内容与自己的尺寸声明，不影响外壳其余行为：标题轨道、折叠行为、公共最小底线一律按公共格子规则，不按类型另立一套。
- 所有类型共用一份插件设置与同一份插件内快照缓存，轮询按 `instanceId` 去重，拆格子不增加端口占用与读取次数。
- 数量上限按类型分别计数（`maxTiles` 每类各计），某一类满额不占其他类型的名额。

## 尺寸与布局

六类格子各有一套布局，**没有 compact / expanded 两套档位切换**：内容随外框尺寸连续自适应，尺寸变化只改变条目数量与相对比例，不切换到另一套版式。共用同一外壳：28 DIP 标题轨道、1 DIP 边框与留白。

清单 `[tiles.size]` 仍按类型声明默认与最小尺寸（默认在前、最小在后）：

| 类型 | 默认 | 最小 |
| --- | --- | --- |
| 状态 | 168 × 114 | 168 × 114 |
| 就绪时长 | 168 × 114 | 168 × 114 |
| 平台连接 | 288 × 300 | 288 × 200 |
| 资源占用 | 220 × 210 | 220 × 150 |
| 消息量 | 420 × 300 | 420 × 210 |
| 运行日志 | 420 × 300 | 420 × 200 |

约束：

- 最小尺寸保证核心信息仍可读；放大只增条目与明细，不引入新的数据类别。
- 状态与就绪时长保持单行呈现，放大不增加信息行。
- 不使用图例、坐标轴与网格线；柱状与横条只表达相对高低，不标绝对刻度。
- 任何空态下外框与标题轨道尺寸不变，避免布局跳动。
- 未在清单声明尺寸的类型退回公共默认值与公共底线。

## 运行日志的时间轴

- 左侧为时间刻度列，右侧是一条固定竖轴；每条日志是轴上的一个节点，节点右侧两行为「级别 + 事件正文」。
- 节点自上而下按时间倒序排列（最近的在最上）。
- 级别着色：`ERROR` 取错误色、`WARNING` 取警告色、`INFO` 取次要文字色。
- 尺寸变化只改变节点数量，轴线位置与时间列宽度不随高度变化。
- 正文单行截断，悬停给完整文本；契约已把正文截断到 500 字，悬停不承诺更长内容。

## 状态语义

四档结论与呈现一一对应，颜色不能单独承载语义，必须同时有文字结论。判据是快照 v2 的 `service.probe.level`（见「数据映射」）：

| 结论 | `probe.level` | 状态点 | 文案 | 就绪时长 |
| --- | --- | --- | --- | --- |
| 在线 | `ok` | 绿色（`--color-active` 同族） | 「在线」 | 显示实际时长 |
| 离线 | `off` | 次要色（`--color-muted`） | 「离线」 | 「—」 |
| 探测被拒 | `warn` | 警告色 | 「探测被拒」 | 「—」 |
| 未知 | `unknown` 或 `probe` 缺失 | 次要色 | 「未知」 | 「—」 |

- 未知不等于离线；探测被拒不等于服务停止，三档必须分别用文案说清。
- 数据超过 60 秒未更新时**保留最后一次有效快照的显示内容**，不清空、不加「数据过期」标记；只有状态格把状态点与结论压成「未知」灰，其余五类照常显示最后的数值。就绪时长也在过期时继续按最后快照的 `startTime` 现算，不清零。
- 语义色只用于状态点与结论字，不铺满整格；数值、柱状与日志正文一律用中性色，不因 CPU 高或内存大而变色。

## 空态

- **只有从未收到过任何快照**才显示「暂无数据」，并补一行原因（「采集插件未上报或未安装」），不显示 0 或空图。
- 拿到过快照后单项字段为 `null` 显示「—」；分段整段缺失用该段的上报文案：平台「平台数据未上报」、消息「消息数据未上报」、日志「日志数据未上报」。
- 平台清单整段缺失时，汇总行显示「平台清单暂不可用」，下方显示「平台数据未上报」；采集正常但没有配置平台时显示「暂无平台」。
- 空态下不隐藏外壳，也不改变格子尺寸。
- **未配对**：通道注册拿到 `loopback-credential-unavailable` 时，六类格子统一显示配对指引（「未配对 / 去设置 → 功能格子 → AstrBot 状态 粘贴共享 token，配对后自动重连」），不显示 0、旧值或任何伪造数据，也不与空态、过期态混用。配对后由插件设置里的配对版本变化触发重新注册，格子在重连成功后恢复正常呈现。

## 设置页的版本展示

版本不进入任何格子，只在「设置 → 功能格子 → AstrBot 状态」二级页静态展示。设置窗口读的是桌面格子写进插件设置的版本缓存，三态各自标注原因，都显示「—」：

| 状态 | 判定 | 显示 |
| --- | --- | --- |
| 未收到快照 | 插件设置里没有版本缓存 | 「—」+「尚未收到快照」，并提示先在桌面添加格子、确认采集插件在推送 |
| 数据过期 | 缓存里的 `collectedAt` 超过 60 秒未更新 | 「—」+「数据过期」与最近采集时刻，不沿用旧版本号 |
| 字段未上报 | 快照存在但该字段为 `null` 或空串 | 「—」+「字段未上报」 |

## 交互

- 格子内只读，不嵌按钮；动作放在右键菜单。
- 右键菜单由插件经外壳菜单接口注入，按功能分组：导航（打开 AstrBot 控制台）、只读动作（刷新一次、复制状态摘要）、写操作（启停平台，仅平台连接格出现且无错误平台时整组隐藏）。菜单项随数据与进行中的动作更新，显示、禁用与点击行为都归插件，宿主只负责渲染与命中。
- 插件菜单首项「打开 AstrBot 控制台」带 `separatorBefore`，与外壳公共项（折叠等）之间划一条分隔线，自成一组的起始；启停平台那组再以 `separatorBefore` 另起一段。
- 悬停提供完整文本：状态点悬停给 `probe.checkedAt` 的本地绝对时间与判定依据；就绪时长悬停给 `startTime` 的本地绝对时间；平台行悬停给该平台 `lastError` 全文与发生时刻；日志正文悬停给完整文本。
- 启停平台走 `request_loopback` 的 `POST /v1/actions`：成功后立即重读快照；失败按结构化错误提示，不回滚已成功的其它平台操作。菜单项在请求进行中禁用，同一时刻只允许一个启停请求。
- 版本信息不进入任何格子类型，只在「设置 → 功能格子 → AstrBot 状态 → 二级页」静态展示；格子不提供版本悬停或复制版本。

## 数据映射

快照契约以 v2 为准；v1 数据视为没有 `probe`，一律按「未知」处理，不得当成离线。

| 类型 | 快照字段 | 呈现 | 为空时 |
| --- | --- | --- | --- |
| 状态 | `service.probe.level` | 结论点 + 结论字（`ok`/`off`/`warn`/`unknown`） | `probe` 缺失或为 `null` → 「未知」灰点 |
| 状态 | `service.probe.checkedAt` | 悬停给本地绝对时间与判定依据 | 不显示悬停补充 |
| 状态 | `service.startTime` | 「已就绪 N 分 / 小时 / 天」 | 「—」 |
| 就绪时长 | `service.startTime` | 一行大号时长（`168 × 114`） | 「—」 |
| 平台连接 | `platforms.summary` | 「平台 3 / 4 在线」 | 「平台清单暂不可用」 |
| 平台连接 | `platforms.items[].status` | 每行状态点 + 运行时长 | 整段缺失 → 「平台数据未上报」；无配置平台 → 「暂无平台」 |
| 平台连接 | `platforms.items[].lastError` | 「错误 ×N」+ 悬停全文 | 无错误时不显示该项 |
| 资源占用 | `resources.cpuPercent` | 「18%」+ 细横条 | 首次采样为 `null` → 「—」 |
| 资源占用 | `resources.memory.processMb` | 「412 MB」+ 细横条 | 「—」 |
| 资源占用 | `resources.threadCount` | 「线程 62」 | 隐藏该行 |
| 消息量 | `messages.total` | 「今日 1,284」 | 整段缺失 → 「消息数据未上报」 |
| 消息量 | `messages.series` | 24 点柱状 + 三个刻度 | 空数组 → 不画柱，只留合计 |
| 运行日志 | `logs.tail` | 时间轴节点：时间 + 级别 + 正文 | 整段缺失 → 「日志数据未上报」 |
| 运行日志 | `collectedAt` | 「11:20 更新 · 间隔 5 秒」 | 无时间 → 「暂无更新时间」 |

- 整格「暂无数据」只在从未收到过快照时出现；各段字段缺失用上面的分段文案，不把整格清空。
- 过期（`collectedAt` 超过 60 秒）不清空内容、不加过期标记，只把状态格的状态点与结论压成「未知」。
- `service.online` 不用于四档展示：它是采集侧按 `probe.level` 派生的兼容字段，只在插件内部做旧版本回落时参考。
- 不进入格子：`instance.astrbotVersion`、`service.versions`——它们只在设置页的版本展示里出现，数据来自插件设置里的版本缓存。

## 刷新

- 采集侧每 5 秒推送一次快照到 `127.0.0.1:8765`；插件以 `mode=listen` 的 loopback 通道接住，宿主只把原始请求放进缓冲，并在该通道被读过一次之后才发 `component-host-event`（`kind = loopback-data:<channelId>`），插件据通道标识回来读原始请求。
- 插件解析快照后写进模块级单例缓存；各类型实例从缓存取，按 `instanceId` 去重，不按类型各开一条通道。
- 版本子集另外写进插件设置（`versionCache`）供设置窗口读取：设置页与桌面格子是两个独立 WebView，单例不跨窗口共享。版本值变化立即写，不变时最多每 45 秒刷新一次采集时刻，已过期则不刷新。
- 设置页保存或清除共享 token 成功后把 `pairingVersion` 递增写入，插件发现它变大就重新注册通道；`pairingVersion` 与 `versionCache` 都存在插件设置里，不新增宿主命令。
- 过期判定分两层，都在插件内：`receivedAt - collectedAt` 超过 30 秒的推送不进入缓存；最近一次有效快照的 `collectedAt` 超过 60 秒即判过期。**过期只影响状态格的结论呈现（压成未知灰），不清空其余内容、不隐藏旧值**；只有从未收到过快照才显示「暂无数据」。
- 宿主缓冲只按条数与时间清理，不判业务是否新鲜。
- 拉取兜底经 `mode=request` 的 `http://127.0.0.1:8766` 发 `GET /v1/snapshot`；推送通道绑不上 8765（端口被占用）时只用拉取兜底并给出可见提示。
- 格子不可见（滚出视口或窗口隐藏）时暂停视觉刷新，重新可见后读缓存里的最新快照，必要时触发一次拉取；恢复后以最新快照重绘，不重放积压更新。
