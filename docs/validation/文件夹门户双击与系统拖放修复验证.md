# 文件夹门户双击与系统拖放修复验证

## 当前结论

- 文件夹连续双击导航已通过实机验收。
- 系统拖入门户的失败根因已定位为门户当前目录使用 `\\?\D:\Project` extended-length 路径直接调用 `SHCreateItemFromParsingName`，目标 `IShellItem` 创建失败，后续没有进入来源提取和 `IFileOperation` 排队。
- 修复已实现：Shell 解析边界将本地 `\\?\` 路径转换为普通 DOS 路径，将 `\\?\UNC\server\share` 转换为 `\\server\share`；文件系统安全校验仍保留原始路径形式。
- 同名覆盖结果在 Shell 未返回新对象时使用覆盖前已确认的目标引用，避免结果无法映射到既有桌面项目。
- 修复后的系统拖入门户、门户间拖放、默认移动、`Ctrl` 复制、取消、失败补偿和同名覆盖归属仍需实机复验，未表述为已完成。

## 双击修复

浏览器的 `click.detail` 会在连续点击中跨目录继续递增，不能依赖一次性的 `dblclick` 事件。当前实现保留单击选择，在偶数点击计数时打开项目，因此导航后连续双击仍能进入下一目录。

实机结果：连续进入子目录、返回根目录并再次进入多个文件夹，导航通过。

## 系统拖放根因

诊断链显示：

1. `IDropTarget::DragEnter` 收到有效 `IDataObject` 和 `DROPEFFECT`。
2. `IDropTarget::Drop` 正常进入，业务层选择效果为移动。
3. `transfer_data_to_directory` 收到目标 `\\?\D:\Project`。
4. 目标 `IShellItem` 创建日志未出现，说明失败发生在 `SHCreateItemFromParsingName`，不是来源路径提取或 `IFileOperation::MoveItem`。
