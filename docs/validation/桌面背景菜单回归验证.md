# 桌面背景菜单回归验证

> 历史记录，组合菜单方案已停止使用。最终实现由 Explorer 的真实桌面窗口显示并执行原生菜单，产品入口通过注册表加入。2026-09-08 用户确认原生菜单与新建 TXT 正常，最终结论见[系统桌面菜单注册](系统桌面菜单注册.md)。下文保留当时证据，不作为当前实现或待办清单。

## 问题与证据

- 用户日志重复出现“原生上下文菜单已关闭，产品命令=无”，没有 HRESULT 失败。该日志不能区分用户取消、原生命令执行与弹出失败，不能据此判定注册表损坏或菜单接口获取失败。
- 从 Explorer 远程视图取得 `IContextMenu` 曾实际返回 `0x80040155`。当前实现不再使用这条获取路径。
- 仅对真实桌面目录调用 `IShellFolder::CreateViewObject` 可以执行新建 TXT，但菜单缺少 `DesktopBackground` 注册的显示设置、个性化等桌面动词。

## 历史实现方向（已替代）

- 保留本地文件夹背景菜单及其真实目录上下文，负责新建和文件夹扩展命令。
- 使用 `SHCreateDefaultContextMenu` 加载 `DesktopBackground` 类，追加桌面专属扩展。两份菜单都在当前 Shell STA 内创建，生命周期覆盖命令执行。
- 文件夹命令编号为 `1..=0x4fff`，桌面扩展为 `0x5000..=0x6fff`；产品命令仍从 `0x7000` 开始。动态菜单消息转发给两份原生处理器。
- 在 `TrackPopupMenu` 之后向 owner 投递 `WM_NULL`，补齐重复弹出的 Win32 收尾协议。记录前台窗口、激活结果、命令编号、跟踪耗时与原生错误码；不能再把所有返回都当作普通关闭。
- 填充或执行失败均清理 owner 的菜单处理器及根菜单，防止污染下一次请求。

## 验证

工作目录：`src-tauri`。

```powershell
cargo test --lib local_background_menu -- --nocapture
cargo test --lib native_menu_reopens_after_cancel -- --ignored --nocapture
```

- 新建测试实际展开 Shell 动态子菜单，在独占中文临时目录创建 TXT，并验证文件存在；不修改用户桌面。
- 桌面动词测试检查实际菜单的 `Display` 和 `Personalize`。临时让生产获取函数只返回文件夹菜单时，断言“缺少显示设置”失败；恢复桌面扩展后通过。
- 交互式检查连续弹出并自动取消八次原生菜单，均通过。该检查会短暂取得前台焦点，因此默认忽略，需显式运行。
- `cargo test --lib`：77 项通过，1 项交互式检查默认忽略；该交互式检查另行显式运行，并已覆盖真实桌面背景菜单。
- `cargo clippy --all-targets -- -D warnings` 通过；`git diff --check` 通过；源码为合法 UTF-8，无 BOM。
- `cargo build --bins` 未完成：现有开发进程自动启动程序后，`build/target/debug/desktop-tools-guardian.exe` 被运行中的守护进程占用，返回 `os error 5`（拒绝访问）。未终止主程序或守护进程，不能将此轮记为完整二进制构建通过。

## 当时的验收缺口

以下是组合方案停止前的限制。最终方案和实机确认已经取代这份待验收状态，未证明的历史根因仍保留为未知。

- 上述独立弹出检查不等同于双屏 WebView 宿主中的用户点击。间歇性打不开的根因尚未完整复现；需要新版本运行日志确认是否仍有前台激活失败或菜单立即退出。
- 当前没有宣称与 Explorer 的完整菜单等价。“查看、排序”等命令属于 Explorer 视图行为，本程序维护独立工作区布局，尚未映射这些命令；不能添加只会修改隐藏 Explorer 视图的无效菜单项。
- 第三方扩展受本机注册、文件夹目标和扩展实现影响，组合菜单可能出现同名扩展项，仍需在实际桌面检查。
