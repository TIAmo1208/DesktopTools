# 主题插件验收

## 验收结论

状态：开发宿主上的安装、选中、切回默认、再次选中、停用和卸载已按观察值通过。没有第二份主题，所以没有做「切换到另一主题」。真实壁纸逐图可读性、不同 DPI、超长主题名裁剪，以及设置窗未打开时的停用或卸载，仍未验证。

实机结论依据用户手动测试反馈；浏览器自动视觉验收未完成，不计入通过证据。

## 回归项

这些是本轮实机先暴露、随后改代码的问题。除脚本路径错误外，其余三项都有修复后的观察值；脚本路径错误只记录为代码已改，没有第二次实机确认。

| 现象 | 处理 | 结论 |
| --- | --- | --- |
| 插件详情把主题报成「插件脚本路径无效」，并显示「重新加载」 | 只按 `role=theme` 跳过脚本加载。格子插件的空脚本仍报这条错误 | 代码已改。修复后的插件页没有再次实机观察 |
| 卸载时每块桌面屏各弹「正式宿主命令无效: save_preferences」 | 自动还原只在没有桌面宿主原生桥、因而能写偏好的文档里发起。不能写的文档不调用，也不把跳过记成成功 | 修复后已观察：重新安装并选中同一主题后再卸载，两块桌面屏不再出现该错误，只留一条「主题已移除」提示 |
| 未归类名称跟着界面主题 | 桌面宿主里的未归类项改用 `--fence-text` 与 `--fence-item-text-shadow` | 修复后已观察：桌面深色下名称为 `#e8eff0` |
| 没有主题时，下拉被一行说明替代 | 主题行保持原生下拉，无可用主题时只显示「默认」 | 修复后已观察 |

## 未验证范围

- 真实壁纸上的围栏文字和菜单文字，没有逐张核对可读性。浅色桌面主题、两组强调色的其余组合也没有逐项看过。
- 多显示器只数过本次的两块桌面屏各一张主题 `link`。不同 DPI，以及设置窗里的 `link` 数量，没有核对。
- 主题名超过 176px 时的选项裁剪，没有在实机里看。
- 只有桌面宿主在跑、设置窗没打开时停用或卸载。按当前实现，这次不会保存还原，要等下次打开设置窗。该场景没有实机走通。
- 没有第二份已安装主题，因此没有验证从一份主题直接换到另一份主题。
- 浏览器自动视觉验收未完成，不计入通过证据。
