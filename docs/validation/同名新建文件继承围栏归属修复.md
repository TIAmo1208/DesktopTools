# 同名新建文件继承围栏归属修复

## 根因与证据

复现前持久布局已经将 `C:\Users\TIAmo\Desktop\新建文本文档.txt` 记录为“测试”围栏 `fence-393` 的成员，复现后沿用相同来源位置和成员引用。诊断日志只出现 Shell watcher 协调且 renames 为空，没有本次 MoveItemToFence、CommitItemDrag 或 complete_external 记录。

复现版本的 `reconcile_items_for_monitors` 未清理已离开 Shell 集合的围栏成员，并因“仍被围栏引用”而保留其来源位置。同路径重建后匹配旧成员，表现为新文件自动进入围栏。该版本的 `unclassified_items` 也存储围栏成员的来源位置，不能据此判断逻辑未归类；当前实现已将成员旧位置移出活动布局。

## 修复边界

在成功完整 Shell 枚举后的统一布局协调中，移除不在当前项目集合中的围栏成员及来源位置。暂时不能解析但仍被枚举的项目仍在集合中，不删除其归属；枚举失败不发布部分观察，历史快照及程序内 Shell 撤销继续走既有恢复路径。

本次恢复 ADR 0013 已有规则：确认离开的引用退出活动布局，同路径外部重建作为新项目进入未归类区域。没有改变网格、围栏几何、拖放许可或领域语义，不机械修改 CONTEXT/ADR。最初引入遗漏的 Git 提交尚未确认，不能仅因事件迁移时发现就认定由事件迁移引入。

## 验证

新增 `recreated_shell_item_does_not_restore_deleted_membership`：建立围栏归属，完整枚举删除，再同名新建。修复前在“已删除的成员必须退出活动围栏”断言失败，修复后通过；同名新建保持逻辑未归类。

修复版 Release 已完成构建，用户实测删除后同名新建不再进入“测试”围栏。临时归属诊断日志已清除，保留有效的成员清理日志与回归测试。后续旧位置与新建落位调整见[新建项目落位与围栏历史位置验证](新建项目落位与围栏历史位置验证.md)。

本机复现前布局为 `build/validation/归属诊断-复现前布局.json`。未直接修改用户现有工作区文件；修复通过后续正常 Shell 协调生效，不能在文件仍存在时凭路径猜测它是否为旧对象。
