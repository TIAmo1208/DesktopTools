# 验收流程

本页规定本项目**用什么命令取证、什么时候用哪一层、证据怎么标注**。执行验收前先读本页，再决定跑哪条命令；不要跳过前面的层直接启动程序截图。

本页是入库的唯一验收文档：只写方法与判据。**验收记录本身写在本机 `build/validation/记录/`，不入库**，因为结论只代表当次构建与本机环境。TMP、互斥体、产物路径与端口见 [环境前提](../agents/环境前提.md)。

完成标准：每一项验收结论都能指向一条可重跑的命令、一份落盘产物或一条明确标注为「人眼确认」的记录。

修复类改动的轮次顺序（复现 → 修复 → 构建 → 独立审核 → 同产物真机验证 → 暂存）见 `docs/agents/修复验收轮次.md`；该页只编排执行顺序，本页仍是证据层、判据与命令的权威来源。

## 1. 分层表

按「跑一次要付出多少环境代价」分层，优先在低层取证；高层只补低层表达不了的事实。

| 层 | 判定对象 | 触发时机 | 命令 | 通过判据 | 产物 | 证据标签 |
| --- | --- | --- | --- | --- | --- | --- |
| L0 单元与契约 | 纯函数、状态机、契约解析、几何与落位 | 每次改动后 | `node --test <受影响文件>`（提交前 `npm test`） | 除已知环境性失败外 0 失败（见 §6） | 终端输出 | 软件模拟 |
| L1 组件与 UI 数值 | 真实 React 组件 + 真实 CSS 的计算样式与布局 | 改组件、样式、交互后；或在真机验收前首次判定既有交互/样式行为时 | `npm run dev` 后 `npm run test:browser` | 汇总行「失败 0」 | 终端输出 | 浏览器断言 |
| L2 宿主原生 | Windows API 返回值、尺寸、Alpha、句柄、命中区域、DPI 映射 | 改 Rust 侧平台代码后 | `npm run test:rust` | 除已知环境性失败外 0 失败（见 §6） | 终端输出 | 软件模拟（真实系统 API） |
| L3-探针 真实宿主数值 | 真实 WebView2 里的计算样式、DOM 计数、`dataset`、`link` 数量、落盘偏好 | 需要在真实宿主里定性但能数值化时 | 开发宿主带远程调试端口启动后 `node scripts/取证探针.mjs` | 清单里每项都拿到预期值 | `build/validation/<主题>/` 下的 `探针结果.json` | 运行时探针 |
| L3 真机取证 | 真实宿主运行时的程序日志、运行返回码、进程状态 | 需要真实宿主行为时 | `scripts/后台启动程序.ps1` | 日志与返回码符合预期，进程无异常退出 | `build/validation/<主题>/<时间戳>/` | 真机日志；用户截图另记 |
| L4 性能与稳定性 | 按线程 CPU、句柄与 GDI 对象、重载次数 | 改动涉及渲染、事件、订阅时 | 待验证（见 §7） | 待验证 | 待验证 | 待验证 |

**层级判定**：某个现象只要能表达成「返回值 / 尺寸 / 计数 / 计算样式」，就必须在 L0–L2 或 L1 收口，不得用截图作为证据。截图只能出现在 §4 的人眼清单里。

**顺序门**：进入 L3 或 L4 前，先给出「判定项 → 证据层」映射；能表达成返回值、尺寸、计数或计算样式的项，未落 L0–L2、L1 或 L3-探针的，不得进入真机。映射缺项时先补低层证据，或把缺项写成待验证，不用真机手势和截图代替。

## 2. 各层操作

### L0 单元与契约

日常只跑受影响部分：

```bash
node --test <受影响文件>
```

提交前跑全量：

```bash
npm test
```

串联 `test:frontend`（`test:frontend:rest` + `test:components`）、`test:weather`、`test:music`、`test:folder-portals`、一组内联的 `src/bridge` 测试和 `test:rust`。

`npm run test:rust` 已通过 `scripts/with-tmp.mjs` 注入 `TMP`；直接 `cargo test` 时先按根 `AGENTS.md` 的构建与门禁一节设置，否则 `cl.exe D8050` 会阻断整条链。

### L1 组件与 UI 数值断言

L1 需要 **两个终端**：dev server 提供断言页，运行器驱动无头 Edge 读取每页的 `#result`。

```bash
# 终端 1
npm run dev
```

```bash
# 终端 2：跑全部断言页
npm run test:browser
```

只跑一页：

```bash
node scripts/跑断言页.mjs --页 desktopItemImage
```

参数：`--页 <路径子串>`、`--超时 <毫秒>`（默认 20000）、`--verbose`。环境变量 `DESKTOP_TOOLS_EDGE` 可指定 `msedge.exe` 路径；未设置时按 `ProgramFiles(x86)`、`ProgramFiles` 查找。

1420 被非本仓库进程占用时，运行器打印占用 PID 与进程名并以退出码 2 结束；这种情况属于环境问题，不得记成断言失败。

断言页清单维护在 `scripts/断言页目录.mjs`，分三类：

| 类别 | 数量 | 判定 |
| --- | --- | --- |
| 断言页 | 9 | `#result` 以 `PASS` 开头为通过，`FAIL` 为失败 |
| 检查页 | 3 | 只核对能在浏览器中加载并渲染，不判 PASS/FAIL（输出 INSPECT） |
| 真机专用页 | 1 | headless 下结论不成立，输出 SKIP，由 L3 覆盖 | |

数量以 `scripts/断言页目录.mjs` 为准；汇总行形如「共 12 页：断言通过 9，检查页 2，真机专用跳过 1，失败 0」。

**设计一致性数值验收**：UI 改动除跑断言页外，还要对照 `docs/design/视觉规范.md` 与 `docs/design/` 下对应组件的设计文档核对尺寸、间距、颜色。视觉期望表（`docs/design/视觉期望表/<组件>.md`）及其解析器**尚未进入仓库**，当前以设计文档中的数值条款为准，待验证。

**当前基线**：按行为增量维护；验收新行为时新增断言页，并把路径列入任务范围。功能分支改造期间个别断言页可能暂时失败（例如 `islandFillet` 改造中），按失败页单独定位，不记成环境问题；稳定后应回到失败 0。`weatherSettings` 断言页带父层 `openAddKey` 夹具，因为入口按钮已移到功能格子二级页页头。

**退出码**：0 全部通过，1 存在失败页，2 环境问题（1420 端口未监听、找不到 Edge、参数错误）。

### L2 宿主原生

```bash
npm run test:rust
```

对应 `cargo test --manifest-path src-tauri/Cargo.toml --all-targets`。需要交互式桌面但不需要人眼判定的实机测试以 `#[ignore]` 标注，统一入口**尚未建立**，当前需手工执行：

```bash
cargo test --manifest-path src-tauri/Cargo.toml --all-targets -- --ignored
```

安装包验证（真装、重装、卸载、SHA256 比对，不启动宿主）：

```powershell
.\scripts\验证安装包.ps1
```

### L3-探针 真实宿主数值

真实宿主里凡是能表达成计算样式、计数、`dataset` 或落盘偏好的事实，在本档用只读探针取证，不上人眼。探针只读：不注入状态、不驱动操作、不改页面。

```powershell
node scripts/取证探针.mjs --清单 <检查清单.mjs> --目标 desktop-host --截图 build/validation/<主题>/截图
```

Debug 构建创建 WebView2 时已附带 `--remote-debugging-port=9223`（`#[cfg(debug_assertions)]`，Release 不含），无需设置环境变量；当前 wry 无条件设置 `AdditionalBrowserArguments`，`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 不生效。端口只监听本机。

清单写法、参数、退出码与截图分级见 `docs/agents/取证工具.md`。

### L3 真机取证

L3 不开启任何调试端口，也不读取页面内部状态。取证方式是：Agent 后台启动真实程序并保留进程，用户在前台实际操作，Agent 事后读取程序日志、运行返回码与进程状态。

```powershell
.\scripts\后台启动程序.ps1 -Theme <主题>
```

脚本行为：

1. 检查 `build/target/debug/desktop-tools.exe` 存在；缺失时打印 `[环境]` 提示并以退出码 2 结束。
2. 检查 `desktop-tools` / `desktop-tools-guardian` 进程；已有实例时打印互斥体原因并以退出码 3 结束，不启动第二份。
3. 建立 `build/validation/<主题>/<时间戳>/`，设置 `TMP` 到 `build\tmp`，把程序 stdout/stderr 重定向到该目录的 `stdout.log`、`stderr.log`。
4. 有界等待窗口出现或进程退出（上限 `-TimeoutSeconds`，默认 120 秒）；窗口就绪即返回并保留进程。
5. 进程在就绪前退出或等待超时，以退出码 1 报告，并打印产物路径与诊断；不把 exit 0 当成启动成功。

程序自身日志另见 `%LOCALAPPDATA%\TIAmo\DesktopTools\<日期>.log`。

操作顺序（前台反馈闭环）：

1. **后台启动**：`.\scripts\后台启动程序.ps1 -Theme <主题>`，必要时先 `npm run tauri:dev` 生成可执行文件（已带 TMP）；直接 `cargo build` 时先设 `TMP`。
2. **用户操作**：在桌面上完成本次要验证的操作。
3. **收集**：Agent 直接读 `stderr.log`、`stdout.log`、程序日志与进程状态；脚本不再等待回车。
4. **反馈**：用户给出结果描述；仅材质、观感与合成本身可由用户提供截图，可数值化的项不得用截图替代。
5. **修复**：按日志与反馈改代码。
6. **重采**：用新的时间戳重跑；不复用旧产物，不对同一次失败反复重启重试。

产物：`build/validation/<主题>/<时间戳>/`（`stdout.log`、`stderr.log`）。退出码：0 窗口就绪并保留进程；1 就绪前退出、超时或未就绪；2 环境问题（可执行文件缺失或参数错误）；3 已有实例占用互斥体。

**音乐歌词与播放进度**：播放任意歌曲后读取当前会话的 `TimelineProperties`；`Position > 0` 且 `LastUpdatedTime` 不是 1601 纪元，才具备逐句跟随条件。`Position`、`EndTime`、`LastUpdatedTime` 全为 0 的客户端（实测网易云）只验证零时间轴兜底：播放时外推、暂停冻结、切歌重置、拖动后不对齐；不得把本地外推结果记为真实播放头。歌词另验：有同步词时当前句随进度变化；无同步词、纯音乐或取词失败时回落「歌名 · 艺人」或播放状态。

## 3. 证据分层规则

四类证据分开记录，**禁止互相冒充**：

| 标签 | 含义 | 不能用它证明 |
| --- | --- | --- |
| 软件模拟 | `node --test` / `cargo test` 的纯逻辑与契约结论 | 真实宿主传参正确、真实渲染结果 |
| 浏览器断言 | 无头 Edge 中的真实组件 + 真实 CSS，桥接为模拟 | WebView2 真实渲染时序、真实原生命令 |
| 运行时探针 | 真实宿主里只读取得的计算样式、计数、`dataset`、落盘偏好 | 用户是否觉得对、DWM 合成后的观感 |
| 真机日志 | 真实宿主进程的程序日志、运行返回码、进程状态 | 界面是否长得对、布局数值 |
| 人眼截图 | 用户实际操作后的截图或口头描述，需记明确认时间 | 任何可数值化的结论 |

写验收记录时，每条结论后标注它属于哪一类。L1 断言页使用模拟桥接（见 `build/validation/记录/系统缩略图验收.md`、`build/validation/记录/天气设置验收.md`），其 PASS 不能作为真实宿主验收结果。L0 纯函数通过也不等于宿主调用时传参正确，后者需 L1 或 L3 覆盖。

L3 已有结论全部来自 **Debug 构建 + 开发服务器**，不能作为 Release 构建的验收结果。

**回归项复跑**：修复后再验收时，必须在同一场景、同一取证层复跑一次并写下观察值。没有复跑的项只能记「未验证」，不得记「已修复」。

**结果只在本机**：日志、截图、探针输出等原始产物写入 `build/validation/`（不入库）；落库的验收记录只写结论与重跑方法，并注明结论代表本机环境与当次构建。

## 4. 必须人眼确认的残余清单

以下八项写死为「只能人眼确认」，不得用其他层的结论替代；抓图手段、裁剪范围与留存规则见 `docs/agents/取证工具.md`：

| 现象 | 为什么脚本化不了 | 何时确认 |
| --- | --- | --- |
| 设计稿还原（布局、间距、字号、图标、配色） | 自动化截图无法代替用户对还原度的判断，且反复采集同一视图只会产生大量无效图 | 每次按设计稿实现后 |
| 透明桌面与壁纸、窗口阴影的真实合成效果 | DWM 合成结果不在任何进程可读的 API 里，`PrintWindow` 与自动化截图都拿不到透明子窗口 | 每次发布前 |
| 原生拖放（OLE `IDataObject` → Explorer）的手感与落点 | 会话与句柄可测，拖动手感是交互体感 | 涉及拖放改动时 |
| 系统缩略图内容是否符合内容策略（无音乐角标、无视频边框、无快捷方式箭头） | 只能看图画；尺寸与 Alpha 已由 `shell_image` 测试覆盖 | 换 Windows 版本或换 Shell 处理器时 |
| 真实 Toast 通知的样式与叠放 | 资源占用可测，样式仍需看 | 改通知外观时 |
| 多显示器真实 DPI 组合（不同缩放、不同分辨率） | 需要真实显示环境 | 用户报告 DPI 问题时 |
| 音乐频谱 canvas 柱形视觉（柱宽、圆角、渐隐） | 可断言 canvas 位图尺寸与颜色变量，柱形绘制本身只能看像素 | 改绘制算法时 |
| 多类型格子创建菜单展开后的实际落位与遮挡 | 断言页表达不了设置窗口内菜单的锚点与裁切 | 改创建入口时 |

确认结果必须写进对应 `build/validation/记录/` 记录，标注「人眼确认」与确认时间；不要把截图当作结论。

## 5. 禁止事项

- **无界重试**：任何等待都必须是有界单次等待，超时即失败并给出原因，不得在脚本内循环重连或自动重启。
- **反复重启程序碰运气**：同一次验收重复启动程序只为「再试一次」，说明缺的是确定性判据；应回到 L0–L2 补断言，而不是继续重启。
- **用截图替代可数值化的断言**：位置、尺寸、颜色、纹理、计数、返回码都能数值化，必须断言数值；只有 §4 的六项允许人眼。
- **用低层结论冒充高层**：L0 纯函数通过 ≠ 宿主传参正确；L1 断言页 PASS ≠ 真实宿主通过。
- **用自动化截图脚本做视觉比对**：视觉还原结论只能来自用户确认或用户提供的截图；Agent 不得编写脚本控制电脑反复采集同一视图来「核对还原度」。
- **复用过期证据**：受测源码、测试配置、依赖或制品变化后，旧结论不再有效。
- **在默认门禁里跑真机层**：L3 需要交互式桌面与显示器，不得并入 `npm test`。

## 6. 环境性失败判定

`cargo test` 与部分前端测试依赖外部环境（注册表写权限、本地应用数据目录、回收站、系统 Shell 菜单模板、交互式桌面）。在受限环境（沙箱、无交互桌面、受管机器）中，这些用例会失败，但失败原因不是产品缺陷。

**适用条件**：本节清单只在「已知受限环境」下适用，用于判断「本机这批失败是否与本次改动有关」，不是永久豁免。换到具备完整权限与交互桌面的机器上，下列用例必须全部通过；若仍失败，按真实缺陷处理。

| 用例 | 典型报错 | 根因 |
| --- | --- | --- |
| `app::desktop_menu::tests::registration_replaces_stale_actions` | 拒绝访问 `0x80070005` | 需要写 `HKCU` |
| `app::desktop_menu::tests::registration_switches_between_root_command_and_cascade` | 拒绝访问 `0x80070005` | 需要写 `HKCU` |
| `platform::windows::desktop_sources::tests::config_watch_ignores_unrelated_values_and_tracks_key_lifecycle` | 配置监听无事件 | 需要真实注册表与文件系统通知 |
| `platform::windows::shell::tests::local_background_menu_creates_text_document` | TXT 模板不在实际菜单中 | 本机系统 Shell 菜单未注册「文本文档」模板 |
| `platform::windows::shell::tests::native_portal_rename_and_recycle` | 重命名或回收失败 | 需要真实交互式桌面与回收站 |

判定方法，三条**同时**满足才可判为环境性失败：

1. 失败用例在**上表清单内**，用例名逐字匹配。
2. 报错为**权限类或前置条件类**（`0x80070005`、`PermissionDenied`、拒绝访问、模板缺失、锁不可用），不是断言值不相等。
3. 本次改动**没有触及**该用例覆盖的模块；触及了就按真实失败处理，先查改动。

允许的判据表述：「除 §6 已知环境性失败外 0 失败」，并写明本次通过的用例数与受阻的用例数，不得只写「全部通过」。

**已修复、不再属于本节**：`collect::cleanup::tests` 下 7 项曾报「附件归属锁不可用」。根因是 `cleanup.rs` 的 `static RECORDS: Mutex<()>` 在持锁期间调用外部 `recycle` 回调，测试回调 panic 后锁被标记为 poisoned，后续所有 `lock()` 返回 `Err` 并连锁波及同进程其余用例。已在 `cleanup.test.rs` 增加测试串行锁修复，生产代码未改。

**禁止**：

- 因环境性失败而重跑同一命令期待结果变好。环境条件没变，结果不会变。
- 因环境性失败而转而启动程序截图。截图不能证明这些用例覆盖的逻辑。
- 把清单扩写成「凡是失败都算环境问题」。清单外的失败一律按真实缺陷处理。
- 长期不复查清单。环境权限或 Shell 配置变化后，清单项可能已能通过，需重新核对。

## 7. 待验证

以下内容在当前仓库中没有可用工具或未实测，使用时按待验证处理：

- **L4 性能与稳定性**：`resource.test.rs` 的 `resources()` 提供了进程累计 CPU、内存、句柄、GDI、USER 对象口径，但**没有脚本化入口**，也没有回归阈值。
- **L2 的 `#[ignore]` 统一入口**：9 项实机测试目前需手工带 `-- --ignored` 执行，尚无 `scripts/` 下的统一脚本。
- **视觉期望表与解析器**：`docs/design/视觉期望表/` 与 `scripts/解析视觉期望.mjs` 尚未创建（本轮暂缓）。
- **产品进程内调试端口**：已验证在同一进程内二次创建 WebView2 不初始化，该方案不可行；当前 L3 不依赖它。
- **`collectEditorImages` 断言页**：headless 下「已卸载图片延迟写 srcset」时序不成立，记为真机专用 SKIP，由人眼截图覆盖。

`scripts/跑断言页.mjs` 退出码：0 全部通过，1 存在失败页，2 环境问题或参数用法错误。

- 1420 未监听、被非本仓库进程占用、找不到 Edge、浏览器启动失败、参数非法，一律以退出码 2 结束并打印 `[环境]`。浏览器起不来时不会把余下页面记成失败。
- 检查页渲染判据为「排除 `vite-error-overlay` 后仍有内容」。出现该浮层即判失败，不会以浮层元素充当渲染结果。
