## 安装与卸载验证

可在没有已安装版本、没有运行实例且测试目录不存在时执行：

```powershell
pwsh -File scripts/验证安装包.ps1 -Installer 'build/target/release/bundle/nsis/Desktop Tools_0.3.0_x64-setup.exe'
```

脚本使用 `build/安装包 验证`，保存并恢复测试前的桌面菜单；拒绝覆盖已有正式安装登记，不启动桌面宿主。卸载器原地运行后保留的测试卸载器与目录需检查后清理，再重复运行。下列首次安装、同版本覆盖与卸载结果来自改动前的模板产物；重装页改动后完成的是构建与生成脚本核对，以及 0.3.0↔0.3.1 的升降级实测，独立脚本尚未重跑。

- 首次安装及同版本覆盖均返回成功，主程序、guardian、许可声明与桌面菜单目标均正确。
- guardian 与构建目录二进制 SHA256 完全相同。
- Tauri 将主程序副本的唯一 `__TAURI_BUNDLE_TYPE_VAR_UNK` 标记改为 `NSS` 后放入 NSIS，再还原构建目录的原文件。校验脚本只对原文件应用这三个字节的预期变化，再比对整个主程序 SHA256，结果一致。
- 卸载成功移除两个程序、产品卸载登记和桌面菜单；验证脚本随后恢复测试前的菜单。
- 生成的 NSIS 脚本确认 `currentUser`、`downloadBootstrapper`、guardian 随包交付、两个二进制同目录安装与依赖安装模式、安装卸载钩子。
- 生成的 NSIS 脚本确认重装页按版本关系分支：同版本与升级为“添加/重新安装组件”（默认勾选）与“卸载 Desktop Tools”两个互斥勾选项，未勾选卸载走覆盖安装分支，勾选走先运行旧卸载器的分支；降级只有一个卸载确认勾选项，未勾选时禁用“下一步”。`bundle > windows > nsis > template` 指向 `installer/installer.nsi`，该模板由 `tauri-cli-v2.11.4` 的上游模板改动而来。

八项现有 lint 修复保持原有业务行为、领域语义、架构职责和视觉规则，因此不为这些等价修复另行修改领域 ADR。未定位 lint 的引入提交，不将其表述为已定位回归。
