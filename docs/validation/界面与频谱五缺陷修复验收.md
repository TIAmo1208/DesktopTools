# 界面与频谱五缺陷修复验收

## 变更范围

| 编号 | 现象 | 根因 | 修复位置 |
| --- | --- | --- | --- |
| 1 | 开着频谱一段时间后柱形不再刷新 | 采集链没有活性判定：回环流静默停摆时仍按帧率反复投递同一份 bins，前端平滑把柱形定在最后一帧；另有一处暂停集合泄漏会让刷新策略永久判为暂停，从而永久停投 | `MusicSpectrum.tsx` 停滞检测与采集重建；`desktop_host.rs` 销毁宿主时退出暂停集合 |
| 2 | 无音频输出时仍有绘制开销 | 绘制循环无条件逐帧重排动画帧，静音时每帧清屏重绘一遍 1px 基线 | `MusicSpectrum.tsx` 改为只在有可见变化时排帧 |
| 3 | 围栏重命名失效（双击与右键菜单均无效） | 右键菜单关闭时把焦点抢回触发元素，编辑器聚焦被菜单的外点关闭监听判为外部点击，随即失焦退出编辑 | `DesktopTileHeader.tsx` 改为菜单卸载后再聚焦编辑框 |
| 4 | 点击桌面后出现一圈边框 | 桌面根容器是全屏元素且被点击路径聚焦，浏览器默认焦点环沿视口绘制；围栏已有同类复位，根容器缺失 | `DesktopWorkspace.css` 复位根容器焦点环 |
| 5 | 打开收集项编辑窗口后顶部空白、桌面层下移 | Vditor 注入到 `<body>` 的图标精灵 `<svg>` 在发布构建中按普通块参与文档流（其内联的绝对定位对 SVG 根不生效），把编辑根下推 153px 并产生滚动条；开发构建未复现 | `main.tsx` 标记编辑页；`CollectEditor.css` 让编辑根脱离文档流 |

条带位置、尺寸、着色与段数裁剪规则未改动，仍以 `docs/design/视觉规范.md` 为准；`CONTEXT.md` 与 ADR 未改，本次为缺陷修复，领域术语、不变量与架构决策不变。

## 验收方法

- 自动化：`npm run typecheck`、`npm test`、`cargo +nightly-2026-09-08 fmt -- --check`。
  - 结果：`npm run typecheck` 通过；`npm test` 退出码 0，其中 `cargo test --all-targets` 227 项通过、9 项忽略、0 失败；Rust 格式检查通过。
- 真机：Debug 构建 + `npm run dev`，带 `--remote-debugging-port=9222` 通过 CDP 驱动真实鼠标事件与读取计算样式；桌面宿主页与设置/编辑窗口分处不同调试端口。
- 像素取证：系统级窗口截图（`PrintWindow`）与 CDP 帧截图并用；桌面宿主被前台窗口遮挡时 CDP 帧截图会返回旧帧，界面状态以系统截图与 DOM/computed 数值为准。

## 证据

### 1 频谱停刷新

| 项 | 结果 |
| --- | --- |
| 停滞判定 | 播放中帧内容签名连续 2 秒不变即判定停摆，清零电平后走既有 1px 基线分支，并以 2 秒起、翻倍至 30 秒封顶的退避复用启动命令重建采集（`start` 内部先停止旧线程） |
| 暂停集合泄漏 | 销毁宿主时退出暂停集合，避免「暂停期间摘显示器」后刷新策略永久为暂停 |
| 恢复路径实测 | **未覆盖**：需要让回环采集真实停摆（切换默认输出端点）才能触发，本轮未构造 |

### 2 无音频时的绘制开销

探针包裹 `CanvasRenderingContext2D.prototype.clearRect`，只统计 `.music-spectrum`，并用自建 rAF 循环证明帧时钟仍在推进：

| 场景 | rAF 帧数（3 秒） | 清屏次数 | 画面 |
| --- | --- | --- | --- |
| 媒体已暂停 | 227 | 0 | 181px 宽 1px 基线，底行 181 个不透明像素 |
| 播放 1kHz 音源 | 227 | 212（约 70 次/秒） | 柱形 97 个不透明像素 |
| 停止播放后 1.2 秒起算 3 秒 | 227 | 0 | 回到 1px 基线 |

修复前该循环每帧排下一帧，同口径约 227 次清屏。证据：`build/validation/五缺陷取证/C-idle-music-tile.png`、`C-playing-music-tile.png`、`C-after-stop-music-tile.png`。

### 3 围栏重命名

围栏 `开发`（`titleMode = hover`），采样间隔 40 毫秒、窗口 1600 毫秒：

| 路径 | 编辑框存活 | 焦点 | 落盘 |
| --- | --- | --- | --- |
| 双击标题 | 31 帧连续存在（约 1428 毫秒） | `document.activeElement` 恒为编辑框 | 回车后 `workspace-layout.json` 标题更新；Esc 取消后 mtime 不变 |
| 右键标题 → 菜单「重命名」 | 33 帧连续存在（1503 毫秒） | 编辑框出现后持续持有焦点 | 回车后标题更新（mtime 11:52:23 → 12:04:12） |

菜单关闭后焦点序列为 `focusout BUTTON` → `focusin SECTION.desktop-tile fence` → 下一帧 `focusin INPUT.desktop-tile-header__editor`，未丢失焦点。证据：`B1-r2-editor-open.png`、`B1-r2-typed.png`、`B1-r2-committed.png`、`B2-r2-editor-open.png`、`B2-r2-after-escape.png`。

### 5 编辑窗口顶部空白与桌面层下移

该缺陷只在**发布构建**复现，开发构建（vite 页面）不复现。两个页面由同一根因触发：Vditor 初始化时把图标精灵 `<svg style="position: absolute; width: 0; height: 0; overflow: hidden">` 注入 `<body>`，该元素在发布构建中计算样式为 `position: static`、高 150px（内联绝对定位对 SVG 根不生效），按普通块参与文档流并排在 `#root` 之前，把页面内容整体下推 153px。

| 页面 | 触发条件 | 修复前 | 修复后 |
| --- | --- | --- | --- |
| 收集项编辑窗口 | 打开编辑窗口，Vditor 初始化 | `#root` 顶部 153，文档高 673（视口 520），出现滚动条；客户区顶部 31–183px 为 `#eef1f4`（`--color-background`，内容被下推露出的页面底色） | `#root` 顶部 0，文档高 520，无滚动条，头部紧贴客户区顶部 |
| 桌面宿主页 | 先选中格子里的快捷方式触发收集箱 Vditor 预览，再双击收集项打开编辑窗口；只双击收集项不复现 | `#root` 顶部 153，文档高 1553（视口 1400），`workspaceTop` 153，首个围栏 top 757；桌面层整体下移 | `#root` 顶部 0，文档高 1400，`workspaceTop` 0，首个围栏 top 604（与常态基线一致） |

| 项 | 结果 |
| --- | --- |
| 反证 | 活页面删除该 `<svg>`：编辑窗 `#root` 顶部 153 → 0、文档高 673 → 520；宿主页 `workspaceTop` 153 → 0 |
| 免疫验证 | 宿主页注入等价 body 级 150px 精灵后，`workspaceTop` 仍为 0、文档高 1400、围栏 top 604 不变 |
| 手势复现 | 用户按报告步骤复现后，宿主页存在 1 个 body 级精灵，`workspaceTop` 仍为 0、文档高 1400，桌面层不再下移；截图 `build/validation/shift-check/user-confirmed-fixed.png` |
| 候选方案取舍 | `float: left` 可消除下推但把编辑内容挤到右侧约 300px；`height/width: 0 !important` 残留 17px 行盒；`display: none` 会让 3 个 `<use>` 引用的符号失去定义 |
| 采用方案 | 编辑页由 `main.tsx` 标记、宿主页由 `data-desktop-host` 标记，两者 `#root` 都脱离文档流占满视口；不触碰第三方精灵语义，符号引用保持可用 |
| 显示器缩放 | 两块屏均 96 DPI（100%），`devicePixelRatio` 均为 1，与缺陷无关 |

结论：顶部空白与桌面层下移同源，都由第三方图标精灵占据文档流造成，已在编辑页与宿主页分别复位，并在发布构建上复测通过。

## 未覆盖范围

- 频谱停摆的真实恢复路径未实测：需要切换系统默认输出端点让回环采集停摆，本轮未构造；停滞判定与重建退避由代码复核确认，无 CDP 证据。
- 暂停集合泄漏的修复只有编译与既有测试覆盖，没有针对「暂停期间销毁宿主」的自动化用例。
- 右键菜单路径的取证中，编辑窗未出现在调试端口目标列表，收集项编辑窗口通过页面原生桥命令打开，几何用 `PrintWindow` 测量；界面手势打开编辑窗口的动作未在本轮重现。
- 第 5 条只在发布构建复现，修复只在发布构建上复测；开发构建本就不复现，未做回归。
- 第 5 条的桌面层复测覆盖手工手势（先选中格子项目再双击收集项）与脚本注入等价精灵两条路径；编辑窗口顶部的复测由脚本以原生命令打开编辑窗口完成。
- 桌面宿主被前台窗口遮挡时 CDP 帧截图返回旧帧，该情况下未使用帧截图作为证据。
- 验证在本机 100% 缩放、单显示器内容（第二屏仅有本地时间格子）的布局下完成，未覆盖其它缩放或更多显示器组合。
