# 新建项目落位与围栏历史位置验证

## 实现与边界

围栏成员身份不再依赖 `unclassified_items` 记录。进入围栏释放桌面位置，原位置由操作前的撤销历史保存；普通移出、拖放和解散使用当前目标落位。选择、焦点、重命名、历史合并和外部投放按围栏及未归类集合联合判断身份。围栏投放不预留桌面格，仍校验 Shell 确认的结果身份。

新建项目沿用 Explorer 原生背景菜单，使用 `IFolderView::GetItemPosition` 按准确身份读取坐标，转换为显示器工作区 DIP 后寻找最近可用网格。只有新增身份使用坐标；已有项目、重命名与重复通知不重新定位。没有坐标时使用列优先空格分配，不缓存上一次右键位置去匹配下一次 Shell 新增。

撤销恢复的旧格若被事务之后新增的项目占用，恢复原项目位置，保留新增项目并将其移至最近空格。整体容量仍不足时保持既有事务失败与不提交规则。

## 自动化验证

- 修复前失败回归确认：进入围栏后活动快照仍持有旧桌面位置。
- `membership_positions_exist_only_in_undo_history` 验证位置退出活动集合、撤销恢复、重做释放、普通移出与解散重新落位。
- `undo_membership_keeps_a_new_item_in_the_released_cell` 验证旧格被新文件使用后的撤销与重做。
- `shell_positions_only_place_new_items` 验证新项目按目标屏坐标落位、已有项目不重新导入、重复通知不移动项目。
- 主屏网格已经填满时，次屏新项目直接使用次屏空格；不因主屏临时分配失败而阻塞。
- Shell 外部投放补偿遇到后来独立操作占用旧格时，保留该独立操作，为恢复项寻找最近空格；这是 Shell 补偿保留后续操作的边界，与整份布局撤销不同。
- 既有选择、焦点、重命名、组拖动、Shell 补偿和同名删除重建回归通过；桌面容量限制保留，围栏不受隐藏桌面槽位限制。
- `cargo check --all-targets --features custom-protocol`、TypeScript 类型检查及完整 `npm test` 通过；Rust 110 项通过、7 项忽略。完整测试输出保存在 `build/validation/新建落位完整测试.log`。
