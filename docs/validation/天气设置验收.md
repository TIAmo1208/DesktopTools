# 天气设置验收

## 可重复检查

运行 `npm run tauri:dev`，从托盘打开设置，进入“功能格子 → 天气”。先填写一个字段，分别检查标题栏关闭、返回和分类导航；选择继续编辑应保留草稿，放弃应清除草稿并完成原动作。

开发服务运行时打开 `/src/features/settings/weatherSettings.browser.html`，页面应显示 `PASS`。这是替代桥交互验证，不证明真实供应商接入成功。

自动回归按分组执行：`npm run test:frontend`（契约与组件）、`npm run test:weather`（桌面天气格子）、`npm run test:rust`（Rust 全量）。多来源、按来源城市列表与格子缺失状态的结论以这三组为准。

## 已验证

- `npm run typecheck` 通过；`cargo test --manifest-path src-tauri/Cargo.toml --all-targets` 全量 221 项通过、0 项失败、8 项 ignored；`npm run test:frontend` 106 项通过（契约与组件分别 101 与 5）；`npm run test:weather` 15 项通过；`npm run build` 与 `npm run tauri:build` 均 exit 0。
- 天气专项 Rust 用例覆盖官方 Host 校验、Ed25519 验签、连续小时、城市时区及夏令时、保存门槛、窗口代次及凭据状态读取失败后的取消；Host 使用虚构地址测试单级、多级、不同中间标签、大小写、连字符及长度边界，拒绝非法标签、协议、用户信息、端口、路径、查询、片段、根域名和伪造后缀。不读取用户实际凭据，不以本地格式测试代替真实账户接入。
- 编辑态敏感字段留空沿用已保存值有自动回归：草稿私钥留空时与已保存记录合并后通过格式校验并可保存，重新输入的值不被覆盖，没有已保存记录时保留空值交由格式校验拒绝。
- 城市写入的副作用边界有自动回归：按来源的验证只调用校验命令，不含写入或回滚；编辑弹窗内的城市添加与删除只改草稿，点保存才写入后端列表，取消即丢弃；配置弹窗不再声明草稿会话写入城市的命令。
- 天气状态锁不可重入有自动回归：`Command::Probe` 在两个来源上各跑一次，均在独立线程执行并用超时断言其必然返回，覆盖“探测在本已持有状态锁时再次加锁”导致线程永久阻塞、进而挂住同步命令与主线程的缺陷。该用例在缺陷存在时以超时失败，已实测确认。
- 凭据记录名只有一处推导有自动回归：`credentials::record_name` 与 `credentials::target` 对两个来源给出同一结果，且状态对象的记录名与之相同，避免读写两侧各写一遍取名规则时出现“写 A 读 B”。
- 限流等待按来源记账有自动回归：一个来源被要求等待时，只拒绝该来源的请求，其他来源的搜索与验证不受影响；错误文案带来源键，已过期的等待时间不拦截；来源门控直接测试 `retry_gate` 的按来源查表，不依赖网络。
- 探测位置选择有自动回归：有城市时使用该来源的第一座城市，列表为空才退回固定占位位置。
- 编辑态留空敏感字段到保存的端到端路径有自动回归：Begin 留空私钥、Save 后读回的私钥仍是已保存值，同一次编辑的非敏感字段更新生效。
- 状态码归类有自动回归：402 额度不足不设置服务端等待且不可重试，429 与 503 可重试，401 使用凭据无效文案，未知状态码使用通用文案；额度说明仍由中文文案参与停止后续请求的判定。
- 升级路径不迁移有自动回归：旧 `weather-city.json` 不被读取，保存后新来源文件存在且旧文件内容不变；旧偏好中的 `weatherSource` 被忽略，`weatherEnabled` 按当前字段解析。
- 创建入口的纯逻辑有自动回归：格子初始状态只含来源与城市两个标识、未绑定入口为 `{}`；返回值的实例选取跳过创建前已存在的实例；功能开关只在关闭时写入开启并保留其余偏好。
- 原生 transport 参数边界有自动回归：缺失或非法来源、缺失城市标识、类型错误的显示器标识均在进入业务前失败；显示器标识的类型错误编码为 `invalid-desktop-host-readiness` 对象，不再返回裸字符串。
- 备份恢复不校验组件能力声明有自动回归：未声明创建与移除能力的实例可随备份还原，还原后的创建与移除命令仍按未声明拒绝。
- 前端控件契约补齐：来源选择浮层的渲染与关闭契约（空列表文案、来源顺序与地址、非模态对话框、Escape 与点外关闭）、城市列表 busy 时全部操作禁用、图标资源统一 24 × 24 画布与 `currentColor`；城市弹窗断言与控件断言复用一个 Vite 服务，避免每个测试文件重复冷启动。
- 切换来源清空城市标识有自动回归：提交载荷以删除语义移除城市标识，合并提交时 `undefined` 键真正从持久状态删除，本地来源、城市标识与城市对象一并清空，避免切源后仍绑定旧城市。
- 格子标识与权威快照同步有自动回归：来源与城市两个标识独立解析，只选来源时来源仍然有效；撤销、重做与备份恢复改变实例状态后，本地绑定按新快照覆盖。
- 配置变更刷新有自动回归：设置页保存或删除来源后，桌面格子重读已配置来源与该来源城市列表，不再停留在首次挂载时的结果。
- 跨来源预报事件隔离有自动回归：调度事件携带来源标识，同名城市只在来源与城市同时匹配时更新，不互相覆盖。
- 城市草稿的增删净零有自动回归：编辑弹窗内删除本次刚添加的城市只撤回草稿、不记入删除；已提交的城市改动逐项从草稿移除，凭据保存失败后重试不会重复添加或删除同一城市。
- 真实搜索与探测入口遵守来源等待期有自动回归：被限流的来源在加载凭据前即被拒绝，另一来源仍进入自己的凭据读取；搜索与探测收到服务端最早重试时间后写回该来源的等待表。
- 浏览器替代回归覆盖新增交互（`weatherSettings.browser.html`）：编辑弹窗内添加城市不写后端、删除城市不写后端、取消后城市改动全部丢弃、保存时才写入；保存的部分失败——城市改动先写入后端、凭据写入失败时弹窗保留失败原因且重试后城市不重复；来源菜单添加城市后展开区按本次写入刷新（第二个城市可见）；第二个来源走完整路径——只填该来源字段即可保存、保存后同样执行可用性检查、编辑态密钥留空时保存按键可用且能收起弹窗、城市写入该来源自己的列表且不影响另一个来源。
- 涉凭据的 Rust 用例通过进程内互斥串行执行：Windows 凭据存储是进程外共享资源，并行读写会让彼此读到瞬时错误，串行前该组用例约每三次完整测试出现一次失败。
- 格子缺失状态有自动回归：只有该来源的城市列表读取成功且确实不含当前城市才报“已从列表移除”；未读取或读取失败都不得报该状态——读取失败保留上一次成功读取的列表，失败本身作为可见消息给出，不能把“读不到”当成“列表为空”。
- 来源隔离按来源索引有自动回归：同名城市标识在两来源各自保留独立的退避记录；城市列表按来源分别读写并按标识去重；删除某来源的城市不影响其他来源的退避与配置代次；Foreca 城市在详情链接为空时仍可保存并保留预报。
- 城市列表项与应用状态有自动回归：来源列表只返回已配置来源，回显和风账户 API Host 与 Foreca 固定服务地址；列表项渲染与删除入口契约、城市弹窗的搜索会话与渲染契约、底栏署名与详情可用性按格子来源决定、五种缺失状态各自给出文案与按键，分别由 `SettingsCityList`、`WeatherCityDialog` 与 `weatherTileState` 的组件测试覆盖；删除来源、删除城市、验证通过后写入城市列表等用例只使用测试专用凭据记录。
- 天气格子行为有自动回归：按完整、7 天、小时、摘要顺序匹配且双维度均须满足；固定模式跳过自动判断，尺寸提交失败不保存模式；模块退出禁用交互、反向切换使用中间帧；来源栏按模块有效期一次性到期并拒绝旧回调；小时与日预报按条目结束时间过滤；折叠与宿主暂停禁止读取、恢复保留缓存并拒绝旧响应；当前天气到期与隐藏恢复时失效。
- 桌面预报与设置共用天气结构、摄氏单位及小时/日预报时间窗校验，覆盖连续小时按实际时间戳验证和日预报按城市 IANA 时区核对含今天的七天。
- 能力验证项按来源返回名称与项数，和风五项、Foreca 四项，`Snapshot.checks` 逐项携带标签与失败原因，前端按后端返回渲染，不硬编码检查项数量。该逐项清单目前只由残留的草稿会话命令返回，前端已不再调用；保存不再以验证通过为条件。
- Windows Credential Manager 使用独立测试目标实际执行写入、查询、超长替换拒绝及清除，不读取或修改用户天气凭据；凭据读取失败回归确认旧会话身份不影响当前草稿，且不提前解除在途请求互斥。
- `weatherSettings.browser.html` 在生产组件、Tauri 替代桥与 React StrictMode 下、真实浏览器（Chrome，Vite 开发服务）中运行结果为 `PASS`，断言覆盖空态、添加弹窗的供应商切换、输入不触发请求、重复验证拦截、保存失败保留草稿、保存成功切换到来源列表、编辑模式回填非敏感字段且不回读私钥、未保存确认、来源右键菜单命令、探测后可用状态更新、删除确认、保存部分失败时城市已写入，以及取消后的迟到成功无效、导航与窗口关闭保护、清理后关闭。
- Windows 原生设置窗口在 960 × 640、浅色、100% 缩放下检查：天气入口、未配置字段、滚动后的能力区和禁用命令可见；输入草稿后标题栏关闭和分类导航均弹出放弃确认，继续编辑保留页面，放弃后完成导航。
- 真实和风账户返回当前天气、24 小时与含今天的 7 天预报；桌面天气格子的渲染、天气获取与数据显示经人工确认通过。实际返回的 `attributions` 为指向供应商署名页的 URL，城市 `fxLink` 指向对应城市详情页。
- 位置检索的覆盖与语言已用真实接口实测：Foreca 收录到城市级，中国主要城市可以检索，区县与街道不收录；中文位置名只在带 `lang=zh_CN` 时命中，不带该参数时「深圳」这类名称没有结果。未收录位置的提示改为建议改用所属城市或英文名。实测只覆盖少量城市，不代表全部行政区划；Foreca 签发的 API key 长度约 400 字符，输入与校验上限相应放宽到 1024 字符。
- Foreca 请求失败按状态码区分参数不合法、凭据无效、权限不足、位置未找到与限流；API key 校验拒绝含空白、不可见字符、`Bearer` 前缀或超出长度的值。

## 待验证

- 天气凭据类测试存在未定根的偶发失败：全量测试下 `source_listing_reports_availability_and_cities_without_current_selection` 与 `credential_store_and_authoritative_save_gate` 偶发失败，观测失败率约 1/8，表现为凭据写入成功后随即读取来源列表为空。已排除的假设：两个用例的凭据记录名完全相同（经修复实验证伪，反而更差）；单纯并发（weather 过滤并行 10 轮、单线程 10 轮均无失败，需全量套件负载才复现）。机制未确定，可能是 Windows Credential Manager 在并发负载下写入可见性延迟，但无证据。本次全量 221 项连续执行未复现，测试代码保持原状，未以改测试掩盖该竞态；复现方式为连续执行 `npm run test:rust`。
- 城市弹窗的“验证配置”当前只校验城市格式与该来源的详情链接规则，不读取凭据、不请求供应商，却呈现“验证通过”；ADR-0026 要求和风必须真实请求才能判断该位置可用，二者冲突。恢复真实请求或修改 ADR 尚未决定，前端文案在此之前不构成供应商可用性结论。
- 真实宿主的点按验收未执行：桌面背景菜单与 Explorer 菜单的“添加天气”实际点击、天气格子右键菜单“切换 API / 选择城市”二级菜单在屏幕右侧与底部边界的翻转、透明壁纸背景下的可读性，以及浅色、深色、跟随系统三套主题。
- 浏览器替代回归已在真实浏览器执行 `PASS`（含 React StrictMode），但未在真实宿主的 WebView2 内复核同一条完整流程；`WeatherCityDialog` 测试曾因 Vite 模块传输 60 秒超时而失败，合并到单一测试服务后通过，该超时属于本机冷启动开销，未在更慢的机器上验证。
- 宿主实测四轮修正未在真实宿主复验：第一轮的验证结果遮挡搜索结果、编辑弹窗入口重复、添加城市后无法保存、Foreca 验证报错、格子二级菜单不显示已添加城市；第二轮的桌面弹窗非模态浮层、已选城市误报“已从列表移除”、添加弹窗布局、验证语义改为只检查、Foreca API key 输入宽度；第三轮的格子误报不可用（读取失败被当成空列表）、城市弹窗被配置弹窗遮住、来源入口添加城市后展开区不刷新、编辑弹窗删除城市未点保存即落盘；第四轮的保存卡在“正在保存”（探测命令在状态锁上重入死锁）、菜单项灰掉无法展开、桌面格子报不可用、点击“检测可用”后托盘与退出失去响应；以及第二轮来源在编辑弹窗内无法保存（密钥留空被判为必填）与保存后长期停在“未确认”。自动回归、`typecheck`、`build` 与浏览器替代回归已通过，但不能代替宿主点按与真实账户复验。
- 开发态桌面宿主页面首次加载耗时 87 秒（`React 页面加载开始` 到 `页面加载完成`）。在冷启动的 Vite 服务与普通浏览器下实测同一页面为 3.6 秒、146 个模块、最慢单个请求 748 毫秒，因此该耗时不属于前端模块图；当时的 `tauri dev` 是从编辑器调试会话启动的（Node 侧挂了 js-debug 引导脚本并逐项 `Debugger attached`），WebView2 与调试器开销是更可疑的方向，尚未在不带调试器的终端里复测确认。
- 城市添加与删除不广播配置变更：设置页与桌面格子的城市列表不会因另一端的写入即时刷新，格子要等菜单打开或重新挂载才重读；共享活动调度仍按已解析的城市继续请求已删除城市。当前实现如此，是否补事件广播尚未决定。
- 草稿会话的城市搜索与验证命令仍保留在命令面，但前端已不再调用，逐项能力清单只由这些命令返回；删除或明确标注为保留接口尚未决定。
- 创建天气格子时“先写功能开关、随后创建失败”会留下“开关开着但没有格子”的状态；这是已确认的取舍，不做回滚。该路径的失败反馈也较弱：Explorer 注册表菜单路径只在日志留下 `ERROR`，用户侧仅表现为“格子没有出现”。
- 多来源并存时的实际请求合并效果，以及来源与城市数量增长后的调度表现。
- 用户真实和风账户的城市搜索权限、临时城市验证、账户接口权限与真实设备时钟误差；权限不足、配额耗尽、网络失败及数据缺失的状态区分。
- 目标网络、离线与恢复、真实网络失败、服务端限流等待、额度耗尽、超时、坏数据与设备时钟偏差；重试上限、服务端最早重试时间、认证失败停止自动请求、清除凭据后停止联网，以及恢复活动遵守未结束退避的效果。
- 位置切换竞态、无活动实例停止请求、目标城市时区及来源链接准确性。
- 同一位置的多个实例与多屏共享缓存、在途请求去重、拒绝旧位置迟到响应及数据归位。
- 城市保存期间的取消与持久化竞态。
- 跨日和不足预报窗口更新的真实网络效果，以及真实错误分类与退避效果。
- 原生拖动、移动或缩放格子时的布局测量，暂停、折叠与隐藏恢复的实际表现，模块动画的视觉连续性，原生到期提示与显示效果。
- 原生深色主题、不同 DPI、大字号、键盘完整选择城市和辅助技术；大字号实际内容测量尚未实现，样式、切换阈值、动画参数及大字号适配未在宿主验证。
