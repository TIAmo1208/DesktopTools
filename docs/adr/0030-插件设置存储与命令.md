# 插件设置存储与命令

插件作者需要一份不属于工作区布局、也不放进插件目录的设置存储。读取与保存使用新增命令；一个插件一份 JSON，放在当前生效的配置目录；配置目录变更时整目录迁移；保存成功后用事件通知，读者再自己读取。

插件代码目录的位置与“不随配置目录迁移”仍按 [ADR-0029](0029-插件来源与范围.md)。本决策只覆盖设置文件、命令、事件和配置目录的复制范围。

## 决策

### 存储位置与命名

插件设置写入当前生效配置目录，不写入尚未重启才生效的目录偏好，也不写入插件目录。一个插件一份文件：清单 id 去掉 `plugin.` 前缀得到名称，文件名为 `plugins-<名称>.json`。`plugin.clock` 对应 `plugins-clock.json`。

文件名只允许 `[A-Za-z0-9._-]`。去掉前缀后的名称为空、含其他字符、长度使文件名超过单个路径分量限制，或由文件名还原的 id 与原 id 不一致时，拒绝该次读写并记录 WARN。未通过校验的 id 不拼进路径。

读写沿用现有的同目录临时文件与原子替换。文件不存在表示没有设置。文件内容不是合法 JSON 时记录 WARN 并按没有设置返回，不改写、不覆盖原文件。命令不解释 JSON 字段，也不读取插件清单。

### 命令面

`get_plugin_settings(plugin_id)` 返回该插件的 JSON；没有设置时返回空。`save_plugin_settings(plugin_id, value)` 在标识合法时原子保存整份 JSON。两条命令只处理这一份数据。

### 事件

保存成功后广播 `plugin-settings-changed`。载荷只有 `pluginId`。收到事件的一方重新调用读取命令，事件本身不携带设置正文。事件名常量放在 contracts。通知失败不回滚已经保存的文件。

### 整目录迁移

配置目录迁移遍历并复制整个源目录，不再使用 `settings.json`、`workspace-layout.json`、`workspace-layout.snapshots`、`collect` 这四项固定名单。仍拒绝链接和重解析点，源目录与目标目录不得互相包含，目标目录必须为空，不覆盖已有文件，复制完成后再提交启动位置指针。`plugins-*.json` 因此随配置目录一起迁移，不另写迁移名单。源文件保留；迁移失败时继续使用原目录。

### 设置窗口脚本加载

设置窗口使用 Tauri 默认资产来源，没有逐屏宿主的 `/plugins/` 路由。`load_plugin_script(plugin_id)` 从本次运行已解析的插件目录读取 `<插件标识>.js`，再在调用该命令的窗口上执行脚本正文。执行发生在宿主侧，不放宽内容安全策略，也不为设置窗口增加自定义协议。

路径只接受插件根内的普通文件。标识必须带 `plugin.` 前缀，文件名与标识往返一致：`plugin.foo` 对应 `plugin.foo.js`。目录穿越、链接、重解析点、非 `.js` 以及其他无法还原的标识拒绝执行，返回中文错误并记录 WARN，不中断应用。同一脚本允许重复执行，是否只执行一次由调用方决定。

### 插件停用状态

插件是否停用是宿主偏好，不是插件自己的设置，因此不写入 `plugins-*.json`。`ApplicationPreferences.disabled_plugins` 保存停用标识。缺失按空列表处理。只接受带 `plugin.` 前缀且前缀后仍有名称的条目，重复项去掉，最多保留 64 条；其余条目丢弃并记录 WARN。

不新增读写命令，沿用 `save_preferences`。不新增事件，沿用 `preferences-changed`。

## 后果

- 插件设置与插件代码目录分离：代码目录不随配置迁移，设置文件随配置目录迁移。
- 一次读取不会把损坏的设置文件修成空对象。
- 整目录复制会带走配置目录中的全部内容，不再漏掉后来新增的数据文件；目标非空或路径互相包含时仍拒绝迁移。

## 待验证假设

- 设置窗口与桌面宿主如何订阅 `plugin-settings-changed` 并刷新插件条目，不在本决策的命令实现范围内。
