# 插件设置存储与命令

插件作者需要一份不属于工作区布局、也不放进插件目录的设置存储。读取与保存使用新增命令；全部插件共用当前生效配置目录里的一份 JSON；配置目录变更时整目录迁移；保存成功后用事件通知，读者再自己读取。

插件代码目录的位置与“不随配置目录迁移”仍按 [ADR-0029](0029-插件来源与范围.md)。本决策只覆盖设置文件、命令、事件和配置目录的复制范围。

## 决策

### 存储位置与命名

插件设置写入当前生效配置目录下的 `settings-plugins.json`，不写入尚未重启才生效的目录偏好，也不写入插件目录。文件是一个对象，键为 `作者@插件ID`，值是该插件的设置对象。作者取清单 `author`，为空时键以 `@` 开头，例如 `@plugin.item`。`TIAmo` 与 `plugin.item` 对应 `TIAmo@plugin.item`。

命令仍只接收 `pluginId`。宿主用当前运行时清单解析作者再拼键。清单不存在时返回「插件清单不存在」，不把设置写到只有 id 的键上。标识去掉 `plugin.` 前缀后为空、含 `[A-Za-z0-9._-]` 以外的字符，或名称超过 240 个字符时，拒绝该次读写并记录 WARN。未通过校验的 id 不写入文件。

未发布的 `plugins-<名称>.json` 不再读写，也不迁移。

读写沿用现有的同目录临时文件与原子替换。文件不存在表示没有设置。文件内容不是合法 JSON 或不是对象时记录 WARN 并按没有设置返回，不改写、不覆盖原文件。命令不解释设置对象里的字段。

「卸载并清理配置」只删除对应键。删完后文件里没有剩余键时，删除 `settings-plugins.json`，不留空对象。文件不存在不算失败。设置文件是链接或重解析点时拒绝清理，也不先删插件文件夹。

### 命令面

`get_plugin_settings(plugin_id)` 返回该插件的设置对象；没有设置时返回空。`save_plugin_settings(plugin_id, value)` 在标识合法且清单存在时原子保存该键。两条命令只处理这一份文件里的一个键。逐屏白名单里的读取走同一条路径。

### 事件

保存成功后广播 `plugin-settings-changed`。载荷只有 `pluginId`。收到事件的一方重新调用读取命令，事件本身不携带设置正文。事件名常量放在 contracts。通知失败不回滚已经保存的文件。

### 整目录迁移

配置目录迁移遍历并复制整个源目录，不再使用 `settings.json`、`workspace-layout.json`、`workspace-layout.snapshots`、`collect` 这四项固定名单。仍拒绝链接和重解析点，源目录与目标目录不得互相包含，目标目录必须为空，不覆盖已有文件，复制完成后再提交启动位置指针。`settings-plugins.json` 因此随配置目录一起迁移，不另写迁移名单。源文件保留；迁移失败时继续使用原目录。

### 设置窗口加载

设置窗口与桌面逐屏使用同一套自定义协议，入口模块由同源 `import("/plugins/<script>")` 加载，模块默认导出外壳对象、宿主按清单 id 绑定。不再有 `load_plugin_script`，也不在宿主侧执行脚本正文。协议、路径校验与内容安全策略见 [ADR-0031](0031-设置窗口迁到自定义协议.md)。

### 插件停用状态

插件是否停用是宿主偏好，不是插件自己的设置，因此不写入 `settings-plugins.json`。`ApplicationPreferences.disabled_plugins` 保存停用标识。缺失按空列表处理。只接受带 `plugin.` 前缀且前缀后仍有名称的条目，重复项去掉，最多保留 64 条；其余条目丢弃并记录 WARN。

不新增读写命令，沿用 `save_preferences`。不新增事件，沿用 `preferences-changed`。

### 插件目录偏好与安装

`choose_plugin_directory` 只在设置窗口使用既有目录选择器；选中默认插件目录时返回空串，表示跟随默认，其他选择返回绝对路径。`resolved_plugin_directory` 只读返回本次启动冻结的插件根。`prepare_plugin_install_from_folder` 与 `prepare_plugin_install_from_archive` 只返回计划。`apply_plugin_install` 在确认后安装，降级还要 `confirmDowngrade`。`cancel_plugin_install` 置取消标记。进度事件 `plugin-install-progress` 携带 `taskId`、`stage`、`percent`、`sourceName`，阶段变化、间隔 100 毫秒或前进 2% 才发送。解压依赖 `zip`。安装或卸载成功后重新扫描插件根、刷新运行时清单并广播 `component-runtime-snapshot-changed`；工作区不动，已有实例不清。

## 后果

- 插件设置与插件代码目录分离：代码目录不随配置迁移，设置文件随配置目录迁移。
- 一次读取不会把损坏的设置文件修成空对象。
- 整目录复制会带走配置目录中的全部内容，不再漏掉后来新增的数据文件；目标非空或路径互相包含时仍拒绝迁移。

## 待验证假设

- 设置窗口与桌面宿主如何订阅 `plugin-settings-changed` 并刷新插件条目，不在本决策的命令实现范围内。
