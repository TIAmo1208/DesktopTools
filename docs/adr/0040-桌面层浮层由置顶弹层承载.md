# 桌面层浮层由置顶弹层窗口承载

## 背景

桌面宿主窗口由 `SetParent` 挂到 Explorer 的 `SHELLDLL_DefView` 之下，整棵窗口树位于桌面 z 带。宿主 WebView 内用 `position: fixed` 绘制的菜单、确认框与天气弹窗因此只能画在桌面层：任何前台窗口都能盖住它们，菜单伸进被占区域时表现为被裁切而不是整块消失。同一问题也解释了原生 Shell 菜单为何既不置顶也不前移——右键输入落在 Explorer 窗口树里，前台进程仍是 Explorer。

## 决策

### 一个置顶弹层窗口，按需创建

- 桌面层浮层统一由一个独立的置顶窗口承载，窗口透明、无边框、`WS_EX_TOOLWINDOW`（不进任务栏与 Alt+Tab）、`always_on_top`；不设 `WS_EX_NOACTIVATE`，弹层需要键盘。
- 窗口按需懒建，同一时刻只存在一个弹层；关闭后先隐藏并保留窗口，空闲 `90s` 后销毁以释放 WebView2 进程，下一次请求走冷启动。不做常驻隐藏窗口，也不随程序启动预建。
- 空闲计时用代次号取消：任何一个新请求都会推进代次，旧计时醒来即失效，不需要可取消的定时器对象。

### 页面来源与载荷协议

- 弹层页面是同一份前端产物的 `index.html?popup-layer=1` 入口，复用设置窗的自定义协议来源（`desktop-tools-settings`）与主题样式表查询参数，不新增协议、不新开资产通道。
- 命令 `open_popup_layer` 携带 `{ requestId, kind, monitor, anchorX, anchorY, payload }`；`kind` 为 `menu` / `confirm` / `weather-city` / `weather-source`。载荷只放呈现字段，菜单项不带闭包。
- 结果经事件 `popup-layer-result` 回传宿主：菜单返回 `indexPath`，确认框返回 `confirmed`，天气弹窗返回所选城市或来源，取消返回 `dismissed`。业务闭包留在宿主，宿主按 `indexPath` 找回原命令执行；天气弹窗只在弹层里做搜索与验证，写入城市列表与绑定仍由格子完成。
- 复用已创建的窗口时先隐藏再替换请求；被替换的未结束请求按取消收束，避免宿主侧订阅悬挂。复选菜单保持打开（`closeOnSelect: false`）时，宿主在选中后把最新命令表推给同一窗口，不重开窗口。

### 先量后显与坐标

- 页面先渲染再量：根菜单与所有二级菜单在一趟布局里量出尺寸，上报 `set_popup_layer_frame`（DIP 尺寸与锚点在文档中的偏移），由 Rust 换算成屏幕物理像素并缩放、定位、显示、聚焦。窗口显示前不出现半成品尺寸。
- 坐标统一为“宿主客户区 DIP × 目标显示器 `scale_factor` + 该显示器工作区原点”；显示器由请求里的枚举索引确定，与逐屏宿主的创建顺序一致。跨屏直接移动同一个窗口，不每屏建一个。
- 窗口尺寸取所有层级菜单的联合盒：创建时就把二级菜单的宽度与每一项的摆放一次算清，窗口一次定位到联合盒，展开与收起只切换二级菜单的可见性。二级菜单开合不再改窗口尺寸或坐标，因此不会整窗移动或闪烁；代价是未展开时窗口包含一块透明预留区，点在这块区域上按“菜单外点击”关闭。
- 窗口位置只做整体推回工作区的收敛，不改窗口内部布局；联合盒的宽高按锚点四周可用空间收敛，保证整窗落在工作区内。二级菜单优先向下方展开，下方放不下而上更宽裕时改为向上贴父项，并按可用高度滚动。
- 二级菜单向左展开时，根菜单在文档里右移 `childWidth`，上报的窗口盒必须同时带上这段偏移与宽度（`anchorOffsetX = childWidth`）；只按根菜单宽度上报会把根菜单裁到窗口之外，表现为“弹层出现但空白”。
- 二级菜单的贴边位置按**每个子菜单自己的实测宽度**算（向左展开贴一级菜单左边、向右展开贴右边）。不能用「最宽子菜单 + 滚动条预留」，否则较窄的子菜单与一级菜单之间会空出预留宽度那么大的缝隙。
- 纵向同理：锚点下方放不下根菜单而上方的空间更大时向上展开，窗口整体上移（`anchorOffsetY = rootHeight`），菜单可用高度取上下两侧较大者；窗口位置只做整体推回工作区的收敛。
- 每次请求都重新挂载浮层组件：窗口尺寸去重只在同一次请求内有效，跨请求沿用会漏报尺寸，窗口被隐藏后不再显示。

### 窗口外观

- 窗口必须去掉系统标题栏样式：Tauri 的 `decorations(false)` 只隐藏可见标题栏，`WS_CAPTION | WS_SYSMENU` 仍在，Windows 11 会在客户区右上角画出系统关闭按钮，边框也按标题栏配色绘制。创建后与每次显示后都要清掉这些样式位并 `SWP_FRAMECHANGED` 让系统重算非客户区。
- 客户区背景设成全透明并保留 DWM 扩展帧，页面 CSS 圆角之外的像素不铺底色。
- 页面地址带 `boot` 序号（进程号 + 单调序号），每次建窗都换 URL，保证入口页重新读取；同一窗口被复用时地址不变，调试构建下复用会重新导航到新地址，发布构建只发换请求事件。
- 显示分两步：先在屏幕外就位、显示并让系统把这一帧画完，再移到目标位置。系统会在“显示”这一帧按标题栏配色绘制窗口边框，直接在目标位置显示会闪一帧系统配色的边框与关闭按钮。
- 隐藏过的窗口重新显示时强制重绘一次（`RedrawWindow` + `DwmFlush`），避免复用窗口只出空白。

### 焦点与关闭

- 弹层显示时激活自己：键盘打开聚焦第一项，指针打开只聚焦菜单容器（方向键、Esc、回车仍然可用，但不画选中框）；打开前记录前台窗口，关闭时能还原就还原，不能就落回桌面。
- 窗口失去激活即按用户取消收束（`WM_ACTIVATE` 对应的 Tauri `Focused(false)`）。失活事件带上当时请求的身份，迟到的失活事件不得收束新请求；宿主收到 `dismissed` 后恢复原状态。
- 弹层关闭不改变宿主折叠偏好；菜单打开与关闭仍沿用现有 `desktop-tile-menu-opening` 语义。

### 与原生菜单的分工

- 原生 Shell 菜单仍由 `show_native_context_menu` 显示，弹出期间把 owner 临时移入置顶带、跟踪结束立即复原，owner 语义不变（ADR-0007）。桌面层自绘浮层才走本 ADR 的弹层窗口。
- 拖动预览、框选与悬停预览不迁：指针交互发生在桌面层，迁到置顶窗口需要双向转发输入，不划算。

## 后果

- 浮层随宿主与设置窗之间的主题差异、焦点归属与显示器拓扑变化成为新的回归面；多屏不同 DPI 与冷启动延迟需真机验证。
- 弹层页面的契约错误必须收口：载荷不合法时渲染错误说明，并以取消结果结束请求，不留一个没有结果的原生请求或空窗口。
- 页面根本没有上报尺寸时同样要收口：弹层页面与设置窗同源、取自 `build/frontend`，前端产物没重建或页面脚本出错时窗口建得出来却没人上报尺寸。弹层模块按 `5s` 上报超时收束这次请求（隐藏窗口、回传取消结果、记一条带请求身份、浮层种类与页面地址的错误日志），计时从建窗或换请求完成时开始；超时只是兜底，不改变正常显示路径。用户不会再只看到“右键没有菜单”而没有任何线索。
- 显示流程只有走到最终定位成功才把窗口记为“已显示”：中途任何一步失败都留给上报超时兜底，不会留下一个永远不会收束的请求。
- 命令面按来源收窄：宿主侧的打开、取消与载荷更新只走原生命令通道，不注册为 Tauri command；该通道在分派前按协议来源过滤，设置窗口来源调用这三条命令直接拒绝。弹层侧的读取、上报尺寸与回传结果只注册为 Tauri command 并校验调用窗口标识，其他窗口调用直接拒绝并记日志。弹层结果回传失败时保留请求，先按取消兜底收束一次，不留悬挂的原生请求。

## 已知残余风险

- 空闲销毁失败时窗口句柄会放回状态，但该次失败不自动重排下一次空闲销毁；连续两次系统级窗口销毁失败时，窗口会保留到下次请求或进程退出。正常路径下窗口已隐藏，不遮挡桌面点击。
- 隐藏失败（`hide` 返回错误）时立即转为销毁窗口；只有销毁也失败才退回“保留句柄 + 空闲回收”，此时窗口可能仍可见并短暂挡住桌面点击，直到下一次空闲回收成功或进程退出。
- 上报超时按固定 `5s` 判定：极慢磁盘或首次冷启动 WebView2 超过这个时长时，这次浮层会被误判为失败并收束，用户再右键一次即可重试（窗口已建好，通常第二次不再冷启动）。

## 待真机验证

- 弹层窗口在真实前台应用之上是否完整可见、无裁切。
- 弹层接管焦点后宿主 React 选择与临时展开状态是否按预期恢复。
- “先量后显”是否真的消除了尺寸闪烁；二级菜单换向是否与锚点可用空间一致。
- 空闲 `90s` 销毁后冷启动延迟是否可接受。
- 冷启动与隐藏复用（窗口隐藏后重新显示）场景下，`5s` 上报上限是否始终够用。
