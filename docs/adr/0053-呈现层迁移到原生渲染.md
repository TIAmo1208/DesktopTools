# 呈现层迁移到原生渲染

## 决策

桌面宿主、围栏、桌面项目、格子外壳与内容、浮岛、桌面层菜单和原生消息统一使用原生呈现层：Direct3D 11 提供图形设备，DirectComposition 合成表面，Direct2D 和 DirectWrite 绘制图形与文字。设置窗口和收集项编辑窗保留 WebView2，按需创建，关闭即销毁，不预建隐藏窗口。收集项编辑窗仍遵循 [ADR-0022](0022-收集项编辑使用按需窗口.md)。

不再追加针对现有 WebView 呈现路径的性能补测，按原生路线实施。资源占用在原生方案完成后统一评估。

## 依据

- 保留模糊样式的静态桌面，三个稳态窗口的应用组私有内存为 387 至 391 MiB。第三个窗口末，8 个 WebView2 进程合计约 368 MiB，占该快照约 94%；Rust 主进程约 19.5 MiB，guardian 约 3.3 MiB。
- 音乐播放且频谱持续重绘时，模糊开关两侧私有内存读数合计覆盖约 477 至 535 MiB。保留模糊侧的应用组单核 CPU 约 25% 至 40%。动态采样期间有其他重负载，读数仅反映该次运行，不能作为样式变更的因果证据。
- 去除格子表面的 `backdrop-filter` 后，静态私有内存三窗口均值低 36.05 MiB（9.25%），动态私有内存中位数低 17.06 MiB（约 3.36%，区间重叠）。静态单核 CPU 差值为 −0.058 个百分点，低于 10 个进程在约 60 秒窗口内的量化分辨范围（约 ±0.26 至 ±0.52 个百分点），不可分辨；动态 CPU 对照的区间重叠且受背景负载干扰，不能归因。样式变更没有移除 WebView2 进程组，不能替代对常驻呈现架构的调整。

内存与工作集取各被测 PID 的 `PrivateMemorySize64` 和 `WorkingSet64` 直接读数。CPU 取同一 PID 的 `TotalProcessorTime` 首尾差，再按实际窗口时长折为单核百分比；该计数受 15.625 ms 记账量子限制。不以启动前后的系统资源总量相减估算应用占用。

## 边界与不变量

- 只替换呈现层，不重写 Rust 领域层。工作区状态、文件事实、Shell 操作、插件清单与能力校验继续由现有 Rust 边界持有。原生呈现层读取同一份权威状态，不建立第二份布局或文件事实；继续遵循 [ADR-0041](0041-底层与UI的分层边界.md)。
- Windows 壁纸仍是根背景，透过原生宿主未绘制区域可见。桌面接管、交互语义、Explorer 与 guardian 的恢复职责沿用 [ADR-0006](0006-在透明桌面宿主中接管桌面项目.md) 和 [ADR-0016](0016-正式项目架构.md)；本决策替换其中由 WebView2 或 React 承担的桌面呈现机制，不改变原生 Shell 操作语义。
- 原生呈现消费主题令牌和装饰参数，主题脚本不再提供表现层。原生路径不执行 [ADR-0034](0034-主题插件角色与基线还原.md) 定义的主题激活脚本，也不加载主题样式表；主题切换与停用仍保留原有偏好基线还原语义。

## 分阶段与回退

1. 原生核心：接入图形设备、合成表面和桌面宿主。
2. 格子内置化：将内置格子的外壳与内容迁入原生呈现层。
3. 插件渲染树：由插件提交树，宿主负责布局、命中与绘制。
4. 主题数据化：原生呈现只消费主题令牌和装饰参数。
5. 窗口收尾：完成浮岛、桌面层菜单和原生消息的呈现迁移，落实保留窗口的按需生命周期。

每阶段独立提交、独立验收。原生路径达到对应 WebView 路径的等价能力前，保留旧呈现路径可回退；阶段未通过验收时，可使用旧路径继续读取同一份领域状态。

## 待验证假设

- 完整原生宿主的实际常驻占用未实测。80 至 200 MiB 是规划估算，不是实测结果或验收阈值。
- 进入插件渲染树阶段前，逐项补齐或明确降级七项能力：交互命中、文本测量回读、节点动画、剪贴板、用 `key` 保持槽位稳定、`hidden` / `visible` 语义，以及宿主定时器、`requestAnimationFrame`（rAF）与可见性上报。
