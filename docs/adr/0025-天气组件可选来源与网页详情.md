# 天气组件采用可选来源与网页详情

多来源并存、按来源城市列表与格子自持来源的调整见 [ADR-0026](0026-天气多来源与多城市并存.md)，本决策中“一次只启用一家”的条款已由该决策替代。

## 已确认决策

天气作为官方桌面组件，提供手动选择城市的当前天气、未来 24 小时和未来 7 天天气预报。每个格子保存自己使用的来源与城市，采用摄氏度、公制及目标城市时区，不进行自动定位。

UX 与 UI 均已确认，样式、配色、动画参数及适配阈值以视觉规范和确认画板为准。天气同时依据可用宽度与高度切换详情视图，默认最小当天摘要。固定标题和默认字号下的预设外框分别为当天摘要 192 × 120 DIP、小时预报 404 × 172 DIP、7 天预报 224 × 352 DIP、完整预报 454 × 372 DIP。最小展开视图不同于公共折叠态；大字号下按实际内容测量提高可读下限，真实字体与切换边界尚未经实现验证。

当天摘要显示城市、当前温度、天气、今日最高/最低温和来源，过期时保留数据并标记，完整获取时间通过提示查看。小时模块显示全部 24 小时的时间、天气和温度，按可用宽度分页；日模块显示含今天的 7 天天气、每日最高/最低温。宽矮显示当前与小时模块，窄高显示当前与日模块，宽高同时显示全部模块。

右键“切换显示模式”二级菜单只显示模式名称，提交对应真实格子尺寸，保留位置与城市，沿用工作区边界及布局撤销；空间不足拒绝该尺寸操作。上方“固定显示模式”勾选项固定当前实际模式，固定期间不调用尺寸选择逻辑，公共缩放下限使用该模式内容阈值加当前标题和内边距；菜单可更换固定模式，取消固定恢复自动判断。固定状态和模式复用组件 state 持久化，缺失时默认自动；不增加专用存储或兼容迁移。先提交尺寸再保存状态，尺寸失败不改变固定模式；若状态保存失败，保留原固定状态并提示错误，已成功的尺寸操作可沿用布局撤销。城市弹窗按提交搜索，结果包含行政区，选择成功后写入该来源的城市列表或绑定到发起格子，随后关闭；取消保持原值，保存失败留在弹窗并允许重试。

接入和风天气与 Foreca 两个来源，可由用户在设置中同时配置与使用；不拼接两家数据、不自动失败切源。来源归属由每个天气格子自己选择，不再有全局“当前启用来源”，也不再有 `weatherSource` 偏好；凭据记录名与城市数据路径仍按来源派生，不以来源字段写入其他来源的记录。和风使用 GeoAPI 搜索城市，天气使用当前、小时与日预报接口，城市搜索返回对应位置的 `fxLink` 承接网页详情。Foreca 使用 `/api/v1/location/search`、`/api/v1/current`、`/api/v1/forecast/hourly` 与 `/api/v1/forecast/daily`，凭据以 `Authorization: Bearer` 提交，服务地址固定为 `weatherapi.foreca.net`；Foreca 没有对应城市的天气网页，该来源下详情入口不可用。接入两家的原因是基础预报覆盖已确认范围，且都允许用户自带账户，不需要产品方代理。

Foreca 的位置搜索覆盖到城市级，不包含区县与街道，未收录的位置需要用户改选所属城市；中国主要城市已验证可以检索，其中中文位置名只在带 `lang=zh_CN` 时才命中，英文名同样可用。位置覆盖范围以供应商数据为准，不补充本地地名映射。

两个来源都采用用户自带账户凭据，设置中按来源分别配置。和风提供 API Host、开发者 ID、项目 ID、凭据 ID 与 Ed25519 私钥，由 Rust 按需签发短期令牌，不要求用户反复粘贴到期令牌；和风 API KEY 不纳入方案。Foreca 只提供 API key，以 `Authorization: Bearer` 提交，字段与格式校验按该来源单独定义。用量、额度及费用归用户自己的账户；每个天气实例按自己选择的来源取数，城市选择只改变该实例的查询位置。产品不内置共享凭据，不提供统一代理服务，以保持纯本地运行边界。配置入口为软件设置的“功能格子 → 天气”二级设置，输入字段随所选来源切换，和风私钥采用密码输入框的遮蔽输入模式并支持导入，沿用现有设置控件视觉规则。凭据由 Rust 配合 Windows 凭据保护能力保存，已选 Windows Credential Manager，每个来源一条独立记录。

设置页以列表显示已配置来源，行内显示服务地址、认证模式与可用状态，不提供启用开关与“当前使用”文本。每个来源维护自己的城市列表，列表项可以添加和删除城市，删除只移除该项。可用状态取该来源最近一次实际请求结果，尚未请求过时显示未确认。来源右键菜单提供显示详情、检测可用、添加城市、添加天气格子与删除，删除单独成组并需要确认；删除只清除该来源凭据，其他来源与其城市列表不受影响，相关天气格子按已确认的窗口继续显示旧缓存。列表只显示已配置来源，未配置来源通过“添加 API”进入添加弹窗；添加与编辑共用同一弹窗，编辑模式不显示供应商切换，非敏感字段回填已保存值，私钥与 API key 不回读。

详细天气通过右键菜单或单击按钮交给系统浏览器打开当前来源的城市天气网页；和风使用其城市搜索返回的 `fxLink`，Foreca 没有对应网页，该来源下入口保持禁用。命令名称和按钮提示统一为“查看详情”，不在入口名称中显示供应商。各尺寸共用公共标题栏右上角详情按钮与右键菜单，底栏贴内容区底边并保持固定高度，仅呈现紧凑来源时间及必要状态，避免详情按钮抬高底栏。链接应指向当前所选位置的天气详情，API 文档或原始 JSON 不替代详情网页，不嵌入浏览器或抓取网页内容。来源署名独立遵守各供应商要求，不因入口简化而移除；和风接口 `attributions` 返回的是指向供应商署名页的 URL 而非显示名，紧凑底栏对该来源固定使用“和风”文字署名，不直接渲染该 URL。Foreca 要求显著展示“Powered by Foreca”或 Foreca logo，紧凑底栏无法展示 logo，对该来源使用“Powered by Foreca”文字。来源没有可用详情网页时，“查看详情”按钮与菜单项禁用，不指向 API 文档或原始 JSON。底栏署名取当前格子所选来源，不写死单一供应商。

“当前天气”“小时预报”“7 天预报”分别作为独立内容模块，尺寸决定模块组合与排布。各模块独立表达加载、缓存与失败，单个模块失败不得清空其他模块的有效数据。跨显示组合切换使用 180ms ease-out、4 DIP 位移与淡入淡出，保留模块只平移，不缩放文字图标；连续反向切换从当前呈现状态收敛到最新目标。沿用现有有效动画状态，遵守“界面动画”及“跟随系统减少动态效果”，不新增天气专用开关。动画关闭或宿主暂停时立即呈现最终布局，稳定画面不保持动画计时器，销毁时清理资源。

## 原因与职责边界

以基础天气查看为目标，通过来源网页承接复杂信息，减少数据接入、凭据、解析与界面维护成本。不引入自动失败切源、多来源数据拼接、自建代理、空气质量、预警或复杂天气数据处理，不复用其他项目内置的 API key。

Rust 统一负责请求、超时、响应校验、缓存和失败退避，React 负责呈现与来源城市设置。天气通过现有官方插件运行时和能力边界接入，Tauri 与原生桌面通道复用同一业务入口；布局保存位置配置，天气缓存与布局分离。

请求成功并通过校验后，将天气结果与获取时间缓存到本地磁盘。打开、重启及恢复显示时优先读取对应位置的本地缓存；有效缓存不请求服务器，过期且存在活动实例时才后台更新，失败时退避。当前天气有效期 30 分钟、小时预报 1 小时、日预报 3 小时，分别判断并只更新过期部分；首版不提供绕过有效缓存的强制刷新，失败重试遵守退避。无活动实例时停止定时请求，同一位置的多个实例与多屏共享缓存和在途请求。活动条件包括功能开启、内容实际展开且宿主未暂停；数据更新通过既有事件通道通知页面，不让各页面持续独立轮询。

拖动缩放、切换预设尺寸、切换或浏览详情内容以及打开菜单只消费本地数据，不触发新的天气请求。显示粒度与数据获取分离，避免界面操作增加请求量。

缓存记录最近成功结果与获取时间。失败时保留旧结果并呈现过期或失败状态，首次无缓存时明确显示失败；更换位置后拒绝旧位置的迟到响应。外部详情地址须校验后由系统浏览器打开。

## 凭据安全、来源隔离与能力验证

API Host 按[官方 API 配置说明](https://dev.qweather.com/docs/configuration/api-config/)从控制台完整复制，作为不透明主机名使用；官方说明未定义中间标签含义，因此不推断区域或环境，也不限制标签层级和中间标签取值。先验证纯 ASCII DNS 主机名：总长不超过 253 字节，各标签为 1–63 字节，只允许字母、数字和非首尾连字符；再按 DNS 大小写不敏感规则要求以带点边界的 `.qweatherapi.com` 结尾。拒绝根域名、空标签、尾点、协议、端口、路径、查询、片段、用户信息和伪造后缀；通过后使用完整 Host 发起 HTTPS 请求，保留 TLS 校验、禁止重定向和凭据保护。格式通过只证明满足本地地址边界，不证明账户或接口可用；真实接入尚未验证。测试与文档只使用虚构主机名，不记录用户真实 Host。

凭据保护采用 Windows Credential Manager 的本机持久通用凭据，按当前用户和应用配置归属隔离；私钥与账户参数整体保存，替换失败保留旧记录，不使用普通 JSON 或 DPAPI 文件作为后备。该能力不抵御已取得同一 Windows 用户执行权限的程序。仅设置窗口可提交、验证、保存或清除凭据；后端仅返回非敏感状态，城市搜索结果和验证天气只保留会话内存。

天气凭据使用固定的应用级 Credential Manager target，不随配置目录变化；配置目录迁移无需复制或删除凭据，应用内清除始终作用于同一条记录。该边界避免后续目录迁移产生应用无法定位的孤儿凭据。历史版本按目录哈希保存的记录没有可枚举索引，已确认不自动迁移，重新保存后由用户通过系统凭据管理器清理旧记录。

配置验证由 Rust 权威会话绑定凭据草稿与临时城市；字段更换、取消或配置提交使旧会话结果失效。后端独立校验全部能力通过才允许保存，不信任前端传入的通过标记。HTTPS 请求限定账户官方 API Host，禁用重定向，限制超时及响应大小；错误不包含原始请求、令牌、私钥或供应商响应正文。JWT 使用 Ed25519 按需签名，签发时间偏移与有效期参数在实现时按官方要求验证。

已确认的天气缓存只保留每位置、配置与模块的最近成功结果，磁盘最多保留 7 天，在读取和成功写入时清理，不增加常驻清理轮询。当前天气获取后最多展示 24 小时并明确过期；预报只显示目标城市时间窗内仍有效的条目，缺项明确不可用。日期或完整预报窗口不足也使缓存失效，由活动实例合并更新，即使尚未达到原有时间有效期。

可恢复网络错误按 1、2、5、15、30 分钟退避，上限 30 分钟；无活动实例停止调度，恢复活动仍遵守未结束的退避。认证或权限失败暂停对应自动请求，配置重新验证后恢复；限流优先遵守服务端等待时间，不以本地上限提前重试；额度耗尽且无明确恢复时间则停止自动尝试，由用户稍后主动验证。手动验证也拒绝并发提交。退避与活动计划按来源和城市隔离，一个来源的失败不停止其他来源的更新。

密码输入框仅遮蔽显示，不提供存储保护。API key、JWT 私钥等敏感材料由 Rust 配合 Windows 凭据保护能力保存，不写入普通偏好 JSON，不加入窗口快照或广播，不进入日志、配置导出与诊断包。普通状态只表达是否已配置及验证结果；设置输入需要提交敏感材料，不等于可以在后续快照中回传原文。凭据保护选用 Windows Credential Manager；真实账户验证尚未完成。

凭据、城市标识、天气缓存及在途请求须具有明确的数据来源归属，更换凭据后拒绝旧配置的迟到响应。若后续单独确认支持平台切换，同样必须隔离平台状态，不能复用另一平台的城市标识、缓存或请求结果。本约束明确来源隔离要求，不扩大首版和风单源范围，不要求提前实现多平台框架。

接入验证分别确认位置搜索、当前天气、未来 24 小时与含今天的 7 天预报能力，并核对所需来源署名与当前城市详情链接。验证项名称与项数由草稿来源决定：和风为城市搜索、当前天气、24 小时预报、7 天预报与来源及详情链接，Foreca 为位置搜索、当前天气、24 小时预报与 7 天预报；没有城市天气网页的来源不设详情链接项，不计为失败。仅认证成功或一个接口成功，不得标记全部能力可用。验证结果区分权限不足、配额耗尽、网络失败及数据缺失；页面的成功状态仅覆盖实际已验证范围。

已确认配置流程为填写凭据草稿、使用草稿搜索临时验证城市、主动验证全部能力、保存并启用。验证通过的城市写入该来源的城市列表，不改变已有格子的绑定。任何凭据字段变化使原验证失效，全部能力通过才允许保存；不持久保存未验证或离线草稿，避免将不可用配置误作已启用配置。验证可取消并拒绝迟到结果；离开未保存编辑时确认放弃或继续编辑。

私钥显隐仅作用于当前编辑草稿，不回读已保存私钥。验证或保存失败保留旧配置，保存失败保留编辑草稿；保存成功才启用新配置、拒绝旧响应并清空敏感草稿。替换需要明确输入新值，空输入不代表清除。清除凭据须明确确认，成功后停止联网更新，保留格子布局与该来源的城市列表；相关格子转入来源缺失状态，旧缓存展示仍受上述保留期限和时间窗口约束。

## 接口计费与缓存适用边界

依据和风[请求定义](https://dev.qweather.com/help/#what-is-a-request)，一次请求无论返回多少内容均计一次，返回非 2xx 不计请求次数。当前天气、小时预报、日预报是三个独立接口，各调用一次合计三次；应用内组合成整包或并行调用不合并计费。单次获取 24 小时或 7 天各计一次，减少返回小时数、天数或仅使用少量字段不减少该次调用的计费次数。批量获取需联系商务，未确认存在公开的三类合并接口或整包折扣。客户端超时不能证明服务端未计次。

读取本地缓存及改变显示粒度本身不产生接口费用。请求量应按实际数据依赖估算：当天摘要若显示最高/最低温，仍需日预报数据，不因隐藏 7 天模块而只依赖当前天气接口。

官方[缓存说明](https://dev.qweather.com/help/)允许天气数据缓存，但明确禁止地理信息数据缓存或建立索引。因此天气本地缓存不包含 GeoAPI 响应整包。产品已确认按来源保存用户显式添加的城市对象列表，用于设置页管理、格子菜单选择与下次启动恢复天气请求；该独立城市存储不保存搜索结果数组，不进入普通偏好、工作区快照或日志。各来源按自己的许可边界保存城市对象，位置标识不跨来源通用。

Foreca [服务条款](https://business.foreca.com/weather-api/terms-of-service)第 2 条只授予“按服务说明使用服务与内容”的有限许可，并声明不得以条款未明确许可的方式使用或转移内容；其服务说明只描述接口、请求限额与署名，未提及本地缓存或位置数据留存。用户已按“自带账户、本机自用、数据量级极小”的风险认知决定该来源与和风采用同一套按来源文件的持久化模型，见 [ADR-0026](0026-天气多来源与多城市并存.md)；供应商的书面澄清仍待补充。署名文本按条款第 3 条使用“Powered by Foreca”；免费额度、付费套餐与非商业使用条件单独核对。

- 和风[官方定价](https://dev.qweather.com/docs/finance/pricing/)采用按量阶梯计费：天气预报与 GeoAPI 等同属“天气和基础服务”价格组，每月前 50,000 次免费，之后 950,000 次为每次 CNY 0.0007；不是每个接口分别享有免费额度。账户实际计费、权限与发行使用条件须在接入前核对，不将免费额度写成永久免费保证。
- 本决策不授权购买服务，不在客户端内置复用其他项目的密钥；设计使用示例数据，不依赖真实凭据。

## 当前实现与实现边界

来源归属、按来源城市列表与格子自持来源与城市的行为见 [ADR-0026](0026-天气多来源与多城市并存.md)，本节记录该调整落地后的实现状态与实现边界。

天气运行期状态按来源索引：凭据记录名按来源派生，每个来源在自己的城市列表文件里维护用户显式添加的城市对象，配置代次、取消标记与预报退避都以来源为键，来源之间互不取消、互不覆盖同名城市。取数与城市搜索入口显式接收来源；城市对象由 Rust 从该来源的城市列表解析，前端只提交来源与城市标识。能力验证项的名称与项数由草稿的凭据结构决定，和风返回五项、Foreca 返回四项，前端按后端返回逐项渲染，不硬编码检查项数量；后端仍按来源声明的完整项数判定验证通过。

设置页已按确认的列表结构实现：列表只显示已配置来源并显示服务地址、认证模式徽标与可用状态，右键菜单提供显示详情、检测可用、添加城市、添加天气格子与删除（删除单独成组并需确认），底部提供“添加 API”。来源列表项可展开查看并管理该来源的城市列表。可用状态保存在运行期内存中，配置保存或删除后回到未确认。探测使用固定位置只请求一次当前天气，与完整能力验证相互独立。

已保存配置的预报和城市搜索请求绑定运行期配置代次与共享取消标记。保存或清除凭据成功后取消旧请求，并清空旧预报退避；保存失败保留旧请求身份和退避。网络期间不持有设置状态锁，预报提交时在同一锁内核对代次并完成缓存、错误和退避写入，拒绝旧配置迟到结果。磁盘天气缓存以全部凭据字段的 SHA-256 指纹核对配置归属，使用 Windows BCrypt 计算，敏感序列化缓冲使用后清零；指纹仅在后端和缓存文件内使用，返回页面前移除，不写入日志。存在凭据时，缺少或不匹配指纹的缓存不命中，不迁移旧缓存；清除凭据后允许按既有展示期限读取旧缓存，但不联网。配置保存或清除成功后通过 `weather-configuration-changed` 发送无数据通知，沿用 Tauri 与原生宿主事件通道；暂停时仍交付失效通知。城市从来源列表删除后同样发送该通知，使已展开格子的城市绑定失效立即生效，见 [ADR-0026](0026-天气多来源与多城市并存.md)。天气内容先订阅再读取，收到通知清除旧快照并拒绝旧响应，只在展开、可见且未暂停时重新读取；订阅失败明确提示，卸载释放监听。城市弹窗搜索已使用会话代次拒绝旧配置和卸载后的结果，搜索开始清空旧选项，配置变化清空结果并提示重新搜索；即时忙碌标记防止重复提交。

缓存有效性同时检查模块获取时间与 Provider 的内容和时间窗规则：时间戳尚未到期也不能复用不足 24 小时、跨日后不再含今天的七天或字段损坏的数据。该检查在预报读取入口执行，只将失效模块纳入更新；展开天气实例由共享活动调度按模块到期和退避时间补齐。

来源栏已按当前、小时、日模块各自的获取时间与有效期显示过期状态，使用最早到期点的一次性计时；隐藏、折叠和宿主暂停时停止，恢复后重新判断，不触发天气请求。完整获取时间通过悬停提示按城市时区显示。原生提示与显示效果尚未经真实环境验证。底栏来源署名取当前格子所选来源，切换来源后随之变化。

天气入口复用功能格子列表与显示开关，`weatherEnabled` 默认关闭并通过普通偏好保存，避免把凭据是否已配置等同于格子是否显示。官方组件宿主已消费该开关；切换开关不更改凭据。API 字段通过已有 `SettingsInfo` 提示来源和格式，避免新增独立引导流程。

桌面预报与设置能力验证共用天气结构、摄氏单位及小时/日预报时间窗校验。桌面响应未通过校验时作为对应模块失败，不赋予成功时间戳、不覆盖旧模块缓存；HTTP 成功不等同于天气数据有效。前端按小时条目的结束时刻和日条目的 `forecastEndTime` 移除已过期预报，通过最近结束点的一次性计时更新；隐藏、折叠或宿主暂停停止计时，恢复活动重新判断，旧回调不得覆盖新预报。日历标签和摘要最高最低温按城市日期定位今天，不以数组首项推断。窗口不足沿用模块状态提示，不因显示过滤发起请求；后台共享活动调度负责后续补齐。

布局测量已改为观察公共视口的实际内容盒，扣除内边距和边框，标题显隐及拖动均可更新；模式切换按完整、7 天、小时、摘要的单条条件链匹配，不保留滞回。大字号实际内容测量尚未实现。模块动画已使用稳定 DOM 身份实现进入、退出及保留模块平移；反向切换先读取当前呈现帧再取消旧动画，退出模块立即移除交互焦点，完成或卸载释放动画资源。前端已复用公共格子实际展开状态和 `desktop-refresh-changed` 宿主事件，暂停或折叠时停止预报读取、到期计时和模块过渡，恢复活动时保留缓存并重新读取；旧生命周期和隐藏前的响应不得覆盖恢复后的结果。后端活动实例共享调度已接入。

天气展示及 API 设置 UX/UI 已确认。API 设置页、临时城市验证、JWT 签名与 Windows Credential Manager 保存替换清除已实现；桌面天气格子已接入当前摘要、24 小时预报、7 天预报、紧凑来源更新时间和过期标记，并按实时格子宽高组合显示，拖动缩放期间即时切换布局。详情入口位于公共标题栏右上角，并保留右键菜单入口。格子启动时从独立天气城市缓存恢复当前城市；城市选择成功后保存该城市，GeoAPI 搜索结果不落盘。Rust 已接入按城市和模块隔离的天气磁盘缓存、模块有效期判断、只请求过期模块、进程内请求串行及当前/小时/日部分失败返回；活动实例调度与预报更新事件已接入；请求入口已实施模块退避。

设置命令只对 `main` 设置窗口开放，后台任务按窗口代次和草稿会话身份拒绝迟到结果。HTTP 使用系统 TLS 校验，禁止重定向，连接超时 8 秒、单请求总超时 20 秒，解压后响应最多 512 KiB；JWT 按官方要求提前 30 秒签发，有效期 15 分钟。连续小时按实际时间戳验证，日预报按城市 IANA 时区核对含今天的七天，避免以固定 24 小时推算夏令时日期。上述参数适用于用户主动验证；自动调度仍按已确认的独立实施规则执行。取消立即使结果失效，已发出的有界 HTTP 请求可等待超时收尾，期间拒绝新并发请求。

城市校验按来源分两层：坐标、时区、标识与长度等公共规则由天气模块统一执行，城市详情链接规则移入各来源实现；没有城市天气网页的来源允许空的详情链接，该来源的“查看详情”入口按链接为空保持禁用，不计为验证失败。
