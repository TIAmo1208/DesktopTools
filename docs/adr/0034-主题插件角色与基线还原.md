# 主题插件角色与基线还原

## 背景

插件原来只有格子外壳、设置条目、能力声明和自带样式表。主题需要换配色和外观四项，但不能执行作者脚本，也不能把用户原来的字体、字号、圆角和强调色永久改掉。

## 决策

### 角色

清单 `role` 缺省为 `tile`。`role=theme` 时宿主同样承认主题数据：`stylesheet` 必须是插件文件夹内的 `.css`，`theme.json` 必须存在且只含 `appearance` 与可选的 `fonts`。`entry` 键必填；主题与格子一样可以带入口脚本，入口文件存在时注册结果里的 `script` 照常下发，不存在时为空串，避免无脚本主题收到一份假的加载失败。主题默认没有格子创建能力；只有入口文件存在且清单声明 `creatable` 时才放行创建并读取 `maxTiles`，其余情况 `creatable` 固定为 false、`maxTiles` 为 0——这样换肤和它自带的格子可以放在同一个插件里，又不会让无脚本主题凭空多出一个空格子。主题脚本通过外壳的 `activateTheme(context)` 在主题被选中后每个窗口执行一次，停用、切换主题和窗口销毁时执行其返回的清理函数；格子的 `renderTile` 与普通插件一致。插件表现不受视觉规范约束。

`theme.json` 的字段、可覆盖令牌和明确不可覆盖的网格、透明根表面、原生窗口外观见[主题变量契约](../design/主题变量契约.md)。

### 挂载时机

每份文档在偏好变量副作用之后挂主题样式表。偏好先把外观四项和网格写成文档根的内联样式，再挂唯一的 `link[data-theme-plugin]`，地址为 `/plugins/<stylesheet>?v=<version>`。切换时先挂新表再摘旧表。没有选中主题、主题已停用，或样式表加载失败时摘掉该 link，页面回到内置主题。加载失败时复用现有消息通知，不另开通道。

停用名单沿用 `disabledPlugins`。样式表路径已经是插件根相对路径，前端不再拼接文件夹名。

### 基线还原

首次选中主题时，把当时的界面强调色、桌面强调色、圆角、字体族和字号记入 `themeBaseline`，并把主题 id 记入 `themePluginId`。换主题先按这份基线还原，再写入新主题里非空的外观项；空项保留基线，不继承上一主题。切回内置主题时还原基线并清空这两个字段。还原时逐字段校验旧基线，非法字段退回当前默认值，不因此拒绝退出主题。字体族不再要求属于系统名单，只校验字形名格式：基线里的字体可能来自已被停用或卸载的主题，保存时不能因此判定整份基线非法，界面按回退栈显示。主题自带的字体不进入基线：捕获时当前字体属于该主题声明的字体就记为默认字体，还原时基线字体与当前字体相同且不属于系统名单也按默认字体处理，避免主题字体被当成用户原值留下去。插件自带字体的来源与注入方式见 [ADR-0035](0035-插件自带字体与字体列表.md)。

外观页的主题选择通过既有 `savePreferences` 一次提交上述结果。跟随 Windows 主题色的开关不进入基线。

## 后果

- 主题插件没有可执行入口，配色只来自宿主挂上的样式表，外观四项只来自偏好。
- 内联样式优先于主题样式表，因此外观四项和网格尺寸不能靠 CSS 覆盖。
- 停用、卸载和清单缺失要回到内置主题时，必须走同一条还原再保存；只改名单或删文件夹不会自动写回基线。
