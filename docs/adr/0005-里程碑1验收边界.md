# 锁定里程碑 1 验收边界

Milestone 1 交付一个可独立使用的 Windows 桌面整理器。Desktop Tools 通过 React/WebView2 呈现并操作完整桌面项目集合、围栏和组件；Explorer 提供桌面命名空间、Shell 操作和恢复兜底。桌面宿主、完整交互和 Shell 操作语义均由当前正式项目实现并验收。

## 桌面宿主门槛

1. 枚举并呈现真实桌面项目、系统显示名称和系统图像。
2. 一个围栏支持移动、缩放、平铺布局、列表布局、折叠和内部滚动。
3. 未归类区域与围栏之间支持桌面项目拖动；进入围栏后释放桌面槽位，原位置仅用于撤销，普通移出按当前目标重新落位。
4. 桌面项目支持单击选择、双击打开和真实 Shell 上下文菜单。
5. 每台显示器通过真实截图或像素探针确认 Desktop Tools 可见像素后，提交接管并隐藏 Explorer 图标视图。
6. 启动失败、正常退出和主进程崩溃后恢复 Explorer 原始状态。
7. 每台显示器使用任务栏上方的有效工作区。
8. 当前开发与运行平台 Windows 10 22H2 执行强制验收。

## 功能与恢复验收

1. 通过 Windows Shell 桌面命名空间枚举文件、文件夹、快捷方式和虚拟项目，并提供稳定项目引用、系统显示名称、系统图像和操作能力。文件夹、快捷方式和虚拟项目显示系统图标；支持缩略图的图片、视频和文档显示 Shell 缩略图，加载期间先显示系统图标。缩略图复用 Windows Shell 缓存并使用进程内 LRU，图像和属性变化通知使对应缓存项失效。
2. 每台显示器拥有一个透明桌面宿主，Win+D 能稳定显示桌面内容工作区。
3. Desktop Tools 自绘未归类桌面项目、围栏成员和组件；图标与名称组成桌面项目的完整交互单元。
4. 整个工作区统一维护完整桌面项目集合、围栏成员与归属、位置、组件和滚动状态；首次接管时导入 Explorer 当前图标位置，无法匹配的项目进入事件发生时 Windows 当前主显示器未归类区域的最近可用网格位置。虚拟桌面切换不切换布局、选择或焦点，不因桌面身份变化主动取消拖动；Windows 原生取消事件仍遵循既有取消契约。
5. 其他程序新建的桌面项目和重新进入桌面命名空间的项目进入当前主显示器未归类区域，并占用最近可用网格位置；Shell 确认删除或移出桌面命名空间后，项目退出全部活动布局；重命名同步更新全部活动布局中的项目引用。
6. 围栏支持平铺、列表、内部滚动、折叠、标题悬停展开、固定展开、锁定和解散；围栏锁定固定位置和尺寸，成员选择、打开、菜单、滚动、排序和归属操作继续可用。平铺模式在 Milestone 1 提供一种跟随 Windows 系统指标和 DPI 的标准密度，项目名称默认最多两行并省略，选中或获得焦点时在固定项目单元上方展开完整名称，网格尺寸与相邻项目位置保持稳定；完整名称覆盖层绘制在相邻项目上方，指针输入归属原项目，并裁剪在所属围栏内容区或未归类区域边界内，焦点与选择结束后收起。列表模式显示系统图像、名称、类型和修改时间，名称为弹性主列并保持单行省略，完整名称通过提示显示；其他列可调整宽度，每个围栏分别持久化列宽、列顺序、排序字段和排序方向。手动排序为默认模式，自动排序提供名称、类型和修改时间规则，自动排序期间拖动只改变围栏归属；自动排序使用 Shell 属性和 Windows 自然字符串比较规则，主字段相同时依次使用系统显示名称和稳定项目引用裁决。具备排序属性的项目正常排列，属性暂缺项目放在末尾并保持已有稳定顺序，属性就绪后重新进入完整排序。Shell 属性变化通知在 `250 ms` 窗口内合并，窗口结束后执行一次完整重排，并以最小滚动量保持焦点项目可见。项目进入自动排序围栏后立即按当前字段和方向重排整个围栏，拖动预览只提示目标围栏。标题持续作为折叠围栏的有效投放目标，悬停 `400 ms` 展开内容区，展开前完成投放时按自动排序规则落位或追加到手动顺序末尾。成功投放后继续遵循围栏展开策略：标题悬停模式在指针与拖动项目离开 `600 ms` 后收起，手动展开和固定展开保持当前状态。最后一个成员移出后保留围栏及其最后展开尺寸、布局模式、滚动位置和层级。空围栏折叠时显示标题，手动或悬停展开后恢复空内容区并继续作为项目拖放目标，直到用户显式解散。解散命令直接形成一个可撤销布局事务，成员以围栏内容区左上位置为组锚点，按当前视觉顺序进入原显示器未归类网格，逐项避让已有项目并保持连续排列；围栏锁定状态随围栏结束，`Ctrl+Z` 完整恢复围栏及成员状态。
7. 桌面交互模型采用 Windows 系统交互作为选择、键盘和焦点行为基线，并支持单击、`Ctrl` 多选、框选、方向键导航、双击、`Enter`、围栏内排序、围栏间归属变更和跨显示器布局；当前工作区使用一个覆盖全部围栏和显示器的选择集合、一个选择锚点与一个键盘焦点，切换虚拟桌面不清空选择或重置焦点。最近获得项目焦点的项目成为选择锚点；`Ctrl+单击` 和 `Ctrl+Space` 切换目标选择状态后继续以该目标为锚点，框选以视觉顺序中的首个选中项目建立焦点与锚点。`Shift+单击` 在同一围栏或未归类区域内按视觉顺序执行范围选择；选择锚点位于其他焦点容器时，清空原选择，以目标项目建立新的选择锚点和单项选择。范围选择包含锚点与目标之间的全部逻辑项目及当前滚动视口外项目，围栏滚动到足以显示当前焦点项目的位置。列表与自动排序模式采用当前渲染行顺序，平铺与自由定位模式按从上到下、从左到右的几何顺序排列，几何位置相同时按持久顺序裁决。自由定位项目重叠时，指针命中层级最高的项目，单击或拖动将目标项目置顶，键盘导航继续覆盖该未归类区域内的全部项目；每个未归类区域独立持久化项目层级，显式置顶命令形成布局事务。方向键移动焦点并将选择收束到目标项目，`Ctrl+方向键` 移动焦点并保持现有选择，`Shift+方向键` 从选择锚点扩展连续选择，`Ctrl+Space` 切换焦点项目的选择状态；项目焦点容器内的 `Ctrl+A` 选择该容器全部桌面项目，围栏标题焦点选择围栏全部成员，桌面背景焦点选择当前显示器未归类区域全部项目，组件焦点按组件交互契约处理。`Tab` 与 `Shift+Tab` 在未归类区域、围栏标题和组件之间按当前显示器视觉顺序正向或反向移动，越过显示器边界后按屏幕几何进入相邻显示器；重叠目标按持久层级顺序裁决，方向键负责焦点容器内部项目导航。单击围栏标题、围栏空白内容区或桌面空白区域时清空桌面项目选择，并将键盘焦点移动到对应围栏或桌面背景。框选从桌面空白区域开始，选择框与项目交互区域相交时选中项目。方向键按屏幕几何方向选择最近项目：左右导航优先选择垂直投影相交的候选，上下导航优先选择水平投影相交的候选，再比较距离，并从边缘继续进入相邻围栏或显示器。项目滚出围栏视口后保持选择与焦点；围栏折叠时清除其成员选择并将键盘焦点移到围栏标题。
8. Shell 操作代理支持 `F2` 重命名、`Delete` 回收站删除、`Shift+Delete` 永久删除、属性和 `Ctrl+C/X/V`；单选桌面项目时 `F2` 直接进入重命名，多选时调用 Shell 明确提供的批量重命名能力。共同 Shell 能力集合缺少批量重命名时，`F2` 保持当前选择并跳过操作，菜单命令保持禁用，同时显示简短中文状态提示。F2 编辑期间项目保持当前位置；Shell 确认重命名后更新项目引用并按当前规则重排，同时保持该项目的选择、焦点和可见性。操作结果以 Windows Shell 返回状态为权威。Desktop Tools 在当前应用会话中为重命名、移动、复制和移入回收站保存可逆操作日志，并通过新的 Shell 操作执行撤销与重做，同时把原始操作和补偿操作分别写入 Explorer 会话撤销记录；永久删除作为不可撤销操作呈现。补偿操作使用原生 Shell 确认与错误界面，成功部分和用户选择形成新的日志状态。Shell 变化通知识别 Explorer 外部撤销或重做，明确匹配时更新对应记录，结果存在歧义时终止该记录及其后续重做链。部分撤销显示“已恢复 X 项，Y 项状态已变化”，后续重做只作用于该次实际恢复且仍有效的项目集合。
9. 桌面项目支持真实多选 Shell 菜单、owner-drawn 菜单项和动态子菜单；右键已选项目时保留当前选择集合并为该集合显示菜单，右键其他项目时将目标设为唯一选择并显示单项菜单。产品命令使用全部选中项目的共同能力集合，命令适用于整个选择集合时启用，并将“加入围栏”“移出围栏”等批量操作提交为一个布局事务。
10. Desktop Tools 与 Explorer 及其他程序之间使用系统 OLE 文件拖放契约；同一围栏内拖动只调整顺序，围栏与未归类区域之间拖动固定执行逻辑归属，`Alt` 在未归类区域控制自由定位，指针进入 Shell 投放目标或跨程序边界后由原生 OLE 契约解释修饰键。外部项目拖入围栏时先完成桌面命名空间操作再加入目标围栏，拖到桌面文件夹项目时委托目标的 Shell 拖放语义。拖动已选项目时携带完整选择集合，拖动其他项目时将目标设为唯一选择并开始单项拖动。拖动开始后冻结全部参与容器的顺序，期间到达的 Shell 变化通知进入队列，拖动完成或取消后处理队列并按最终事实更新布局。多个项目进入围栏时按来源容器当前视觉顺序组成连续块并在投放位置一次插入；来源覆盖多个容器时，依次按显示器视觉顺序、容器视觉顺序和项目视觉顺序稳定排列。批量“移动到围栏”命令保留目标围栏已有成员的位置，并将其他选中项目按稳定视觉顺序追加到末尾。组落位与已有网格项目碰撞时，优先整体平移到位移最小的可用区域并保持组内相对位置，剩余溢出项目按组内视觉顺序进入最近可用网格；多个候选位置具有相同位移距离时，依次按从上到下、从左到右和网格坐标裁决。目标网格容量不足时恢复拖动开始前的源布局、滚动位置和层级，保留完整选择集合，并将焦点恢复到拖动锚点，同时显示“目标区域空间不足，项目已恢复原位”；按住 `Alt` 投放时允许项目在目标工作区内自由重叠定位。选择集合来自多台显示器时，每个源显示器子组保持内部 DIP 几何，各子组按显示器视觉顺序组成连续块，并以实际拖动项目所在子组为落位锚点。暂时无法解析的项目引用继续参与逻辑拖动、归属和排序，进入 Shell 投放目标时依据共同 Shell 能力和系统操作结果执行。重叠围栏悬停只显示临时目标预览；成功投放后将目标围栏置顶并持久化层级，取消拖动恢复开始前层级。按 `Esc` 或系统取消拖放时恢复拖动开始时的归属、顺序、位置和自动滚动前滚动位置，并保留原选择集合与拖动锚点焦点。拖动项目进入围栏内容区 `24 DIP` 边缘区域后自动滚动，速度随指针接近边缘的程度增加，离开边缘或结束拖动时停止。系统剪贴板持有剪切数据期间，对应项目在整个工作区中显示剪切状态，粘贴、取消或剪贴板内容变化后清除。
11. 实时处理桌面命名空间中的创建、删除、重命名、属性和图像变化，并协调桌面项目引用与围栏归属。
12. 暂时无法解析的围栏成员保留引用并显示失效状态，重新解析后恢复原围栏、顺序和布局；Shell 确认项目删除或移出桌面命名空间后将其移出活动布局，历史快照继续保留恢复信息。
13. 使用版本化 Schema 原子保存自有布局，持久化显示器身份、围栏完整状态和桌面项目引用，并支持自动快照、手动备份、还原、Schema 迁移和上一可读版本恢复。手动备份覆盖完整自有布局、显示器映射、围栏、组件和桌面项目引用，并用于同一 Windows 用户配置文件内的备份与还原；Windows Shell 命名空间提供项目事实，选择、焦点与撤销历史属于运行期状态。还原前自动保存完整工作区快照，并计入发起还原时当前工作区的最近 `20` 份自动快照配额，再以事务方式替换工作区，暂时无法解析的项目保持失效状态。旧 Schema 在临时副本中完成迁移与校验，更高版本和校验失败的备份保持只读，当前工作区维持原状态。还原只替换统一工作区，不管理 Windows 虚拟桌面。
14. Windows“显示桌面图标”关闭时隐藏 Desktop Tools 桌面项目与围栏，组件继续显示；隐藏项目和系统项目遵循当前 Shell 可见性设置。
15. Desktop Tools 接收桌面空白区域输入，负责清空选择、普通模式框选和桌面背景菜单；桌面背景菜单通过 Shell 操作代理提供原生桌面操作并追加 Desktop Tools 操作，项目菜单提供 Shell 项目操作和产品归属操作。菜单键或 `Shift+F10` 根据当前键盘焦点显示桌面项目菜单、围栏菜单或桌面背景菜单；项目菜单锚定焦点项目，围栏菜单锚定围栏标题，桌面背景菜单使用当前显示器内最后指针位置，并以工作区左上区域作为回退坐标。单实例命令按照接收顺序执行一次，幂等界面动作聚焦已有界面。
16. Explorer 重启后重新附着并恢复接管；guardian 持续观察用户对 Windows 桌面图标可见性的修改，启动失败、正常退出、`Ctrl+C` 和主进程崩溃均恢复最近一次观察到的用户设置。
17. 不将虚拟桌面身份或生命周期作为工作区分区依据；当前 Windows 10 22H2 平台验证单显示器、多显示器、混合 DPI、锁定与解锁、睡眠与恢复、虚拟桌面和全屏应用。其他 Windows 版本不再作为当前 Milestone 1 的发布阻塞。

guardian 就绪、全部显示器宿主附着、真实像素确认、首份交互命中图确认和单实例命令通道就绪后自动执行桌面接管提交，不等待人工输入探针。当前平台宿主准备失败时保持 Explorer 原始状态并记录错误。

正常运行期间渲染器失效时，宿主保留最后一帧与最后一份交互命中图并执行轻量重启；WebView2 对该目标行为的实际支持程度由当前宿主实现和 Windows 实机验收确认。重启期间的输入行为不扩展为独立恢复状态机。

完整选择模型、键盘交互、Shell 文件操作、剪贴板、OLE 拖放和变化同步由 Milestone 1 正式模块和工单承担。

Milestone 1 保留组件交互契约，当前 Tauri/WebView2 宿主使用官方组件验证透明渲染与交互命中。公开组件与组件 SDK 由 Milestone 3 交付。

当前工作区的布局撤销历史与共享 Shell 操作日志按完成时间组成统一撤销时间线；文本控件获得焦点时处理自身撤销，桌面内容工作区获得焦点时 `Ctrl+Z/Y` 作用于时间线最近一项，重命名提交后形成 Shell 操作记录。

## 性能与工程验证

- 空闲 CPU 目标为 1% 或更低。
- 单显示器工作集目标为 300 MiB 或更低。
- 第二显示器增量工作集目标为 120 MiB 或更低。
- 用户手动执行 60 分钟空闲测试和 30 分钟交互测试，并记录 CPU、工作集和内存趋势。
- AI 验证格式化、类型检查、Rust 测试、渲染器测试和 `tauri build`。
- 当前 Windows 10 22H2 平台维护 Markdown 证据矩阵并附运行日志和截图；用户填写交互、空闲与视觉结果，AI 填写构建和静态验证结果。
