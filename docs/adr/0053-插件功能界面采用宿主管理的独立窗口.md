# 插件功能界面采用宿主管理的独立窗口

## 决策与原因

允许插件从不同呈现位置打开自己的功能窗口。待办的新建和编辑共享一套表单；桌面格子和浮岛不分别维护编辑器。能力以插件窗口而非「打开待办编辑器」为单位：其他插件可用同一路径承载详情或报表，宿主不需要认识任务、报表及其字段。

插件提供本地视图、窗口标识、标题和期望的初始及最小尺寸；宿主提供原生非模态窗口、可用工作区内的尺寸约束、权限校验与生命周期管理。不同插件的同名视图彼此独立。同一插件的同一视图、同一内容重复打开时聚焦原窗，不重建草稿，不重设用户调整的尺寸；不同任务可分别打开。新建草稿有独立于既有任务的身份。

## 能力边界

窗口只挂载已注册且获准的本地插件内容，不接受外部页面地址、文件路径或脚本文本充当窗口内容，不因为开窗增加新的原生命令权限。关闭窗口应清理挂载，停用或卸载插件应回收其窗口。多个入口写入同一任务时，保存表单不能悄悄撤回用户在另一处完成任务的操作。

本决策扩展 [插件外壳](0029-插件来源与范围.md) 的设计范围。可参考[收集项按需窗口](0022-收集项编辑使用按需窗口.md)的复用语义，但插件窗口不采用收集项的文件身份或保存协议。

## 实现状态

这是已确认的架构方向，不是已发布的插件接口。`plugin-window`、`openWindow`、`renderWindow` 是接口草案中的名称；调用载荷、错误协议、能力注册与运行期验证应随实现定稿。
