# 浮岛承载收集箱与天气卡

## 背景

浮岛此前只有音乐控制声明 `island: true`，收集箱与天气仍只能作为工作区格子出现。用户需要把这两项功能也放到浮岛：收集箱要在浮岛直接接收拖入内容，不要求先展开卡片；天气要选择 API 与城市后在浮岛显示。文件夹映射明确不在本次范围。

桌面收集箱的收入规则、类型白名单、编辑窗锁和失败反馈都已经在 Rust 业务层；天气的来源、城市列表、预报缓存与活动调度也已经按来源和城市隔离。浮岛是独立呈现位，不持有工作区布局、不进入撤销，因此不能把桌面格子实例直接搬过去。

## 决策

### 收集箱

- 官方清单 `official.collect-box` 声明 `island: true`；用户在设置页的「浮岛」卡片列表中打开后才进入 `islandCardOrder`，不自动上浮岛。
- 浮岛收集箱卡以呈现和拖放为主：紧凑态改为按活动出现的通知锚点——只在检测到新条目收录时出现完成态、停留 `3s` 后收回，不再常驻显示最新标题（出现条件与生命周期见 [ADR-0045](0045-浮岛通知型锚点与图标语义.md)），展开为 300 DIP 宽的三列列表（最多 50 条），文本与文件行显示标题和摘要，图片项只显示缩略图、不显示名称；展开条目可单击打开，也可按住拖出到系统或其他目标。菜单、选择、删除与排序仍留在桌面收集箱。
- 浮岛窗口在创建时向根窗口与 WebView2 后代窗口注册 Shell 投放目标；只在 `islandCardOrder` 含 `official.collect-box` 时接收。常态、hover 与展开态都接收，不要求展开卡片。
- 投放只协商复制效果，不向源端报告移动；收入复用桌面收集箱的同一业务入口、类型白名单与编辑窗锁。内部收集项只按本进程登记的身份证复制，外部文件映射不删除源文件。
- 收集项拖出复用桌面收集箱的 `prepare_collect_drag` 与 `start_desktop_item_drag`，拖动结束时保留原条目；浮岛不新增第二套系统拖出协议。
- 投放目标注册失败只记录日志，不阻止浮岛显示；卡片仍可由设置关闭。

### 天气

- 官方清单 `official.weather` 声明 `island: true`；浮岛天气卡是单卡，保存来源与城市标识两个普通偏好 `islandWeatherSource`、`islandWeatherCityId`，不写工作区组件状态，也不保存城市对象。
- 设置页的天气卡片二级页提供「天气 API」与「城市或地区」两个选择行；API 只列已配置来源，切换来源清空城市；城市只列该来源已保存的城市。城市增删仍在功能格子的天气页完成。
- 浮岛天气卡的紧凑态改为按活动出现的通知锚点——只在当天摘要真实变化时出现、停留 `3s` 后收回，hover 第二行为城市与今天高低温（出现条件与生命周期见 [ADR-0045](0045-浮岛通知型锚点与图标语义.md)），展开显示当天摘要（当前温度、天气、今天最高最低温、城市与来源）；24 小时与 7 天预报继续由桌面天气格子承载。
- 浮岛天气使用与桌面天气相同的预报事件与活动调度。桌面天气开关关闭时，只要 `islandCardOrder` 含 `official.weather` 仍保持活动；订阅命令接受合成实例 `island.official.weather` 与主屏身份，不伪造工作区实例。
- 来源或城市失效时卡片只显示一句说明，不在浮岛内提供选择控件；修复入口留在设置页。

### 范围边界

- 文件夹映射不声明 `island`，不进入浮岛卡列表，也不注册投放。
- 浮岛仍不持有布局、不参与撤销、不进入工作区快照；收集箱与天气都不新增工作区实例。
- 浮岛不新增设置入口或菜单；所有选择与开关留在设置页。

## 原因与职责边界

收集箱在浮岛的价值是「随手把内容丢到常驻位置」，完整管理仍属于桌面格子；把桌面格子的菜单与多选搬进独立窗口会与浮岛的禁止事项和弹层生命周期冲突。收入规则已经集中在 Rust，浮岛只需要一个投放目标。

天气在浮岛是常驻摘要，不是第二套完整天气格子；复用同一预报事件与活动调度，避免为浮岛单独维护请求、缓存与退避。来源与城市标识放进普通偏好，是因为浮岛没有工作区实例状态，而偏好已经有跨窗口同步与设置页编辑路径。

## 后果

- 官方浮岛卡从一项增加到三项：音乐控制、收集箱、天气；设置页卡片列表自动出现后两项。
- 浮岛窗口多一个 OLE 投放目标生命周期；窗口销毁、外部销毁重建与 OLE 初始化都在平台层收口。
- 天气活动判断从单一 `weatherEnabled` 扩展为「桌面开关或浮岛天气卡启用」，桌面天气行为不变。
- 浮岛收集箱的拖入、拖出、悬停与展开高度需要真机验证；软件单测只能证明收入规则、绑定判定与静态样式。

## 待验证

- 在真实 Explorer 与桌面收集箱之间拖入文本、链接、图片、普通文件和内部收集项，确认浮岛在常态、hover、展开三态都接收，且源文件不被删除。
- 从浮岛展开收集箱把文本、图片、文件映射拖到 Explorer、桌面和其他应用，确认拖出内容与桌面收集箱一致、原条目保留。
- WebView2 后代窗口在导航完成后是否仍由已注册投放目标覆盖；若出现只在空白边缘可投放，需要补子窗口重建后的注册。
- 浮岛天气在桌面天气开关关闭、仅浮岛卡开启时的刷新节奏与暂停行为。
- 天气卡在四边、两种形态和窄宽度下的省略、换行与不撑宽表现。
