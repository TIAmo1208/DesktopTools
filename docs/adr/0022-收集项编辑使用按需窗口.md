# 收集项编辑使用按需窗口

编辑一份收集项时打开独立 `WebviewWindow`（对标设置窗）。同一文件同时只开一扇编辑窗，重复请求显示并聚焦已有窗口，避免并行编辑副本；不同文件可同时打开，不设全局单窗限制。应用内重命名后，已有编辑窗继续关联改名后的文件。窗口关联只保留在当前会话，窗口销毁后再次打开重新读取文件。窗口内使用打包进应用的 Vditor，`mode` 为 `wysiwyg`，工具栏不含 `edit-mode`、`both`、`preview`，并关闭 `cache.enable`。保存写回该收集项的 Markdown 文件后，桌面格子按文件变化重新静态渲染。

设置页提供退出编辑窗是否自动保存：开启则保存并关闭，关闭则询问保存、不保存或取消。

桌面暂停刷新无法约束已挂入桌面宿主的编辑器，因此编辑器放在按需窗口。

Windows 窗口创建与应用内重命名的关联维护在后台线程串行执行。Tauri 命令通过异步入口转交后台任务，原生桌面通道沿用其后台请求线程；主线程不得等待该关联锁，以避免 WebView2 创建窗口时互相等待。此线程边界不代替多窗口显示、聚焦与关闭的实机验收。
