# 插件清单声明创建与移除能力

官方插件的清单新增两个布尔字段，声明该插件是否可由用户创建、是否可由用户移除。字段缺失按 `false` 处理，即默认既不可创建也不可移除；工作区执行创建与移除命令时以清单声明为准，不再按插件身份硬编码可操作范围。

## 已确认决策

创建与移除的允许范围由插件清单声明，`CreateComponent` 与 `RemoveComponent` 只校验目标插件是否声明了对应能力。创建沿用统一入口：选择目标显示器、计算工作区可用位置、使用默认尺寸、分配未占用的实例标识并保留旧身份的外观记录，最后发布工作区快照并纳入布局撤销；移除沿用原子保存、快照发布与撤销重做，不接触插件自身的数据。

收集箱与天气格子声明可创建、可移除；本地时间与音乐控制此次不声明这两项能力，继续只有默认实例。声明缺失或为 `false` 时，命令以“不支持创建该组件”或“不支持移除该组件”失败，不因插件存在默认实例而放行。

## 原因与职责边界

可创建、可移除的官方插件已出现第二个。按插件身份在创建与移除两处各写一份判断，会在每新增一个可创建插件时重复一次，并且插件身份同时出现在清单、注册表和命令校验三个位置，容易漏改。把能力声明放进已有的版本化清单，使“能不能创建”成为插件自己的事实，命令层不需要知道具体有哪些插件。

本决策不引入通用插件系统；插件来源与外壳接入另由 [ADR-0029](0029-插件来源与范围.md) 定义。本决策不允许清单声明任意入口，也不扩大能力授权范围：清单的身份、入口与能力声明仍由注册表校验，创建与移除只读取新增的两个布尔字段。

天气格子与收集箱共用创建入口后，两者的默认尺寸、初始状态与绑定信息仍由各自入口决定，不在公共流程内特判插件身份。功能开关只控制实例显示，不阻止创建，重新打开功能后可见已创建的格子。

## 待验证假设

- 插件清单字段缺失时按 `false` 处理，未同步声明新字段的既有清单会失去创建与移除能力；正式注册表内的官方清单需在同一批改动内补齐声明，尚未在发布构建中验证遗漏声明的实际表现。
- 可移除插件增加后，用户自行移除默认天气实例的桌面焦点恢复、快捷键行为与撤销重做表现尚未经真实环境验证。
