# 插件自带字体与字体列表

## 背景

主题需要宋体这类界面字体，但 `APPLICATION_FONTS` 只有六个系统字体，用户机器上不一定装得齐；把宋体名写进 `theme.json` 也只能碰运气。此前插件协议只放行 `.js` 与 `.css`，CSP 是 `default-src 'self'`，字体文件既读不出来、也不能走 `data:`。

决策目标是：字体随插件包一起安装，能在「设置 → 外观」的字体列表里直接选，切主题时跟着主题走；字体缺字时逐字符回退到系统字体，不回退整段文字。

## 决策

### 声明

字体只由主题插件的 `theme.json` 声明，写在 `fonts` 数组里，每项含 `family`、`file`，可选 `weight`、`style`。样式表不写 `@font-face`：字体必须经过清单校验才能进入页面，绕过校验的第二条注入路径不保留。

### 校验与边界

- `file` 只能指向插件文件夹内的 `.woff2`、`.woff`、`.ttf`、`.otf`，按与样式表相同的路径规则拒绝绝对路径、`..`、链接和重解析点。
- 单个文件上限 `16 MiB`，单个主题最多 `4` 项。超限或任一项非法时主题注册失败，与其他主题数据错误同一处理路径。
- 字体族名只做字形名格式校验，禁止 `;{}()'"\` 与控制字符；偏好、基线、主题外观三处使用同一条规则，不各自维护名单。
- 协议层只新增字体扩展名的 MIME 映射，CSP 不改：页面与 `/plugins/` 同源，`default-src 'self'` 已覆盖字体请求。

### 注入与列表

- 宿主在运行时把每个已注册主题的字体项用 `FontFace` 注册进 `document.fonts`，地址带版本参数；加载失败静默，不打断主题挂载。
- 外观页字体列表 = 系统名单 + 当前已注册主题字体，同名只保留一项；字体项来自运行时快照，不读插件目录。
- `--interface-font` 写成选中字体族加内置回退栈（`Segoe UI Variable`、`Segoe UI`、`sans-serif`）；缺字由浏览器逐字符回退，回退结果不写回偏好。
- 主题自带字体不进入外观基线：切换、停用或卸载主题时随主题一起撤下，字体回到用户原有值；旧版本留下的、以主题字体为值的基线在还原时按默认字体处理。

### 主题切换

主题的 `appearance.fontFamily` 可以指向自己声明的字体族；选中主题时随其他外观项一起写入偏好，切回内置主题时按基线还原。字体偏好为字符串，卸载主题后残留的字体名按不存在的字体处理，只影响显示。

## 后果

- 安装包和插件包体积由作者负责；字体许可也由作者负责，插件索引与仓库 README 要求注明来源与许可。
- 字体文件缺失时没有用户可见错误：字形回退到系统字体，需要作者在发布前自查。
- 子集化字体缺字时表现为同一行内字形混排，这是逐字符回退的预期代价，不是缺陷。
- 字体列表随运行时快照变化，插件停用或卸载后立即消失，不需要单独清理偏好。
