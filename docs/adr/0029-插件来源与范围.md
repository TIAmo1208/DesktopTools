# 插件来源与范围

## 背景

官方能力已通过版本化清单、注册表和现有宿主能力运行。新增本地插件来源时，需要明确“可接入的扩展单元”和“桌面上的功能呈现”不是同一概念：前者称为插件，后者继续称为组件或格子；React 组件也保留原称。接口、类型、命令和持久化字段保留现有技术标识。

本期授权的是“声明式清单 + 外壳接入”，不是第三方插件平台。创建与移除仍由 [ADR-0027](0027-插件清单声明创建与移除能力.md) 的清单声明决定；本决策补充来源、作者代码送达和宿主责任边界。

## 决策

### 作者受信，外壳归宿主

插件代码在宿主页面内执行，与宿主共享页面和 JavaScript 执行环境，不具有独立进程、iframe 或沙箱隔离。安装插件即信任其作者；清单能力校验不构成对页内代码的安全隔离，也不保证插件无法访问页面已有的桥接对象。

插件自带格子内容与设置条目内容，呈现形式、内容正确性、定时器、订阅和资源开销由作者负责。宿主不限制、不管理、不保证插件内容，只承诺可选外壳契约：桌面格子外框及其既有几何、命中、折叠与状态接入，以及软件设置界面的新增条目接入。宿主不以固定内容模板替代作者内容。

可用性仍属宿主责任：格子内容抛错由该格子的错误边界收敛，设置条目内容抛错由对应条目的错误边界收敛；作者代码死循环可能冻结所在屏幕的整个页面，接受这一代价，由现有心跳超时机制重载该屏。错误边界不承诺捕获死循环，宿主既有暂停、恢复、接管与布局撤销路径不交给插件接管。

### 来源与启动快照

插件目录独立于配置目录，由用户偏好解析；偏好为空时使用 `%APPDATA%\TIAmo\plugins`，不跟随配置目录自动迁移。当用户在设置中修改插件目录时，在下一次程序启动时触发整目录迁移，并在本次运行内冻结，解析优先级、基线建立与迁移安全规则见 [ADR-0033](0033-插件目录随设置迁移.md)。预设插件随安装包的交付与版本处理见 [ADR-0032](0032-预设插件随安装包交付.md)。一个插件是插件根下一层子文件夹，文件夹名等于 `manifest.ini` 的 `name`。宿主只读该文件，不扫描其余资源。`manifest.ini` 为 UTF-8，只认 `[plugin]` 节：`id` 由宿主安装时写入，`name`、`version`、`entry` 必填；`minAppVersion`、`maxAppVersion`、`author`、`description`、`repository` 可空。`version` 与两个版本边界都必须是三段数字，边界文本无效时整份清单不注册；`author`、`description` 缺省为空串，`description` 的换行写成 `\n`；`repository` 只保留 `http`/`https`，其他值记 WARN 后视同未声明。单份清单上限为 64 KiB，超限整份拒绝；目录不存在视为无本地插件。插件根上的扁平 json 不再识别。

启动时先注册内置官方清单，再读取插件文件夹；重复标识保留先注册项，本地来源不得覆盖官方。目录读取、清单读取、解析或校验失败只加入运行时 `failures`，不使应用启动失败，也不影响其余合法清单与官方插件。声明集在启动时读取；安装或卸载成功后按插件根重扫并广播运行时清单，不经这两条命令的文件变化仍须重启程序后生效。入口模块按同源地址缓存，导入后不热替换。

### 身份、入口与能力

官方入口只允许与其配套的官方标识组合。本地插件的 `id` 必须带 `plugin.` 前缀，其余字符限于小写 ASCII 字母、数字、`.` 与 `-`，长度不超过 128。清单上的 `entry` 是文件夹内的脚本相对路径，运行时把它算成插件根相对路径写入 `script`（`<文件夹>/<entry>`）。前端分派键仍是固定的 `plugin:slot`，不把脚本路径写进 `entry`。`entry` 拒绝绝对路径、`..`、链接和重解析点，且必须以 `.js` 结尾；入口文件暂时不存在时只记 WARN，清单照常注册，加载失败交给前端。`version` 必须是三段数字。`name` 必须能作为文件夹名：禁止 `\ / : * ? " < > |` 与控制字符，最长 80。`minAppVersion` / `maxAppVersion` 与当前程序版本比较，不满足则不注册并写入 `failures`。

插件当前没有宿主能力通道：`manifest.ini` 不含能力键，运行时把插件清单的能力声明按空集注册，插件拿不到 `ReadHostTime`、`ReadCurrentMedia` 等宿主能力。需要时再引入 ini 键与对应 API。`creatable` 与 `removable` 从 `manifest.ini` 读取，接受 `1`/`0` 和 `true`/`false`。缺省 `creatable` 为 false，缺省 `removable` 为 true。空串和其他值记警告后按缺省，不拒绝注册。官方 JSON 清单仍按字段缺省 false，不因插件 ini 的缺省而改变。`maxTiles` 是格子数量上限：缺省或 `0` 表示不限；负数、非数字或超出 `u32` 的值按不限处理并记警告，不拒绝注册。创建时统计所有显示器上该 `componentId` 的实例总数，达到上限则拒绝。

持久化标识符沿用 `component` 命名：包括 `componentId` 字段和实例外观键 `component:<instanceId>`，不改名、不迁移，以免既有布局与外观失效；源码接口、类型与命令名不因中文术语调整而改名。

### 运行时代码送达

代码送达方式已确定为同源动态 `import("/plugins/<script>")`，模块默认导出外壳对象，宿主按清单 id 绑定，脚本不写注册键。多个插件共享 `plugin:slot`，模块加载与外壳绑定按插件标识区分，不能按槽入口把不同插件合并为一次加载。

资产路由只提供 `.js` 与 `.css`，解析后的真实路径必须仍位于插件目录内，并拒绝符号链接与重解析点。沿用既有 `script-src 'self'`，不放开 `unsafe-inline` 或 `unsafe-eval`；插件不得依赖 `eval` 或内联脚本。不把作者代码拼入宿主初始化桥接脚本，也不通过宿主级脚本执行通道绕过 CSP。

### 外壳 API 契约

插件入口模块默认导出外壳对象。`renderTile(container, context)` 可选，可以返回清理函数。`settingsEntries` 可选，没有该字段表示没有设置条目。每个条目是 `{ id, name, render(container, context) }`：`id` 在该插件内唯一，`name` 是行标题，`render` 可以返回清理函数。`context` 为 `{ pluginId, instanceId, collapsed, settings, saveSettings }`。宿主只提供空的 `container`，不规定其中的 DOM 与样式。格子渲染只调用 `renderTile`。

宿主 `import` 入口模块后，取 `default`；没有 `default` 时用模块对象本身。导出不是对象时加载失败，原因是「插件模块没有默认导出」或「插件导出不是对象」。绑定键是清单 id，不是脚本里写的字符串。同一 id 只绑定一次，模块被缓存时复用已绑定对象。此前把外壳对象赋给 `window.__DESKTOP_TOOLS_PLUGINS__[pluginId]` 的方式作废；该契约未发布，不做兼容。

`settingsEntries` 不是数组时整组丢弃并记 WARN，不因此丢掉 `renderTile`。条目缺少 `id` 或 `name`，或 `id` 在该插件内重复时，丢弃该条并记 WARN。

设置窗口与桌面逐屏都用同源动态 `import` 加载同一份入口模块，不插入 `<script>`。同一插件标识只绑定一次。加载失败记下错误并可再查询，不自动重试。停用名单包含该标识时不加载，从名单移除后才按需加载。加载成功后通知当前订阅，订阅必须退订。

`settings` 来自 `get_plugin_settings`，没有文件时为 `null`。读取失败时记 WARN，并以 `null` 调用 `renderTile`，不把格子切到错误态。`saveSettings` 调用 `save_plugin_settings`。保存成功后的 `plugin-settings-changed` 只携带插件 id。逐屏页面通过既有事件转发白名单收到该事件，然后重新读取；先调用该实例上一轮 `renderTile` 返回的清理函数，再以新的 settings 调用 `renderTile`。同一次读取只采纳最后返回的结果。折叠变化使用已经读到的 settings，不再等待命令。

暂停的屏幕不转发该事件。恢复时跟随既有 `desktop-refresh-changed` 重新读取并调用 `renderTile`。

同一插件的多个实例共用一份注册对象，以 `instanceId` 区分。实例离开当前屏幕时，调用该实例最近一次 `renderTile` 返回的清理函数。

重复绑定保留首份并记 WARN。已绑定但缺少 `renderTile`，或脚本加载失败，格子显示既有错误态「组件渲染失败」。

脚本只在运行时快照存在对应 `plugin.` 清单、且当前屏幕已有该插件实例时，以同源动态 `import` 加载。地址由清单里的插件根相对路径拼成 `/plugins/` 开头的路径。按插件标识去重，同一标识只加载一次，加载失败不重试。停用的不加载。

### 安装

安装先给出计划，不落盘。来源可以是文件夹，也可以是 zip。清单在来源根上，或只在下一层。宿主生成 `plugin.` 加名称的 ASCII slug（名称没有 ASCII 字母数字时用固定词干 `item`），冲突时从 2 起加数字后缀，并写回 `manifest.ini`；同一名称再次安装沿用原来的 id。入口脚本不存在时只记 WARN，仍完成安装。升级和同版本直接覆盖文件夹。降级必须确认后才先卸载旧版（移除实例、删除文件夹、保留配置）再安装。文件先进入插件根下的临时目录，成功后再改成目标文件夹；失败或取消会删掉临时目录。zip 拒绝绝对路径、`..` 和链接条目，单文件超过 64 MiB、总体积超过 256 MiB 或条目超过 2000 时中止。进度事件是 `plugin-install-progress`。解压使用 `zip` 依赖。

### 卸载即移除实例与布局

`uninstall_plugin` 删除当前插件目录中该插件的整个文件夹，并当场移除该插件在所有显示器上的工作区实例。实例包围盒、`tileAppearances` 里 `component:<instanceId>` 的键，以及指向这些实例的焦点一并清掉。`remove_settings` 为假时保留该插件的设置（配置目录 `settings-plugins.json` 中以 `作者@插件ID` 对应的键），重装后设置仍可恢复。为真时从该文件删除这一条键，文件因此为空时删除文件。清理配置不可恢复。

这是宿主发起的清理，不经过用户「移除格子」的 `removable` 声明门禁，也不改变该门禁的判定和错误文案。卸载清理不进入布局撤销历史，已有撤销和重做记录里的同名实例也一并去掉。撤销若能把格子恢复回来，恢复出来的实例会指向已经删除的插件。

顺序是先校验全部文件，再保存工作区，最后删除文件。文件校验失败时工作区和文件都不变。工作区保存失败时文件仍在。删除文件中途失败时实例已经不在，再次调用会补删剩余文件，不把格子留在桌面上。

失效插件只用于外部原因：清单被外部删除或加载失败，使已经存在的格子不能继续使用。正常卸载不走这条路径。卸载成功后重扫插件根并广播运行时清单，设置页不必等重启就不再列出该插件。

文件不存在不算失败，返回值只列出实际删除的文件名。清单和脚本必须是插件根内的普通文件，设置文件必须是配置目录内的普通文件。拒绝目录穿越、链接和重解析点。任一目标未通过校验就不删除其余目标，也不改工作区。不删除其他插件，也不删除这两个目录以外的文件。

`open_plugin_directory` 在资源管理器中选中该插件的清单文件。打开方式沿用现有 `ShellExecuteW`，不另写进程启动封装。清单不存在时不改为打开目录。

插件实例的创建入口在设置页。`create_plugin_component` 只接受当前清单里存在、`entry` 为 `plugin:slot` 且 `creatable` 为 true 的插件；位置沿用主显示器上的默认格子尺寸和既有创建事务。

## 后果

- 复用既有注册、能力与格子流程，不为每个插件新增分派分支；宿主只需维护外壳契约，作者内容不属于宿主内容保证。
- 作者受信不免除来源校验、资产路径限制和宿主可用性责任；页内执行意味着单个插件可影响同屏其他内容，心跳重载不是安全隔离。
- 清单随安装或卸载刷新，其余文件变化与脚本替换仍须重启程序，代价是修改插件文件不能即时生效。

## 未决项与范围之外

- 同源动态 `import` 已确定，不再作为待选代码送达方案。开发页面来自不同 origin 时的模块加载与 CSP 适配仍须单独核实，不据发布同源方案推断开发模式已经可用。
- 本期不建设沙箱策略、公开插件 SDK 打包、第三方插件分发、能力市场或通用插件平台；未来若要承载不受信作者，必须另行决定隔离与授权模型。
