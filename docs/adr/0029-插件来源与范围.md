# 插件来源与范围

## 背景

官方能力已通过版本化清单、注册表和现有宿主能力运行。新增本地插件来源时，需要明确“可接入的扩展单元”和“桌面上的功能呈现”不是同一概念：前者称为插件，后者继续称为组件或格子；React 组件也保留原称。接口、类型、命令和持久化字段保留现有技术标识。

本期授权的是“声明式清单 + 外壳接入”，不是第三方插件平台。创建与移除仍由 [ADR-0027](0027-插件清单声明创建与移除能力.md) 的清单声明决定；本决策补充来源、作者代码送达和宿主责任边界。

## 决策

### 作者受信，外壳归宿主

插件代码在宿主页面内执行，与宿主共享页面和 JavaScript 执行环境，不具有独立进程、iframe 或沙箱隔离。安装插件即信任其作者；清单能力校验不构成对页内代码的安全隔离，也不保证插件无法访问页面已有的桥接对象。

插件自带格子内容与设置条目内容，呈现形式、内容正确性、定时器、订阅和资源开销由作者负责。宿主不限制、不管理、不保证插件内容，只承诺可选外壳契约：桌面格子外框及其既有几何、命中、折叠与状态接入，以及软件设置界面的新增条目接入。宿主不以固定内容模板替代作者内容。

可用性仍属宿主责任：格子内容抛错由该格子的错误边界收敛，设置条目内容抛错由对应条目的错误边界收敛；作者代码死循环可能冻结所在屏幕的整个页面，接受这一代价，由现有心跳超时机制重载该屏。错误边界不承诺捕获死循环，宿主既有暂停、恢复、接管与布局撤销路径不交给插件接管。

### 来源与启动快照

插件目录独立于配置目录，由用户偏好解析；偏好为空时取当前生效配置目录的同级 `plugin/`，配置目录使用默认值时即 `%APPDATA%\TIAmo\plugin`。解析结果在启动时冻结，本次运行内不再变化，改动需重启生效；插件目录不随配置目录迁移。清单和脚本均位于插件目录，一插件一份与插件标识同名的 `.json` 清单和 `.js` 脚本。单份清单上限为 64 KiB，超限整份拒绝；目录不存在视为无本地插件。

启动时先注册内置官方清单，再读取插件目录中的清单；重复标识保留先注册项，本地来源不得覆盖官方。目录读取、清单读取、解析或校验失败只加入运行时 `failures`，不使应用启动失败，也不影响其余合法清单与官方插件。声明集在启动时冻结，不做清单或脚本热加载；文件变化须重启程序后生效。

### 身份、入口与能力

官方入口只允许与其配套的官方标识组合，本地插件使用 `plugin.` 前缀标识和唯一槽入口 `plugin:slot`。入口按精确白名单校验，不接受任意路径或 URL，也不允许本地插件冒用官方入口。

插件槽的能力声明只允许现有 `ReadHostTime`、`ReadCurrentMedia` 两项中的单元素集合，即二选一，不允许同时声明两项或引入新能力。创建与移除继续读取独立的 `creatable`、`removable` 布尔声明，不因接入插件来源而自动放行。

持久化标识符沿用 `component` 命名：包括 `componentId` 字段和实例外观键 `component:<instanceId>`，不改名、不迁移，以免既有布局与外观失效；源码接口、类型与命令名不因中文术语调整而改名。

### 运行时代码送达

代码送达方式已确定为运行时创建 `<script src>`，从插件目录对应的同源 `/plugins/` 资产路由加载，再由插件按自身标识向宿主提供的页内全局注册格子内容与设置条目。多个插件共享 `plugin:slot`，脚本加载与内容注册按插件标识区分，不能按槽入口把不同插件合并为一次加载。

资产路由只提供 `.js` 与 `.css`，解析后的真实路径必须仍位于插件目录内，并拒绝符号链接与重解析点。沿用既有 `script-src 'self'`，不放开 `unsafe-inline` 或 `unsafe-eval`；插件不得依赖 `eval` 或内联脚本。不把作者代码拼入宿主初始化桥接脚本，也不通过宿主级脚本执行通道绕过 CSP。

## 后果

- 复用既有注册、能力与格子流程，不为每个插件新增分派分支；宿主只需维护外壳契约，作者内容不属于宿主内容保证。
- 作者受信不免除来源校验、资产路径限制和宿主可用性责任；页内执行意味着单个插件可影响同屏其他内容，心跳重载不是安全隔离。
- 清单和脚本仅在启动周期内使用，简化生命周期，代价是修改插件文件不能即时生效。

## 未决项与范围之外

- 运行时注入 `<script>` 已确定，不再作为待选代码送达方案。开发页面来自不同 origin 时的脚本加载与 CSP 适配仍须单独核实，不据发布同源方案推断开发模式已经可用。
- 本期不建设沙箱策略、公开插件 SDK 打包、第三方插件分发、能力市场或通用插件平台；未来若要承载不受信作者，必须另行决定隔离与授权模型。
