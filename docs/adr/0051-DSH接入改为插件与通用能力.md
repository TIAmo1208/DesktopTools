# DSH 接入改为插件与通用能力

## 背景

上一版把 DSH 接入做成了原生领域（`src-tauri/src/dsh/`）+ 官方浮岛卡 + 设置页。用户明确：连接 DSH 属于插件范围，DSH 相关内容应放进插件目录，按插件方式开发，运行时提供可复用的接口与能力。

同时确认：插件只拿脱敏 DTO；配对令牌存 Windows 凭据管理器，插件不拿明文；现有原生 DSH 界面全部迁走。

## 决策

### 归属

DSH 接入由 `plugin/DSH 接入/` 插件承载：清单声明 `island = 1`、`creatable = 0`，不占桌面格子。连接、配对、轮询、卡片与提醒都在插件内；运行时不再有 DSH 专属领域、命令、官方卡或设置页。

### 运行时补齐的通用能力

不新增 DSH 专属能力，只补可被任意插件复用的通用接口：

| 能力 | 用途 | 载荷 |
| --- | --- | --- |
| `loopback-channel` | 本机 HTTP 通道，本轮对浮岛实例开放 | 沿用注册、读取、请求三条命令 |
| `plugin-credential` | 插件在自有命名空间写入或清除凭据，永不回读明文 | `{ action: "set" | "clear", slot, value? }` |
| `plugin-credential-exchange` | 宿主代发一次本机 JSON 请求，把响应中指定字段写进插件凭据槽，响应不回页面 | `{ slot, url, body, extract }` |
| `publish-island-message` | 向浮岛消息锚点投递一条本地条目，不弹原生 Toast | `{ key, kind, text }` |
| `open-uri` | 打开协议白名单内的 URI | `{ uri }`，仅接受 `dsh:` 与 `https:` |

插件清单的 `required_capabilities` 取消「只能声明一个」的限制，允许声明集合；未知能力、重复能力仍让清单加载失败。

### 信任边界

插件脚本与宿主页面同源加载，运行时**不提供插件之间的隔离**：同页插件可以调用同一份命令面。实例查册只保证「这个实例存在且声明了该能力」，不证明调用来自哪个插件。

这条边界由用户明确批准：本轮按「同页作者皆受信」部署，不声称能防御同页恶意插件或同用户已攻陷的进程。需要真正的隔离时，必须先把插件移入独立执行环境（独立 WebView 或进程），再谈跨插件能力隔离。

### 凭据

插件凭据落在 `DesktopTools/plugin/<pluginId>/<slot>`。命名空间识别按 Windows 语义大小写不敏感；`plugin-credential` 只写不读；`loopback-channel` 的 `credentialRef` 只接受插件自己的命名空间或明确保留的 `DesktopTools/astrbot-status`，其余目标一律拒绝。通道注册可声明凭证前缀（只允许 `Bearer `），宿主注入时拼接，凭据本身存原始秘密。

配对令牌不回到页面：插件用 `plugin-credential-exchange` 让宿主直接完成 `POST /pair` 并把 `token` 写进凭据槽，命令只返回是否落槽。

### 删除

删除 `src-tauri/src/dsh/`、`commands/dsh.rs`、`contracts/dsh.rs`、`official.dsh` 清单与注册、设置页「DSH 接入」、浮岛原生 DSH 卡与相关事件；`DesktopTools/dsh-bridge` 保留目标随之移除。

### 提醒

插件调用 `publish-island-message`；运行时发出 `island-plugin-message` 事件，浮岛页把条目并入既有消息锚点，按 `key` 去重，不新建队列、不弹 Toast。

## 后果

- 浮岛页面未运行（关闭浮岛、锁屏、全屏隐藏）时没有轮询与提醒；这是插件路线的取舍，不再有原生后台常驻。
- 插件的轮询节奏、状态机、提醒去重都由插件自身维护，运行时只提供传输与投递。
- 插件可声明多个能力，ADR-0038 的单能力约束在本轮被放宽，需要同步更新其正文。

## 待验证

- 浮岛隐藏/锁屏时插件定时器的实际暂停行为。
- 插件设置项里的配对流程与错误显示。
- 真实 DSH 桥与插件的端到端配对。
