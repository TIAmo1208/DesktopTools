# 分阶段集成 Windows 桌面右键菜单

Milestone 1 分开实现桌面背景菜单与项目 Shell 菜单。Desktop Tools 接收桌面空白区域的右键输入，通过 Shell 操作代理显示原生桌面背景菜单，并追加产品操作；项目菜单通过完整 Shell 菜单接口显示选中项目的真实菜单，并追加加入围栏、移出围栏和编辑布局等产品操作。右键已选项目时保留当前选择集合并以全部选中项目构建多选菜单；右键其他项目时将目标设为唯一选择并构建单项菜单。产品命令使用全部选中项目的共同能力集合，命令覆盖整个选择集合时启用并提交为一个布局事务。菜单键或 `Shift+F10` 打开的项目菜单锚定焦点项目，围栏菜单锚定标题，桌面背景菜单使用当前显示器内最后指针位置，并以工作区左上区域作为回退坐标。项目菜单使用专用原生 owner HWND，转发 owner-drawn 菜单、动态子菜单和菜单字符消息。Milestone 1 锁定 x64 主程序与 x64 Shell 扩展；x86 Shell 扩展进入后续兼容范围，Windows 11 现代菜单进入后续发行阶段。

桌面背景中的 Desktop Tools 菜单按主进程状态维护两套当前用户注册表内容：进程未运行时在一级菜单直接提供“打开程序”，不保留空级联菜单；正常运行并完成 `install()` 后，在 Desktop Tools 二级菜单提供“新建围栏”“新建文件夹映射”“添加天气”“添加收集箱”“打开软件设置”和“退出整理”。产品一级入口前后设置分隔线，使其作为独立菜单组。父菜单与打开程序使用程序图标，各功能动作使用对应的 Lucide 图标；SVG 随程序嵌入，注册时利用已有 SVG 渲染器生成并缓存 Windows 可读取的 ICO，退出后仍可读取图标。动作通过固定 `--desktop-menu` 参数转发到已有主实例；“添加天气”与“添加收集箱”一样只携带固定动词，不携带位置、来源或城市参数，格子位置与初始状态由统一创建入口决定；“退出整理”复用正常退出恢复流程。正常退出时先回退为一级“打开程序”，再销毁菜单接收窗口；回退失败只记录错误，不阻止已有退出恢复。更新仅替换产品自己的注册表键，清除前一状态的 `shell`、`command` 和 `SubCommands`，避免一级与二级配置混用。注册表更新后调用 `SHChangeNotify(SHCNE_ASSOCCHANGED)` 请求 Explorer 重新读取菜单；Explorer 对图标、分隔线及层级的缓存表现尚未经真实环境验证。进程异常终止时不保证立即回退，下一次启动或显式注册流程负责纠正菜单状态。COM `IContextMenu`/`IExplorerCommand` 动态处理器不属于本阶段范围。
