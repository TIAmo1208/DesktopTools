# 预设插件随安装包交付

## 背景

本地插件已通过清单、入口脚本及设置项能力建立基本规范。为了降低上手门槛并提供功能参考，仓库根目录提供了预设插件示例（位于 `plugin/`）。这些预设插件需要在用户安装 Desktop Tools 时自动送达至用户环境，并在卸载时提供受控清理机制。

## 决策

### 1. 源码位置与打包资源携带

- 预设插件源码固定存放于仓库根目录的 `plugin/` 下。
- 安装包打包配置 `src-tauri/tauri.installer.conf.json` 中，通过 `bundle.resources` 将 `../plugin/` 映射为安装包内部资源目录 `plugin/`（开发构建 `tauri.conf.json` 不携带）。

### 2. 当前生效插件目录定位与写入

安装程序在安装生命周期的 `POSTINSTALL` 阶段，通过调用桌面主程序的无 GUI 命令行子命令写入预设插件：
- **目录定位**：采用「当前生效插件目录」原则（`plugin-location.json` 指针优先，指针缺失时按配置偏好解析，偏好为空时回退至默认 `%APPDATA%\TIAmo\plugins`）。若用户此前在应用内修改了插件目录偏好但尚未重启，安装器仍向当前生效的旧目录写入，待下次启动时统一执行目录迁移。
- **覆盖规则**：
  - 若目标目录中尚无同名插件，完整复制并写入；
  - 若目标目录已存在同名插件且版本相同，**跳过复制**，以保留用户可能进行的本地自改或调试；
  - 若版本不同（更新或升级），则执行整目录替换。
- **写入安全**：先在临时目录写入，校验完毕后原子替换，严禁出现半包残留；严格拒绝符号链接、重解析点与路径穿越；不修改、不删除目标目录内用户自行安装的其他插件。

### 3. 卸载确认与受控清理

- **卸载页复选框**：在 NSIS 卸载确认页（`installer/installer.nsi`）中，在“删除应用数据”下方新增「同时移除随程序安装的预设插件」复选框，**默认不勾选**。
- **受控模板修改**：此复选框及相关页面逻辑属于对 Tauri CLI 模板（`tauri-cli-v2.11.4`）的受控修改，已在 [ADR-0024](0024-采用当前用户NSIS安装包.md) 登记，升级 CLI 后须对照回放。
- **卸载调用与保护**：
  - 仅在用户主动勾选该项且非覆盖更新模式（`$UpdateMode <> 1`）时，调用程序的无 GUI 卸载预设命令；
  - 静默卸载（silent uninstall）与安装更新时不清理预设插件；
  - 卸载时严格按照安装包内随附的预设插件清单 `id` 逐一精确匹配目标目录中的插件文件夹并删除，绝不影响用户自建或安装的其他第三方插件；
  - 即使移除了预设插件文件夹，已保存在 `settings-plugins.json` 中的插件自定义配置仍予以保留（不触碰配置清理）。

## 结果与影响

- 预设插件可以在首次安装及升级时无缝交付给用户，无需手动解压或导入。
- 同版本跳过规则保护了用户的本地二次开发；卸载默认不勾选项避免了误删插件资产。
- 预设插件的安装与卸载逻辑收敛在主程序的 CLI 子命令中，NSIS 脚本仅充当调度方，保持了领域校验规则与文件操作权限在 Rust 后端的一致性。
