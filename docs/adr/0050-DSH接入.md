# DSH 接入：窄桥、原生适配与仅岛提醒

> 本决策已被 [ADR-0051](0051-DSH接入改为插件与通用能力.md) 取代：DSH 接入改为插件承载，运行时不保留 DSH 专属领域与官方卡。

## 背景

用户要在 DesktopTools 内看到 DSH 的账户余额、任务进度与消息提醒，并在需要处理时一键切回 DSH。

调研结论：

- 已开的 DSH Desktop 宿主用 `127.0.0.1 --port 0`，端口每次启动不同；启动凭据（launch token）只存在于内存、stdout 与父子进程 IPC，不落盘。Electron 的私有转发只给受信主窗口注入 Cookie，不向外部程序发放配对凭据。
- DSH 的 Remote API 先要 `/connect?token=…` 换取签名 Cookie，之后才有 HTTP 与 WS；没有该凭据一律返回 401。
- DSH 的审批是宿主 Cordis waterfall：前置监听器不调用 `next()` 即认领，认领后内置 UI 看不到该请求。DSH 不提供跨 UI 的共同仲裁入口，也没有 pending 注册表与 answerer 列表。
- 因此 DesktopTools 一旦认领审批，会屏蔽 DSH 原生审批卡。这是用户明确拒绝的行为。

## 决策

### 架构

采用 DSH Host 窄桥插件 + DesktopTools 原生 Rust 适配层 + 官方浮岛卡 + 既有统一消息锚点。不新增桌面格子、不扩插件能力枚举、不建第二通知队列。

DesktopTools 侧不是 loopback 插件：浮岛卡实例 `island.<pluginId>` 由运行时合成、不写工作区，`register_loopback_channel` 只认工作区实例，浮岛卡拿不到通道。桥的连接与凭据由原生 Rust 持有，浮岛卡只读渲染。

### 桥只读

桥只读钱包、会话、job、任务板与待决摘要；订阅会话事件与 `approval/asked` 用于产生提醒，但不认领 `approval/request`，不做代批，不调用任何写方法。所有裁决仍在 DSH 完成。

### 提醒只在浮岛

提醒进入既有浮岛消息锚点，不调用 `publish_message_notification`，避免入原生 Toast 队列；点击提醒切回 DSH 处理。待决项只展示，不提供批准入口。

### 配对

一次手工复制短时配对码。配对码只在 DSH 同源、要求 owner 已认证的配对页显示，不写 Host 日志；页面同时提供轮换与撤销。桥侧只保存哈希，DesktopTools 侧存 Windows Credential Manager，插件与浮岛卡拿不到明文。因为不存在写操作，不区分读写权限。

### 数据面

桥自建监听固定绑 `127.0.0.1:47832`，端口占用即明确失败，不做端口发现。请求带 `Authorization: Bearer <token>`；桥校验精确 `Host`，`/pair` 只接受 JSON。

桥有两层身份：`bridgeId` 首次生成后持久化，用于把已配对令牌绑定到同一桥；`bridgeInstanceId` 每次启动变化，用于作废旧快照。DesktopTools 在配对前先读 `/health`，只接受同一 `bridgeId` 的配对结果；改基址会清空令牌并要求重新配对。

快照携带 `revision`、`fetchedAt`、`stale`，页面按 `revision` 去重、恢复时无条件重读；余额、会话、job、待决任一变化都推进 `revision`。失败、未登录、未授权一律显示对应状态，不显示为 0。不读取 DSH 状态文件、数据库或浏览器 Cookie 代替授权。

### 版本与降级

协议版本 + `bridgeInstanceId` + 桥代际。不兼容时收起入口并显示未连接；DSH 升级、插件被禁用、桥不可达时保留陈旧快照并标注时间，不自动补写。

### 跳转

点击提醒调用 `dsh://open` 打开并抬升 DSH。当前安装版只处理通用打开、不读取会话参数，因此 DesktopTools 不声称已定位会话：命令返回 `{ opened, located }`，`located:false` 时界面如实显示「已打开 DSH，请在 DSH 中处理」。深链不可用时只保留只读提示，不新开替代窗口。

### 能力范围

首版交付余额、会话与 job 状态、待决摘要与提醒；不实现 AgentTeams 任务板投影，任务进度以会话与 job 状态表达。

## 后果

- 余额要求 DSH 账号已登录且平台授权有效；只有模型 API Key 不足以保证有值。
- 通知是尽力而为：没有可靠推送与重放，靠快照与失效重读补偿。
- 快照事件沿用既有宿主事件广播，未按窗口收窄；载荷不含凭据，但含余额与会话标题，接受为受信同机部署的已知边界。
- 不做代批意味着用户必须在 DSH 内完成审批；DesktopTools 只负责把人叫回来。
- 不改 ADR-0038 的插件通道合同，不扩 `ComponentCapability`，不放宽页面 CSP。

## 待验证

- 桥插件在 `desktop` profile 的安装方式与 DSH 升级后的兼容性；本机实装版是否注册了 `dsh://open` 协议。
- 浮岛卡点击后 DSH 抬窗在锁屏、全屏隐藏、无卡时的实际表现。
- 配对页在 DSH 同源页面下的 owner 认证行为，以及撤销后旧令牌立即失效。
