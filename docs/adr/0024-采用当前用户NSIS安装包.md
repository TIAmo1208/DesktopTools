# 采用当前用户 NSIS 安装包

## 决策与原因

Windows x64 测试安装包采用 Tauri 自带的 NSIS 打包路径和标准安装界面，以当前用户身份安装，与现有 HKCU 桌面菜单和用户配置边界一致。复用现有图标，不引入 MSI、全用户安装、自动更新或 GitHub 发布流程。

安装包包含同次构建的 `desktop-tools.exe` 与 `desktop-tools-guardian.exe`，两者安装在同一目录。构建必须启用 `custom-protocol` 并内嵌前端。保留纯程序构建入口，另设安装包构建入口。

缺少 WebView2 Evergreen Runtime 时使用 Tauri 的联网引导安装方式，避免每份安装包携带完整运行时；无网络且缺少运行时的机器不能完成依赖安装。

## 安装与卸载边界

覆盖与卸载前复用 `--desktop-menu exit` 请求正常退出，并在有限时间内检查当前用户的主程序与 guardian 均已停止。未退出、退出命令失败或存在无法定位安装程序的运行实例时中止，不强杀进程。检查只在安装与卸载阶段短暂执行，不增加常驻监听。

检测到已安装版本时，重装页按版本关系分支：同版本与升级提供互斥的“添加/重新安装组件”（默认勾选）和“卸载 Desktop Tools”两个勾选项，勾选卸载时先运行旧卸载器再安装，否则直接覆盖安装——只覆盖同名文件并重写卸载登记与卸载器，旧版本独有的文件会保留；降级只提供卸载确认，未勾选时“下一步”不可用，勾选后先卸载再安装。默认覆盖是为了让同版本重装与升级不再依赖卸载器，避免卸载失败中断安装，同时保留用户数据与桌面菜单登记；代价是旧版本遗留文件不会被清理。重装页由 `src-tauri/installer/installer.nsi` 提供，该文件取自 `tauri-cli-v2.11.4` 的 NSIS 模板并只改动重装页，升级 Tauri CLI 后必须重新对比上游模板并回放修改；不引入应用内自动更新或静默更新入口。

安装完成后通过 `--register-desktop-menu` 登记当前程序位置；卸载在删除程序前通过 `--unregister-desktop-menu` 移除产品菜单。保留用户配置、布局、收集箱、自定义数据目录与日志；不增加用户数据清理逻辑。

核心应用采用 `GPL-3.0-or-later`，随包提供许可证及第三方许可文件。本次产物为未签名测试安装包，不改变已签名官方发行版的定义；生产签名与公开发布另行落实。

安装生命周期、WebView2 依赖环境、用户数据保留与桌面菜单恢复尚未经真实环境验证；构建成功不等同于功能可用。
