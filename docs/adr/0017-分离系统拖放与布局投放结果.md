# 分离系统拖放与布局投放结果

Windows 原生 OLE 负责跨程序拖放，自定义 `IDropTarget` 接入工作区命中和预览，`IFileOperation` 执行真实文件复制、移动。逐项最终身份驱动围栏归属；内部布局投放只提交布局事务。文件传输与布局持久化分别执行，不承诺跨系统原子回滚。

## 接收与交互决策

首期外部接收支持已有文件和目录的左键复制、移动，写入 Windows 解析的当前用户真实桌面目录，支持系统重定向。虚拟文件、创建快捷方式请求和右键拖动不在接收范围；已有 `.lnk` 文件可作为文件复制、移动。不支持的效果不得降级为复制，包含不支持项目的集合在传输前整体拒绝。

桌面项目拖动一律由 OLE 承载，不按拖动距离或落点区分路径：未归类区域项目、围栏成员、组拖动和跨屏拖动共用同一条输入路径，拖动光标、拖动图像与修饰键反馈由 Windows 驱动。内部 Alt 保留自由定位，拖出时 Alt 遵循外部目标语义。拖出提供完整 Shell 数据对象，不受首期拖入格式限制。围栏与格子的移动缩放、桌面空白区域框选继续使用内部指针路径，不创建 Shell 数据对象，也不进入 `DoDragDrop` 嵌套消息循环。选择集合无法整体创建 Shell 数据对象时拒绝拖动并报错，不静默缩减选择集合，也不回退内部布局拖动。

从外部拖入且全部确认为现有桌面项目时，无修饰键只调整归属和布局，显式 Ctrl 复制仍执行文件操作。该路径使用已验证的项目身份，不将外部来源标记为本进程会话。本进程内部会话通过自身登记的身份与项目集合识别。

已有桌面项目与新文件混合投放时，新文件按协商效果传输，再将已有项目与实际成功的新结果一次提交共享归属。新文件失败不阻止已有项目归属；用户取消传输时不再提交已有项目归属，已经完成的新文件保留并进入未归类。显式 Ctrl 复制时，已有项目和新文件均执行复制。整批投放不承诺原子成功。

## 内容与结果归属

同围栏内部投放必须区分“没有激活插入”和“明确插到最后”：前者保留原顺序，后者执行重排。跨围栏及外部来源的空白投放仍允许追加，避免修复原位误重排时破坏已有收纳能力。

遵循 [ADR-0001](0001-围栏采用逻辑归属.md)，工作区统一保存围栏成员、归属、位置、尺寸、滚动和组件布局，不按虚拟桌面分区。投放释放后固定共享围栏身份，切换或删除虚拟桌面不改变内容目标；围栏本身消失按目标失效处理。释放前切换虚拟桌面不因桌面身份变化主动取消拖动；原生系统取消仍按既有契约处理。

只将本次投放逐项确认完成、最终身份可解析的顶层结果加入目标。目录后代不能成为独立围栏成员，并发下载或其他创建通知不能作为本次结果。覆盖或合并后的成功结果跟随本次共享围栏目标，跳过项保持原归属。并发组按实际布局提交顺序插入有效后继之前，后继消失时追加，自动排序沿用现有规则。

传输前发现目标无效或容量不足则拒绝。文件完成后布局失败时保留文件，新结果回退未归类，已有结果保持原归属，并报告失败。布局写入整体失败时不能宣称回退已保存，也不能重做文件传输来补一次布局失败。

用户层一次撤销关联文件补偿与共享归属恢复，只恢复实际补偿成功部分，延续 [ADR-0014](0014-分离布局撤销与Shell操作撤销.md) 的分离执行边界。

覆盖或目录合并无法证明补偿安全时，该部分保留并列入“未恢复项目”，仅对可安全补偿的部分执行撤销；禁止通过回收整个合并目标恢复，不引入完整文件备份系统。部分补偿成功后立即记录成功部分，重做只覆盖这些项目；失败部分的身份与外部状态仍明确时允许用户再次撤销重试，存在歧义则标记失效并提示。不得自动重试或重复执行已成功部分。

## 线程与反馈约束

遵循 [ADR-0012](0012-在专用STA运行时执行Shell操作.md)，宿主线程持有 HWND 与 OLE 投放目标生命周期，Shell STA 执行原生文件操作。注册线程需要 `OleInitialize`、持续消息处理及配对撤销注册；跨 apartment 使用 COM 接口需合法封送。

原生回调不得同步等待 WebView 回传落点，最终投放使用可立即读取且版本有效的命中数据。拖动光标反馈与内部布局释放共用同一确认规则：使用最新已确认的渲染几何帧，不要求原生指针序号与确认帧完全相等；布局修订、显示器身份、落点坐标与几何有效性仍须严格匹配，过期帧不得覆盖正在使用的落点。屏幕物理坐标按目标显示器转换，覆盖混合 DPI、宿主与子窗口切换。进入 OLE 前需结束原指针捕获与监听，避免重复提交或提前回滚。大文件传输期间桌面须保持可交互，不能提前报告成功；异步数据提取遵循 `IDataObjectAsyncCapability` 的协商和完成协议。

内部布局结果与文件传输反馈分开记录。`DROPEFFECT_NONE` 不等同于取消；`DoDragDrop` 效果、`CFSTR_PERFORMEDDROPEFFECT` 和 `CFSTR_LOGICALPERFORMEDDROPEFFECT` 分别按协议解释。真实移动遵循优化移动的完成反馈与删除责任，避免源端重复删除。

## 当前实现与验证边界

- [desktop_host.rs](../../src-tauri/src/platform/windows/desktop_host.rs) 为宿主及子窗口注册自定义目标，负责 COM 身份、效果协商、物理坐标转换、文件封送、消息泵等待和完成反馈。释放使用已登记会话、原生指针序号、布局修订、几何修订、显示器和准确坐标一致的渲染确认。
- [desktop_drop.rs](../../src-tauri/src/app/desktop_drop.rs) 接收确认后的 DIP 几何及文件结果，负责目标解析、容量预检、内部布局提交、混合来源拆分、环境协调、结果归属和撤销记录。应用层不持有 COM 对象，不改变宿主与 Shell STA 的执行约束。
- [useWorkspaceDrag.ts](../../src/features/workspace/interaction/useWorkspaceDrag.ts) 异步准备完整 Shell 数据对象，使用 Windows 系统阈值和单次凭据交接 OLE；取消、单击和过期准备释放数据。目标在自己的 apartment 比较规范 `IUnknown` 身份，内部布局结果使用独立完成标记，返回 `DROPEFFECT_NONE`。
- [useCrossMonitorPreview.ts](../../src/features/workspace/surface/useCrossMonitorPreview.ts) 管理跨屏会话、消息序号、过期和异步几何确认；[workspaceDropTarget.ts](../../src/features/workspace/surface/workspaceDropTarget.ts) 拥有目标 DOM 命中、围栏滚动、插入及桌面传播预览。OLE 拖动图像由 Windows 持有，异步准备 Shell 数据对象时通过 `IDragSourceHelper` 初始化锚点系统图像，内外来源均接入 `IDropTargetHelper`，页面不重复绘制跟随指针的项目图像。源命中几何仍用于布局计算；非 OLE 格子拖动仍由 [crossMonitorDragPreview.ts](../../src/features/workspace/surface/crossMonitorDragPreview.ts) 呈现。此分工避免原生交接后等待页面帧才出现拖动图像；多选、混合 DPI 和跨应用显示仍需实机验证。释放后停止滚动，结束时清理临时节点和迟到帧。
- Wry 本地命令通过 `with_asynchronous_custom_protocol` 和阻塞工作池执行，Tauri 拖动与历史命令使用异步入口。文件传输和补偿各自在独立 STA 执行，主 Shell STA 保持菜单与打开请求的处理能力；同步 OLE 来源仍由宿主消息泵等待最终结果，不提前反馈完成。
- [shell.rs](../../src-tauri/src/platform/windows/shell.rs) 使用 `FOLDERID_Desktop` 与 `IFileOperation`，每个顶层来源独立执行，保留整体失败前的逐项事实。门户目标先通过 `SHCreateItemFromParsingName` 创建 `IShellItem`；文件系统安全边界可使用 `\\?\` extended-length 路径，但进入 Shell 解析接口前转换为普通 DOS/UNC 解析路径。Pre/Post 按 COM 身份关联来源，覆盖成功但 Shell 未返回新对象时沿用覆盖前已确认的目标引用；目录后代失败不被根成功覆盖。明确取消码与普通文件失败分别处理；实际复制、移动与内部布局不混用删除责任。
- [file_proof.rs](../../src-tauri/src/platform/windows/file_proof.rs) 记录卷、文件身份、属性、长度、修改时间、内容摘要及命名数据流。补偿前和 Pre 回调核对原结果树，拒绝变化、重解析点及已有目标冲突。覆盖或合并缺少安全依据时只报告不可自动恢复，不生成文件备份。
- [drop.rs](../../src-tauri/src/workspace/drop.rs) 将固定共享目标与原视图空间意图分开提交；原视图删除后不复活视图。Shell 历史逐项记录应用、撤销、失效和待保存布局，文件成功立即记账，布局保存重试不重放文件动作；部分成功后代仅参与文件补偿，不成为围栏成员。恢复只处理确认项目，保留并发归属和空间改动。
- 当前结构只读取 Schema 4，共享成员独立保存，不迁移或兼容读取旧围栏结构。共享外观沿用 ADR-0018，不被布局恢复覆盖。

- 统一桌面项目拖动路径的决策尚未实施：当前代码仍按拖动阈值区分内部布局拖动与 OLE，桌面项目拖动仍保留内部指针路径。光标反馈与内部布局释放当前都要求渲染确认的原生指针序号完全相等，未采用最新已确认几何帧。

类型检查、前端构建、Windows 原生构建、Rust 格式检查及差异与 UTF-8 检查通过。前端 58 项测试通过；带 `tauri/custom-protocol` 的完整 Rust 测试运行中 99 项通过、零失败，四项显式原生测试未执行。实机交互与这些显式测试未全部验证，整体验收保持未完成。

Windows 10 build 19045 上，当前构建已经启动两个宿主，每个宿主注册六个 OLE 投放窗口，日志确认桌面接管成功。实机交互由用户手动验收；混合投放、覆盖/合并、部分成功、取消、跨屏 DPI、虚拟桌面切换、撤销重做及长传输响应性在收到结果前均保持待验证，不能用单元测试或启动日志替代。

完整剩余事项以当前代码、编译结果和后续验收记录为准。
