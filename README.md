# Desktop Tools

Desktop Tools 是一款面向个人效率用户、专业创作者和开发者的 Windows 桌面内容工作区。它把文件、文件夹、围栏、门户和信息组件放在同一个可恢复的桌面表面上，同时保留 Windows Explorer 的文件事实、Shell 操作和系统恢复能力。

## 功能

- **桌面工作区**：组织文件、目录、快捷方式和功能格子，支持移动、缩放、折叠、边缘吸附、布局恢复和多显示器显示。
- **围栏与文件夹门户**：围栏负责项目归属、排序和滚动；文件夹门户负责浏览绑定目录及其子目录，并支持真实文件拖入和拖出。
- **Shell 内容呈现**：按需读取 Windows Shell 缩略图、视频帧和音频封面；加载失败时保留系统图标，不添加音乐角标、视频边框或快捷方式箭头。
- **收集箱**：集中保存文本、独立图片和普通文件映射。支持 Markdown 编辑、图片预览、类型筛选、多选、拖出和共享内容；删除收集记录不会删除文件映射指向的源文件。
- **功能格子**：提供收集箱、音乐、时间、Debug 和天气等官方组件。组件沿用统一的标题、菜单、移动、尺寸和跨屏交互；收集箱与天气格子可以从零添加，也可以移除。
- **插件扩展与预设插件**：支持通过声明式清单与 JavaScript ES 模块外壳扩展桌面格子与设置页条目；插件可在清单中声明宿主能力，运行时经能力通道按实例授权调用。仓库根目录 `plugin/` 提供最小格子、设置条目以及复合型示例插件，并包含面向插件开发者的全套文档；安装程序安装时自动将预设插件写入当前生效插件目录（同版本跳过以保留自改，不同版本更新），用户在设置中修改插件目录后会在下次启动时自动整目录迁移，卸载程序提供可选的预设插件清理勾选项（默认保留）。
- **AstrBot 状态格子**：安装随附的「AstrBot 状态」插件后，可在桌面上添加一个状态格子，显示本机 AstrBot 控制台是否在线以及核心加载完成以来的时长。在线时每 15 秒探测一次，连续失败后退避到 60 秒；数据超过 60 秒未更新时标记为过期。探测只读取 AstrBot 的免鉴权启动时间接口，不使用也不保存任何账号、密码或令牌，不显示平台连接与消息统计。
- **天气**：支持当前天气、24 小时预报和包含今天的 7 天预报；每个格子保存自己使用的 API 与城市，同一个 API 可以被多个格子使用，同一个城市也可以同时出现在多个格子里。可以同时配置多家 API，各自维护自己的城市或地区列表，城市搜索结果不保存。天气格子按照实时尺寸显示摘要、小时、日或完整预报；右键“固定显示模式”可锁定当前模式并限制最小尺寸，“切换显示模式”可选择其他模式，取消固定后恢复自动适配。来源栏显示来源与更新时间，详情通过标题栏右上角按钮或右键菜单打开；和风按城市搜索返回的详情页打开，Foreca 没有对应城市网页时该入口禁用。凭据由用户在设置中配置。- **编辑与系统操作**：Markdown 编辑窗保留原始文件引用；打开网页、邮件、文件和媒体时使用系统默认程序。文件打开、重命名、复制、移动和删除通过 Windows Shell 执行。

## 构建与运行

### 环境

- Windows 10/11 x64
- Node.js 与 npm
- Rust stable，以及项目配置所需的 Cargo 工具链
- Tauri 所需的 Windows WebView2 和 C++ 构建工具

### 安装依赖

```text
npm install
```

### 开发运行

```text
npm run dev
```

### 检查与构建

```text
npm run typecheck
npm run test:frontend
npm run test:rust
npm run build
npm run tauri:build
```

`npm run build` 生成前端发布资源；`npm run tauri:build` 生成 Windows 应用构建产物。未签名的 Windows x64 测试安装包可通过 `npm run tauri:installer` 生成，NSIS 产物位于 `build/target/release/bundle/nsis/`。已安装旧版本时，重装页默认勾选“添加/重新安装组件”并直接覆盖安装，勾选“卸载 Desktop Tools”则先卸载再安装；降级安装须先勾选卸载确认才能继续。

## 使用说明

首次打开后，可以从桌面背景菜单或设置入口添加功能格子。拖动文件或文件夹可将内容交给门户或收集箱；双击、Enter 或格子菜单可打开对应内容。工作区状态会保存，重新启动后恢复已保存的布局和组件设置。

天气功能默认关闭。启用后在“功能格子 → 天气”中添加来源：列表显示已配置来源及其可用状态，底部“+ 添加 API”选择供应商并填写对应凭据——和风天气需要 API Host、开发者 ID、项目 ID、凭据 ID 与 Ed25519 私钥，Foreca 只需要 API key——凭据填写完整即可保存。和风在保存时会自动用该来源第一座城市验证一次，结果直接显示为可用或不可用；验证不通过不影响凭据已被保存，稍后可用右键“检测可用”重试。编辑来源时留空的 API key 或私钥表示沿用已保存的值，填入新值表示替换。可以同时添加多家来源，不需要在其中选一家使用。

每个来源各自维护一份城市或地区列表：展开列表项可以查看、添加和删除城市，也可以右键“添加城市”；编辑来源的弹窗里同样可以管理这份列表，添加城市使用该来源已保存的凭据。搜索到候选城市后点“添加”才写入列表，“验证配置”只是可选的可用性检查，不写入也不阻止添加；搜索命中即可证明位置可用的来源只校验字段与链接，其余来源会实际请求一次当前天气。删除城市只是把它从该来源列表移除，正在使用该城市的天气格子会提示重新选择。

天气格子按需添加：桌面空白处右键菜单的“添加天气”、来源列表右键菜单“添加天气格子”下按城市创建，两者与 Explorer 桌面背景菜单的“添加天气”共用同一创建流程与布局撤销。从“添加天气”创建的格子初始不绑定来源与城市，在格子的右键菜单里用“切换 API”“选择城市”选定即可；切换到另一家来源会清空该格子的城市，需要在新来源下重新选择。同一个来源可以被多个格子使用，同一个城市也可以同时出现在多个格子里。格子选择的来源与城市随格子保存，用于下次启动恢复；缺少来源或城市时，格子按原因提示“选择 API”或“选择城市”。格子右键菜单底部的“移除”只移除当前格子，已保存的凭据与该来源城市列表不受影响，布局撤销可以恢复。

删除来源只清除该来源凭据并需要确认，该来源的城市列表与已有格子布局都会保留；使用该来源的格子提示“天气 API 配置已删除，请重新选择”，不继续展示旧数据。

## 功能边界

- Desktop Tools 维护工作区布局、围栏归属、门户配置和功能格子状态；Windows Explorer 继续维护文件事实和 Shell 恢复能力。
- 天气使用用户自己的天气服务账户（和风天气或 Foreca），不内置共享凭据；真实账户权限、网络可用性和供应商配额由用户账户决定。
- 天气的多家来源可以并存并同时更新，应用不自动切换来源、不拼接两家数据，也不按位置自动定位；每个格子使用哪一家、看哪个地区都由用户指定。同一个来源被多个格子使用时，相同城市共享一次请求与缓存。
- 天气缓存用于减少重复请求，数据可能因网络、有效期或服务端限制而暂时不可用；天气页面显示来源、更新时间和失败状态。
- 界面图标取自开源图标库 [Lucide](https://lucide.dev/icons/) 的 SVG 资源，许可证随资源一并提供；应用不使用图标字体，也不内置第三方地图或天气图标。
- 多显示器、混合 DPI、Windows 外部拖放和持续拖动性能需要在 Windows 宿主上验证，自动化测试不能替代真实设备检查。
