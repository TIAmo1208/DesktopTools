# 插件总览

Desktop Tools 支持通过本地插件扩展桌面格子与设置页选项。插件以轻量外壳对象的形式与宿主交互，具有极简的生命周期与配置规范。

## 什么是插件包

每个插件是一个独立的文件夹，结构扁平清晰：
- 插件文件夹必须直接放置于**插件根目录**的第一层子级中（不支持多层嵌套子文件夹）。
- 文件夹内必须包含 UTF-8 编码的清单文件 `manifest.ini`。
- 文件夹内包含入口脚本（例如 `index.js`）及关联的静态样式文件（例如 `style.css`）。主题插件改用 `theme.css` 与 `theme.json`，入口脚本可选：需要开机转场、音效、彩蛋等运行期行为时才创建 `activateTheme` 入口；需要自带字体时把字体文件一起放进该文件夹，在 `theme.json` 的 `fonts` 里声明。
- 文件夹名是清单 `name`，或设置页安装写入的 `作者@名称`。手工放入的插件用 `名称` 即可；同一个作者名加同一个 `id` 才算同一个插件。
- 以 `.` 开头的文件夹不注册，安装用的 `.install-*` 临时目录因此不会被当成插件。
- 主题插件文件夹按 `主题-<主题名>` 命名，以便与格子插件区分，例如 `主题-青笺`。这是仓库与分发约定，宿主不强制前缀；清单 `name` 仍须与文件夹名一致。
- `id` 由作者在清单里声明，安装时原样保留，不重新生成也不改写；内容不在安装阶段校验，格式错误由运行时扫描报出。

## 默认插件根目录与生效目录

- 默认插件路径：可执行文件所在目录下的 `plugin`，即安装目录 `plugin` 子目录。无法定位程序时明确报错，不回退到用户数据目录。
- `pluginDirectory` 可显式覆盖默认目录，仍按既有绝对路径与特殊字符规则校验；修改后下次启动直接采用，运行期不热切换。
- 不读写插件位置指针，不自动复制迁移旧插件，也不提供旧版兼容。
- 开发运行通常使用 `build/target/debug/plugin`，不自动使用仓库 `plugin/`；开发者可显式设置插件目录。

## 安装途径

1. **安装包直接输出**：插件资源随程序写入安装目录的 `plugin`，不再由主程序复制第二份。升级按打包清单覆盖同名文件，保留用户新增插件；真正卸载会删除该目录内全部插件，包括用户自装插件，无独立清理勾选。安装目录外的显式插件目录不被安装器写入或清理，配置目录中的自定义设置继续保留。
2. **设置页手动安装**：在 Desktop Tools 的「设置 → 插件」页面中：
   - 支持通过「选择文件夹」直接安装包含 `manifest.ini` 的插件开发目录。
   - 支持通过「安装压缩包」安装 `.zip` 格式的插件包（清单位于压缩包根目录或仅下一层子目录内）。

## 预设示例索引与开发方向

仓库根目录下的 `plugin/` 目录提供主题插件、功能插件和开发示例。安装包通过 `src-tauri/tauri.installer.conf.json` 显式映射分发 `主题-青笺/`、`主题-宋律/`、`主题-夜之城/`、`AstrBot 状态/`、`docs/` 与 `README.md`；`示例/` 下的三个格子/设置示例仅保留在仓库，不进入安装包。运行时只扫描插件根下一层含 `manifest.ini` 的文件夹，不递归扫描 `示例/`，文档目录不注册为插件。

| 示例目录 | 插件 ID | 适用场景 / 开发方向 |
|---|---|---|
| [示例-最小格子](./示例/示例-最小格子) | `plugin.example.minimal` | **纯桌面格子组件**：演示 `renderTile` 挂载静态 DOM、开启定时器及返回注销清理函数。 |
| [示例-设置条目](./示例/示例-设置条目) | `plugin.example.settings` | **纯设置扩展条目**：`creatable=0`，不导出 `renderTile`，仅导出 `settingsEntries` 演示读取与保存插件自定义设置。 |

| [主题-青笺](./主题-青笺) | `plugin.theme-qingjian` | **主题插件**：`role=theme`，不含入口脚本。宿主挂载 `theme.css` 覆盖配色令牌，`theme.json` 写入字体、字号、圆角和两组强调色。 |
| [主题-宋律](./主题-宋律) | `plugin.theme-songlv` | **主题插件**：宣纸浅色与夜墨深色两套宋制配色，青绿承担交互强调色、窑铜用于桌面与菜单边框；自带裁剪过的思源宋体（SIL OFL 1.1），安装后进入外观字体列表。 |
| [主题-夜之城](./主题-夜之城) | `plugin.theme-nightcity` | **主题加格子一体的插件**：NC 黄与霓虹青的夜之搭配色，深色为主形态、浅色为日间变体；样式表自带 CRT 扫描线与 45° 切角表现层，不打包字体，终端质感由等宽数字、标题字距与悬停冷光叠加实现。同一文件夹里的入口脚本提供「夜之城时钟」格子：NC-TIME 读出配十六进制数据流，只读本机时间，折叠时只保留时间。 |
| [AstrBot 状态](./AstrBot%20状态) | `plugin.astrbot-status` | **声明宿主能力的功能插件**：清单声明 `required_capabilities = probe-service-status`，通过 `invoke_component_capability` 探活本机 AstrBot，按四档状态轮询并在格子不可见时暂停刷新。 |

## 快速开始

1. 在 `plugin/` 目录下参考上述示例创建一个新文件夹（文件夹名称必须与 `manifest.ini` 中的 `name` 严格一致；经设置页安装时宿主会装到 `作者@名称` 文件夹）。
2. 在该文件夹中创建 `manifest.ini`，声明插件基本元数据（名称、版本、入口脚本、创建上限等）。
3. 编写 `index.js` 入口文件，默认导出一个符合外壳契约的对象：
   ```javascript
   export default {
       renderTile(container, context) {
           container.innerHTML = "<div>你好，桌面插件！</div>";
           return () => {
               // 退出清理逻辑
           };
       },
   };
   ```
4. 将整个插件文件夹放入程序所在目录的 `plugin`（或显式配置的插件目录），或者在「设置 → 插件」中点击安装。

## 调试与生效机制

- **日志排查**：在开发环境下打开控制台或检查应用运行日志，若清单格式不合法、入口缺失或脚本语法错误，宿主会在运行时输出包含插件 ID 的 WARN 或 ERROR 级别的警告日志。
- **生效机制与重启**：
  - 通过设置界面的安装/卸载命令操作后，宿主会立即重新扫描清单并广播运行时快照，列表即时刷新。
  - 若在外部直接手动编辑、修改文件、覆盖脚本或替换样式，模块受同源模块缓存机制影响不会热替换，**必须重启 Desktop Tools 软件后方可生效**。

## 运行约束与安全限制

- **作者受信原则**：插件代码在宿主页面（WebView）内直接执行，与宿主共享执行环境，不包含独立进程、iframe 或沙箱隔离。请仅安装受信作者提供的插件。
- **无沙箱**：插件具有页内 JS 运行权限，但宿主不提供外部恶意代码防护沙箱。
- **CSP 策略**：
  - 宿主严格执行内容安全策略 `script-src 'self'`，**严禁使用 `eval`、`new Function` 或内联脚本 `<script>`**。
  - 宿主执行 `style-src 'self'`（未放开 `unsafe-inline`），**内联 `<style>` 标签与 DOM 元素的内联 `style="..."` 属性均会被 CSP 拦截**。插件样式只能来自独立 `.css` 静态资产或通过 JS CSSOM 属性赋值操作。
- **静态资产路由限制**：宿主本地协议对插件目录提供 `.js`、`.css` 与 `.woff2`/`.woff`/`.ttf`/`.otf` 字体文件的路由，其他类型资源不支持通过 `/plugins/` 协议直接加载（`img-src` 允许 `data:` 图片，但字体 data URL 不可依赖；字体走 `theme.json` 的 `fonts` 声明）。
- **声明宿主能力**：插件在清单中用 `required_capabilities = probe-service-status` 声明宿主能力（逗号分隔，可用值见[开发指南](./docs/开发指南.md)），运行时只能通过 `invoke_component_capability` 按实例调用；插件无法调用未声明的能力。
