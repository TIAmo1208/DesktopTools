# 插件开发指南

本文档面向插件开发者，详述插件清单配置、外壳导出接口、生命周期回调、上下文状态以及样式接入规范。

## 1. 清单配置（`manifest.ini`）

插件必须在根目录下提供 `manifest.ini` 配置文件，且所有配置项均置于 `[plugin]` 节中。文件必须采用 UTF-8 编码。

### 字段说明与校验规则

| 字段名 | 必填 | 默认值 | 取值与格式要求 |
|---|---|---|---|
| `name` | **是** | - | 插件显示名称。**必须与所在的插件文件夹名称严格完全一致**；设置页安装的目标文件夹是 `作者@名称`，手工放入时用 `名称`，两种都接受。长度最多 80 字符，且禁止包含 `\ / : * ? " < > \|` 等非法文件名字符及控制字符。 |
| `id` | **是** | - | 插件唯一标识符。必须带 `plugin.` 前缀（如 `plugin.qingjian`）。前缀后仅允许 ASCII 小写字母、数字、点号 `.` 和短横线 `-`，最大长度 128 字符。标识由作者声明，安装时原样保留、不重新生成也不改写；安装阶段只要求它非空。同一作者的同一标识视为同一插件。 |
| `version` | **是** | - | 插件自身版本号。必须为严格的三段数字格式，如 `1.0.0`。 |
| `entry` | **是** | - | 插件执行入口脚本。必须为该插件文件夹内的相对路径，必须以 `.js` 结尾（例如 `index.js` 或 `dist/main.js`）。禁止包含绝对路径、父级跨目录 `..`、符号链接或重解析点。主题插件同样可以带入口脚本；入口文件不存在时不向页面下发脚本地址。 |
| `minAppVersion` | 否 | 空 | 要求的最低宿主程序版本（例如 `0.4.0`），必须为三段数字格式。若当前宿主版本低于该值，插件将被拒绝注册。 |
| `maxAppVersion` | 否 | 空 | 允许的最高宿主程序版本，必须为三段数字格式。若当前宿主版本高于该值，插件将被拒绝注册。 |
| `author` | 否 | 空字符串 | 插件作者名称。插件独立持久化设置的存储键会以此作为前缀命名（格式为 `作者@插件ID`）。 |
| `description` | 否 | 空字符串 | 插件功能描述。因 ini 规范限制跨行，**描述文本中的换行请显式写成 `\n`**。 |
| `repository` | 否 | 空字符串 | 插件源码仓库或项目主页链接。仅允许以 `http://` 或 `https://` 开头的合法 URL；其他非法协议（如 ftp）会记录 WARN 警告并被丢弃视同未声明。 |
| `creatable` | 否 | `0` (`false`) | 是否允许用户在工作区（桌面）创建该插件的格子实例。接受 `1`/`0` 或 `true`/`false`。若为 `0` 或未声明，则用户无法将该插件添加为桌面格子。主题插件只有在入口文件存在时才会采纳这个声明，否则一律不能创建格子。 |
| `removable` | 否 | `1` (`true`) | 是否允许用户从工作区移除已添加的格子实例。接受 `1`/`0` 或 `true`/`false`。缺省为允许移除。 |
| `maxTiles` | 否 | `0` (不限) | 允许在桌面上创建的格子实例数上限（跨所有显示器累计）。缺省或填 `0` 表示不限制数量；填正整数表示上限值。声明了 `[tiles]` 时，这是**每个类型各自**的上限，见下方格子类型一节。超出上限时宿主将拒绝创建新实例。 |
| `required_capabilities` | 否 | 空 | 声明插件需要的宿主能力，多个能力用英文逗号分隔（如 `probe-service-status`）。插件槽当前只放行单个能力 `probe-service-status`（探活宿主固定的本机服务地址）；填入未支持的能力名、重复能力或一次声明多个能力，插件清单都会被拒绝注册。 |

### 格子类型（`[tiles]` 子节）

同一个插件可以在桌面上创建几种不同内容的格子。类型写在 `manifest.ini` 的 `[tiles]` 子节里，每行 `键 = 显示名`：

```ini
[plugin]
id = plugin.example.multi
name = 示例-多类型
version = 1.0.0
entry = index.js
creatable = 1

[tiles]
status = 连通状态
messages = 消息数
```

- 键是代码里的稳定标识，只能用 ASCII 小写字母、数字、`-`、`_`，最长 32 个字符；显示名去掉首尾空白后 1 到 24 个字符。
- 第一节是默认类型。子节写了却没有任何有效行，或键重复、键或显示名不合法，整份清单不注册。
- 不写子节时只有一个隐式类型，键是 `default`，菜单不展开。
- 一个插件的 `maxTiles` 是**每个类型**的上限，不跨类型共用：写了 `status = 连通状态` 和 `messages = 消息数`、`maxTiles = 2`，就表示这两类各自最多 2 个。没有 `[tiles]` 的插件仍按插件身份整体限一次。
- 实例没有类型（旧格子，或创建时未选类型）时按第一节的默认类型计数。
- 用户创建时会先选类型；二级页右上角按钮和右键菜单在多于一种类型时展开为类型列表。创建后类型随实例持久化，运行时不能改。
- `renderTile` 用 `context.tileType` 区分内容；类型为空串时按默认类型画。不同类型实例共用一份注册对象和一份设置，定时器与订阅要按 `instanceId` 各自清理。

### 判断这份清单是否已生效

清单由宿主按文件内容判重，**只改文件内容的长度、不改文件修改时间时宿主不会重新解析**：用 `copy` 覆盖安装或升级插件包后，目标文件的修改时间或大小通常不变，宿主仍沿用旧清单，表现是新增的字段（例如 `[tiles]`、`maxTiles`）不生效，也不报错。修改清单后请先删掉目标文件夹再放入，或者顺手改一处长度不同的文字，然后重启程序。脚本与样式表只读磁盘，不受这条限制。

### `manifest.ini` 示例

```ini
[plugin]
id = plugin.example.combined
name = 示例-格子与设置
version = 1.0.0
entry = index.js
author = Desktop Tools Project
description = 这是一个包含桌面格子与设置条目的示例插件。\n修改设置将实时同步到格子。
repository = https://github.com/DesktopTools/DesktopTools
creatable = 1
removable = 1
maxTiles = 2
minAppVersion = 0.4.0
```

## 2. 入口模块与外壳对象

入口脚本（如 `index.js`）是一个标准 ES Module，**必须默认导出（`export default`）一个外壳对象**：

```javascript
export default {
    // 可选：渲染桌面格子
    renderTile(container, context) {
        // ...
        return () => { /* 清理函数 */ };
    },

    // 可选：注册设置页条目列表
    settingsEntries: [
        {
            id: "my-settings-entry",
            name: "插件偏好配置",
            render(container, context) {
                // ...
                return () => { /* 清理函数 */ };
            }
        }
    ],

    // 可选：主题被选中时执行一次，返回停用或切换主题时的清理函数
    activateTheme(context) {
        // ...
        return () => { /* 清理函数 */ };
    }
};
```

`activateTheme` 只对 `role=theme` 有意义：主题被选中后，每个窗口各执行一次；停用、切换主题或窗口销毁时执行返回的清理函数。它的 `context.instanceId` 是空串，`context.collapsed` 恒为 `false`，`settings` 与 `saveSettings` 按插件标识读写，与格子共用同一份持久化设置。主题不需要脚本时不要创建入口文件，宿主不会下发空的脚本地址。

### 宿主事件订阅

桌面宿主页面暴露 `window.__DESKTOP_TOOLS_NATIVE__.onPluginEvent(handler)`，返回退订函数。它**只在桌面宿主窗口可用**——设置窗口没有这个桥接对象，设置条目里不要依赖它。

```javascript
const stop = window.__DESKTOP_TOOLS_NATIVE__?.onPluginEvent?.((event) => {
    if (event.type === "toast-shown") console.log(event.payload.kind, event.payload.source);
});
// 在 renderTile / activateTheme 返回的清理函数里退订
return () => stop?.();
```

| `type` | 时机 | `payload` |
| --- | --- | --- |
| `toast-shown` | 原生通知真正入队之后 | `{ kind, source }`，不含正文 |
| `app-started` | 首批桌面宿主就绪，每个进程只发一次 | `{}` |
| `app-quitting` | 用户退出程序、窗口销毁之前 | `{}` |

- 事件对象是 `{ type, at, payload }`，`at` 是毫秒时间戳。
- 回调抛错只记日志，不影响其他插件，也不阻塞宿主。
- 只在需要时订阅，并在清理函数里退订；常驻订阅请用 `activateTheme` 的返回值释放。
- 通知正文不外发，插件拿不到用户看到的具体内容；需要正文请自己发消息时记录。

## 3. 桌面格子渲染：`renderTile`

### 方法签名

```typescript
renderTile(container: HTMLElement, context: PluginShellContext): void | (() => void)
```

- **`container`**：宿主提供的一个空白 DOM 宿主容器。插件可自由向其添加元素、渲染内容或挂载轻量组件。
- **返回值**：可选返回一个**清理函数**。当格子实例被销毁、实例离开屏幕、或者因配置变更即将重新渲染时，宿主会优先执行此清理函数。
- **定时器与事件清理**：若在 `renderTile` 中使用了 `setInterval`、`setTimeout` 或全局 `addEventListener`，**务必在返回的清理函数中予以注销清除**，避免内存泄露与脏回调。

### `context`（外壳上下文）对象

`context` 包含当前格子的运行上下文与配置通信能力：

| 属性/方法 | 类型 | 说明 |
|---|---|---|
| `pluginId` | `string` | 当前插件的全局唯一 ID（例如 `plugin.example.combined`）。 |
| `instanceId` | `string` | 当前格子实例的唯一标识。同一插件可在桌面上创建多个格子，每个格子拥有唯一的 `instanceId`。 |
| `tileType` | `string` | 当前实例的格子类型，来自清单 `[tiles]` 的键。没有声明类型或实例缺少类型时为空串，插件应按默认类型处理。 |
| `collapsed` | `boolean` | 当前宿主外框是否处于折叠收起状态。 |
| `settings` | `unknown` | 插件当前持久化的自定义设置。若尚未保存过配置或文件不存在，则为 `null`。 |
| `saveSettings` | `(value: unknown) => Promise<void>` | 保存插件设置的方法。宿主会将配置原子写入配置目录的 `settings-plugins.json`。 |

### 重新渲染与生命周期语义

1. **设置变更驱动重绘**：当调用 `saveSettings` 或其他窗口修改了该插件的设置时，宿主会触发配置同步事件并重新读取最新配置；随后先执行当前实例上一次 `renderTile` 返回的清理函数，再以全新的 `settings` 再次调用 `renderTile`。
2. **折叠状态变化**：当用户切换格子的折叠收起状态时，宿主复用当前已持有的 `settings` 重新触发挂载流程。
3. **实例卸载/移动**：当格子从当前屏幕被移除时，触发清理函数。

### 宿主能力调用

清单在 `required_capabilities` 声明能力后，插件通过宿主桥按实例调用，不使用平铺原生命令：

```javascript
const result = await window.__DESKTOP_TOOLS_NATIVE__.invoke("invoke_component_capability", { instanceId: context.instanceId, capability: "probe-service-status" });
// result.payload：{ level: "ok" | "warn" | "off" | "unknown", startTime: number | null, checkedAt: number }
```

- 能力按实例授权：清单未声明该能力、实例未就绪或实例标识不存在时，调用失败，插件应按「未知」处理而不是当成服务离线。
- 宿主桥把命令名编入请求路径、把参数对象原样作为请求体发送，因此第二个参数必须是可 JSON 序列化的纯对象，字段名按上面的 `{ instanceId, capability }` 原样书写；不需要额外编码。
- `probe-service-status` 只返回本机 AstrBot 控制台的探活结论，端口由宿主固定，不接受插件传入地址、端口或凭据。
- `checkedAt` 是判定时刻（Unix 秒）；`startTime` 是 AstrBot 核心加载完成时刻（Unix 秒），只在 `ok` 时给出，时长由插件按当前时间现算。

## 4. 设置页条目：`settingsEntries`

插件可通过 `settingsEntries` 数组向 Desktop Tools 的「设置 → 插件 → 插件详情」页面注入自定义配置交互表单。

### 条目定义

```typescript
interface PluginSettingsEntry {
    id: string; // 插件内唯一的条目标识（不可重复，非空字符串）
    name: string; // 在设置页显示的行标题
    render: (container: HTMLElement, context: PluginShellContext) => void | (() => void);
}
```

- `id` 必须在当前插件内唯一，缺失或重复的条目会被丢弃并记录 WARN。
- `render` 接收宿主提供的空 DOM 容器及同款 `context`，可在容器内渲染配置表单（如文本输入框、下拉菜单、滑动条等），并监听表单事件调用 `context.saveSettings(...)` 保存设置。同样可返回清理函数。

## 5. 样式引入与样式隔离

### 引入方法

宿主支持通过原生 ES 模块标准资产定位方式加载样式：
在入口脚本中，使用 `import.meta.url` 构造相对 URL，并向 `<head>` 或 `container` 中追加 `<link rel="stylesheet">`：

```javascript
const styleUrl = new URL('./style.css', import.meta.url).href;
if (!document.querySelector(`link[data-plugin-style="plugin.example.combined"]`)) {
    const link = document.createElement('link');
    link.rel = 'stylesheet';
    link.href = styleUrl;
    link.setAttribute('data-plugin-style', 'plugin.example.combined');
    document.head.appendChild(link);
}
```

### 资产路由与安全限制（CSP 约束）

- **CSP style-src 'self' 约束**：宿主严格执行 `style-src 'self'`，**未放开 `unsafe-inline`**。这意味着：
  - HTML 中的 `<style>` 内联标签会被浏览器拦截；
  - DOM 元素上的内联属性（如 `element.innerHTML = '<div style="..."></div>'` 或直接写 `style="..."`）会被浏览器拦截；
  - 样式的唯一合法来源是插件自带并通过 `/plugins/` 路由加载的 `.css` 静态样式表文件，或通过脚本直接操作 CSSOM 对象（如 `element.style.color = ...`）。建议优先使用 CSS 样式类名切换。
- **资产路由放行 `.js`、`.css` 与字体文件**：宿主内部协议对 `/plugins/` 相对路径做过文件类型过滤，只响应 `.js`、`.css` 以及 `.woff2`、`.woff`、`.ttf`、`.otf`。其他类型资源（图片、JSON、字体以外的二进制）不支持直接从插件路由读取；`img-src` 允许 `data:` 图片，但字体的 data URL 不可依赖。
- **主题自带字体**：`role=theme` 的插件在 `theme.json` 里用 `fonts` 声明字体，宿主注册后进入「设置 → 外观」的字体列表：

    ```json
    {
        "appearance": { "fontFamily": "宋律宋体" },
        "fonts": [{ "family": "宋律宋体", "file": "fonts/songti.woff2", "weight": 400, "style": "normal" }]
    }
    ```

    `file` 只能是插件文件夹内的相对路径，单个文件不超过 `16 MiB`，一个主题最多 `4` 项。字体族名不允许 `;`、`{}`、`()`、引号、反斜杠和控制字符。主题样式表不写 `@font-face`；缺字由宿主拼的回退栈逐字符退回系统字体。字体许可由作者负责，插件索引里注明来源。
- **主题样式表缓存键**：主题 `<link>` 的地址带 `?v=<样式表缓存键>`，三档回落依次为宿主派生的 `stylesheetCacheKey` → 清单 `version` → `"0"`，设置页组装的链接与宿主首帧拼进窗口地址使用同一串。`stylesheetCacheKey` 是宿主只读派生字段：注册主题插件时按清单 `version` 加样式表文件大小和修改时间计算，`manifest.ini` 里没有对应键，插件不可声明、声明无效；改主题文件后缓存键自动变化，无需 bump 版本。
- **样式隔离（Scoped CSS）**：插件与宿主及其他插件共享同一 WebView 页面，样式并不具备 Shadow DOM 的天然隔离。格子与设置条目的 CSS 选择器必须添加专属前缀或特定命名空间类名（例如 `.plugin-example-combined-tile .title`），禁止污染全局样式。`role=theme` 的样式表除覆盖[主题变量契约](../../docs/design/主题变量契约.md)列出的配色令牌外，还可以声明本主题自己的表现层（覆盖层、切角、扫描线等）与专属类名；字体族、字号、圆角与强调色仍走宿主偏好写入。主题样式表随主题撤下，因此表现层必须由该样式表自身完整定义，不得依赖切换主题后仍然存在的规则。视觉规范不约束插件表现，插件作者自行保证可读性与可用性。
- **主题可声明的原生消息外观**：原生 Toast 由 Rust 绘制，页面样式覆盖不到，不能用页面 CSS 添加结构装饰；改它要走 `theme.json` 的 `notification` 段：`surface`、`border`、`text`、`muted`、`subtle` 五项基础色，`success`、`warning`、`error` 三项状态色，`weight` 字重，以及可选的 `cornerStyle`（`round`/`bevel`）与 `cornerSize`（`1`–`24` DIP）。只有同时声明 `cornerStyle: "bevel"` 与合法 `cornerSize` 才绘制左上、右下切角；任一缺省都保留原圆角外观。切角量独立于 `appearance.cornerRadius`，后者为 `0` 时切角仍生效。颜色字段须为 `#RRGGBB`，非法值、越界值或未知键使整份主题注册失败。形状与装饰属于可撤销表现层，随当前主题撤下而消失；整套外观只有一份，不随深浅模式切换。字段含义与校验见[主题变量契约](../../docs/design/主题变量契约.md)。
- **启动覆盖层**：宿主建桌面窗口时就把当前主题样式表地址拼进页面地址，所以 `theme.css` 从第一帧起生效，不需要等偏好回包。桌面首屏会出现 `#boot-splash`（只在主显示器、本进程启动后两秒内、且未要求减少动效时出现），默认显示 `900ms`，主题可以用 `theme.json` 的 `boot.durationMs`（`0`–`10000`，`0` 表示不播）改这个总时长——宿主把时长拼进页面地址，页面据此写 `--boot-splash-duration` 并安排移除，不会出现「CSS 改长了但 JS 提前收走」。外观改它的底色、`::after` 扫描层与 `.boot-splash__mark` 字色即可；不想播就把 `durationMs` 设为 `0`。
- **主题设置条目**：`settingsEntries[].render` 可同时绘制布尔开关和有边界的数值输入；数值只保存当前插件的设置对象，例如一个切角量 `bevelPixels`。读取时先归一（非法值用当前默认值，合法值限制在已声明范围），`change` 时保存归一值并把效果应用到当前文档；`activateTheme` 在每个窗口读取同一设置重放，返回的清理函数移除自身写入的 `data-*` 状态与主题私有 CSS 变量。布尔开关同理：缺省按主题自己的默认解释（未声明不等于关闭），并把开关名与作用范围写进行内的名称与提示。开关划分、作用范围与门控关系的具体写法参考主题自带说明文档（如[夜之城主题说明](../主题-夜之城/说明.md)）；主题私有 CSS 变量仅供该主题使用，不是宿主令牌，也不应列进[主题变量契约](../../docs/design/主题变量契约.md)的可覆盖清单。
- **主题按语义叠加，不重写变体配色**：`data-button` 已有 `primary`、`secondary`、`danger`、`icon`、`ghost`、`switch`、`row-hit`；原生禁用态用 `:disabled`，不是 `data-button="disabled"`。`primary`/`secondary`/`icon`/`ghost` 的视觉由组件 CSS 持有，`danger` 与禁用由 `src/styles/global.css` 持有；主题修改它们的颜色应覆盖[主题变量契约](../../docs/design/主题变量契约.md)里的令牌，不另写同一组填充、边框、文字规则与组件争特异性。主题的按钮悬停冷光等可撤销特效要排除 `:disabled`，并保留按钮的青色键盘焦点环；文本输入的聚焦冷光不要覆盖复选与开关。`row-hit` 只属于 `position: absolute; inset: 0` 的整行命中层，不参与按钮视觉；自绘菜单项、格子内部按钮等普通按钮不加 `primary` 或 `row-hit` 标记。交互控件的主题切角只调整绘制轮廓，不裁文字与命中区；结构面保持直角，页面 CSS 的角标只给自绘菜单等真实结构件，不加在按钮或原生 Toast；原生 Toast 的可撤销表现层仅支持上述 `notification` 切角。菜单的 `4px` 容器内距由组件管理，主题不可改。
  取值与控件的对应见[视觉规范](../../docs/design/视觉规范.md)的按钮语义表。
- **禁止对通用标签使用 `transform`、`filter`、`contain`、`will-change`**：它们会改变元素内部绝对定位后代的包含块。整行命中按钮的命中面就是靠 `inset: 0` 铺满整行，一旦父级被加上这类属性，命中面会缩回文字框，表现为“按钮点了没反应”。按下反馈用颜色或亮度，不要用位移。
- **避免 HTML 注入**：对于用户输入或配置中的动态文本，请通过 `element.textContent` 或 `element.value` 赋值，切勿直接拼接进 `container.innerHTML`，避免引入 XSS 隐患。

## 6. 常见失败原因与排查清单

1. **缺失默认导出**：入口模块未提供 `export default` 或导出的不是普通 Object，宿主将报错「插件模块没有默认导出」或「插件导出不是对象」。
2. **entry 路径不正确**：`entry` 必须是相对于该插件文件夹的相对路径，结尾必须为 `.js`。格子插件的目标文件缺失会在前端报加载失败；主题插件的目标文件缺失时宿主不下发脚本，`activateTheme` 不会被调用。
3. **违反 CSP 安全策略**：宿主执行 `script-src 'self'` 与 `style-src 'self'`：
   - 脚本方面：禁止使用 `eval()`、`new Function()` 或内联字符串注入脚本代码；
   - 样式方面：禁止在 `innerHTML` 中直接使用 `style="..."` 内联样式属性，否则会被浏览器 CSP 静默拦截并报 CSP 违规警告；
4. **脚本单次加载机制**：浏览器同源模块仅在初次加载时执行一次并被缓存。当遇到脚本逻辑或运行时报错时，宿主不会自动重试；修改本地文件后必须**重启软件**才能重新加载。
5. **名称不一致**：文件夹名必须是 `manifest.ini` 里的 `name`，或设置页安装写入的 `作者@名称`，区分大小写；点开头的文件夹不注册。
