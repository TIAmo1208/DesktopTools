# 插件发布与分发

本文档面向插件打包者与维护者，说明插件的打包压缩规范、版本升级与覆盖规则、卸载机制，以及预设插件随宿主打包的约定。

## 1. Zip 插件包结构要求

插件可通过打包为 `.zip` 压缩文件进行分发与分享。宿主支持以下两种压缩目录结构之一：

### 结构 A：清单文件位于压缩包根目录
```text
my-plugin.zip
├── manifest.ini
├── index.js
└── style.css
```

### 结构 B：清单文件位于压缩包下一级子文件夹内
```text
my-plugin.zip
└── my-plugin/
    ├── manifest.ini
    ├── index.js
    └── style.css
```

### 安全与解压约束

宿主在解压插件 Zip 文件时执行严格的安全检查：
- **禁止绝对路径与路径穿越**：压缩条目中不得包含绝对路径、驱动器盘符（如 `C:`）或父级跨目录标记（`..`）。
- **拒绝符号链接**：压缩包中包含 Unix 软链接等重解析点时将直接中止解压。
- **文件体积与数量限制**：
  - 单个文件体积上限为 **64 MiB**；
  - 压缩包解压总体积上限为 **256 MiB**；
  - 压缩包条目总数上限为 **2000 个**。
  - 超过上述任意阈值时将拒绝安装并提示错误。

## 2. 版本升级、同版本覆盖与降级确认

当在「设置 → 插件」界面安装插件时，宿主会依据 `name` 及 `manifest.ini` 中的 `version` 判定安装策略：

1. **版本升级（目标版本 > 已安装版本）**：
   - 宿主直接以新版本文件覆盖原插件目录。
   - 保留原有的插件唯一 ID（`id` 不变）。
   - 保留原有的插件配置与工作区桌面格子实例。
2. **同版本覆盖（目标版本 == 已安装版本）**：
   - 视为开发调试或资源重刷，直接覆盖插件目录。
   - 保留原有的插件唯一 ID 与现有配置。
3. **版本降级（目标版本 < 已安装版本）**：
   - 宿主将标记为冲突，并在安装确认对话框中向用户提示版本降级警告。
   - 只有在用户明确勾选/确认降级后方可执行。
   - 确认降级后，宿主会先行执行旧版本卸载流程（移除桌面格子实例、删除原文件夹、但保留用户配置数据），然后写入新版本。

## 3. 卸载机制与配置清理

用户可在设置页面中对插件进行卸载操作，卸载分为两种模式：

### 模式一：标准卸载（默认）
- 立即物理删除当前插件目录中的整个子文件夹。
- 立即当场移除该插件在所有显示器工作区上的所有格子实例，清理焦点并清除外观包围盒记录。
- **保留用户配置**：保存在用户配置目录 `settings-plugins.json` 中的插件自定义配置项（键为 `作者@插件ID`）予以保留。若未来重新安装该插件，原配置仍可直接恢复。

### 模式二：卸载并清理配置
- 执行标准卸载的所有步骤（删除文件、清理桌面格子）。
- **彻底抹除配置**：从 `settings-plugins.json` 中物理删除对应的配置键。若该文件因此不再包含任何其他插件的配置键，宿主将把该空文件一并删除。此操作不可逆。

## 4. 重新扫描与重启生效边界

- **即时生效的操作**：
  - 通过宿主图形界面完成的插件安装、升级或卸载，宿主内部会触发一次插件根目录重扫，并立即广播运行时快照事件，设置页的插件列表无需重启即可更新。
  - 桌面格子在收到设置更新事件（`plugin-settings-changed`）时会立即触发重新挂载。
- **必须重启 Desktop Tools 生效的场景**：
  - **手动修改文件**：用户在本地磁盘直接编辑、替换已安装插件的 `.js` 脚本或 `.css` 样式。由于浏览器引擎已对动态 `import()` 的 ES 模块进行了内存缓存，页内无法热替换已执行的模块。
  - **手动增删目录**：在外部资源管理器中直接新建、复制或删除插件文件夹，未经过宿主安装/卸载命令。
  - **修改插件根目录偏好**：在设置中切换自定义插件目录后，下次启动直接使用新目录，不自动搬迁原文件，也不读写插件目录指针。

## 5. 预设插件的随包交付与自改建议

- **随安装包分发的预设插件**：
  - `src-tauri/tauri.installer.conf.json` 显式分发 `plugin/主题-青笺/`、`plugin/AstrBot 状态/`、`plugin/docs/` 与 `plugin/README.md`，直接输出到安装目录。`plugin/示例/` 下的三个开发示例不进入安装包。
  - 默认插件根为可执行文件同级的 `plugin`，显式 `pluginDirectory` 可覆盖。运行时仅注册根下一层有清单的插件，不将文档目录注册为插件。
  - 主题插件文件夹采用 `主题-<主题名>`，属于仓库与分发约定，宿主不强制此前缀。
  - 安装和升级按打包资源覆盖同名文件，不提供按插件版本跳过的复制流程；升级保留用户新增插件目录。
  - 真正卸载（包括静默卸载）递归清理安装目录的 `plugin`，用户自装插件也会被删除；更新模式 `$UpdateMode=1` 不执行该递归删除。没有独立的预设清理勾选或主程序安装/卸载预设命令。
  - 显式配置到安装目录外的插件目录不由安装器触碰；配置目录里的 `settings-plugins.json` 继续保留。开发运行通常使用 `build/target/debug/plugin`，不自动使用仓库插件目录。
- **自定义修改建议**：
  - 若用户或开发者希望对官方示例进行深度二次开发，建议将示例文件夹复制一份并重新命名（例如由 `plugin/示例/示例-最小格子` 复制为 `我的小组件`）。
  - 同时修改其 `manifest.ini` 中的 `name`、`id` 与 `author`，避免与随包插件同名而被覆盖。若要在软件卸载后保留插件文件，应另设安装目录外的插件目录并自行备份。
